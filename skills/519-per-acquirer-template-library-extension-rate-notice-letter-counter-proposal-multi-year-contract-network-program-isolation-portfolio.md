## Common pitfalls (15 from real builds)

P1. **The per-acquirer-multi-year-contract-network-program-isolation-portfolio-leverage matrix MUST weight by per-acquirer-multi-year-contract-term-weight, NOT raw per-acquirer-portfolio-share × per-network-program-volume-share.** A common pitfall is to skip the per-acquirer-multi-year-contract-term-weight dimension and weight only by per-acquirer-portfolio-share × per-network-program-volume-share — this under-counts long-term-renewers (3-year / 5-year / 7-year / 10-year contract-asks) by 30-50% because their long-term-renewal-commitment is worth more than their spot-portfolio-share alone. The fix is to weight by per-acquirer-portfolio-share × per-network-program-volume-share × per-acquirer-multi-year-contract-term-weight (e.g. 40% Adyen × 70% Visa-branded × Year-3-weight 1.5x).

P2. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-aligned-window is MAX of objection-deadlines across N acquirers, NOT MIN.** A common pitfall is to use MIN(per-acquirer-objection-deadline across N acquirers) — this forces the operator to draft + send a per-acquirer-multi-year-contract-network-program-isolation-portfolio letter by the EARLIEST objection-deadline, which may be only 7 days for Adyen while Stripe has 28 days. The fix is MAX(per-acquirer-objection-deadline across N acquirers) — the per-acquirer-portfolio-aligned-window = the LATEST acceptance-deadline, giving the operator 28 days to draft + send the per-acquirer-multi-year-contract-network-program-isolation-portfolio letter.

P3. **The per-acquirer-multi-year-contract-network-program-isolation-portfolio-counter-proposal-walk-away-threshold MUST be calibrated per-network-program AND per-contract-year, NOT a flat -0.10% across all cells.** A common pitfall is to apply a flat -0.10% net-discount walk-away-threshold to every per-acquirer × per-network-program × per-contract-year cell — this treats the small-discrepancy VAMP-passthrough ($50K-$100K/yr cost-impact) the same as the large-discrepancy AmEx-MER-passthrough ($300K-$500K/yr cost-impact). The fix is to calibrate per-network-program AND per-contract-year: e.g. -0.05% for VAMP Year 1, -0.10% for VAMP Year 3, -0.15% for AmEx-MER Year 1, -0.25% for AmEx-MER Year 3, etc.

P4. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-BAFO-process MUST handle the multi-year-contract-renewal-ask porting question (does the operator port the per-acquirer-multi-year-contract-renewal-ask to the per-acquirer-counter-counter-counter round?).** A common pitfall is to treat the per-acquirer-multi-year-contract-renewal-ask as static during the BAFO process — the operator may want to UPGRADE the renewal-ask from 2-year to 3-year during counter-counter-counter to sweeten the deal. The fix is to make the per-acquirer-multi-year-contract-renewal-ask a per-round variable in the BAFO process: round 1 (counter) = 2-year, round 2 (counter-counter) = 3-year, round 3 (counter-counter-counter) = 3-year + ratchet-reversal.

P5. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-ask-ladder MUST include the per-acquirer-multi-year-contract-rate-freeze term in every ask, NOT just ask 1.** A common pitfall is to scope the per-acquirer-multi-year-contract-rate-freeze to only ask 1 (rate-freeze-multi-year-3yr) — this leaves asks 2-7 (network-program-passthrough-isolation, volume-commitment, ratchet-reversal, auto-renew-opt-out, pricing-collar, pricing-cap) without an explicit per-acquirer-multi-year-contract-rate-freeze clause. The fix is to include the per-acquirer-multi-year-contract-rate-freeze term in every ask so the operator can layer network-program-passthrough-isolation + volume-commitment + ratchet-reversal + auto-renew-opt-out + pricing-collar + pricing-cap on TOP of the rate-freeze.

P6. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-render pipeline MUST use the per-acquirer-multi-year-contract-renewal-ask-portfolio MCP tool to pull multi-year-contract-renewal-asks, NOT the per-acquirer-multi-year-contract-context MCP tool.** A common pitfall is to use the per-acquirer-multi-year-contract-context MCP tool (which returns the operator's existing multi-year-contract-state) — this misses the acquirer's RENEWAL-ASK (the acquirer is asking the operator to renew for 2-year / 3-year / 5-year). The fix is to use the per-acquirer-multi-year-contract-renewal-ask-portfolio MCP tool which returns BOTH the acquirer's renewal-ask AND the operator's existing multi-year-contract-state.

P7. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-leverage matrix MUST use the per-acquirer-multi-year-contract-renewal-history dimension (not just per-acquirer-tenure), because multi-year-contract-renewal-history is a stronger signal of operator leverage than raw per-acquirer-tenure.** A common pitfall is to use per-acquirer-tenure as a leverage dimension — this conflates per-acquirer-tenure (years on contract) with per-acquirer-multi-year-contract-renewal-history (number of multi-year contracts renewed in prior 5 years). The fix is to use per-acquirer-multi-year-contract-renewal-history as a SEPARATE leverage dimension (1.5x weight for prior-renewers, 1.0x for first-time-renewers, 0.5x for never-renewers).

P8. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-window tracker MUST distinguish the per-acquirer-effective-date (when the rate-increase takes effect) from the per-acquirer-multi-year-contract-renewal-ask-start-date (when the multi-year-contract-renewal-ask kicks in), because these are typically 30-180 days apart.** A common pitfall is to use per-acquirer-effective-date as the per-acquirer-multi-year-contract-renewal-ask-start-date — this conflates the rate-notice effective-date (e.g. 2026-12-01) with the multi-year-contract-renewal-ask-start-date (e.g. 2026-09-01 if the acquirer wants the renewal to start 90 days before the rate-increase). The fix is to track BOTH per-acquirer-effective-date AND per-acquirer-multi-year-contract-renewal-ask-start-date as SEPARATE fields in the per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-window tracker.

P9. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-ask-ladder MUST include the multi-region-multi-currency dimension for multi-region acquirers, NOT collapse multi-region-multi-currency into a single ask.** A common pitfall is to use the same multi-year-contract-network-program-isolation ask-ladder for multi-region acquirers (NORAM + EU + APAC) as for NORAM-only acquirers — this misses the per-acquirer-multi-region-multi-currency alignment ask (which is a SEPARATE ask for multi-region acquirers). The fix is to include the per-acquirer-multi-region-multi-currency alignment ask as ask 8 in the multi-region variant of the ask-ladder.

P10. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-counter-proposal-window-bundle MUST include the per-acquirer-portfolio-counter-proposal-renewal-window (the window for the operator to renew the multi-year-contract before the per-acquirer-auto-renew-clause kicks in), NOT just the standard 30/60/90-day windows.** A common pitfall is to use only the standard 30/60/90-day counter-proposal windows — this misses the per-acquirer-auto-renew-clause which typically auto-renews the multi-year-contract 30-90 days BEFORE the per-acquirer-objection-deadline. The fix is to add a per-acquirer-portfolio-counter-proposal-renewal-window (typically 90 days before per-acquirer-objection-deadline) to the per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-counter-proposal-window-bundle.

P11. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-counter-proposal-render-time MUST be parallelized across the N × M × K tensor, NOT computed serially.** A common pitfall is to compute the per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-leverage matrix serially (one cell at a time) — this scales as O(N × M × K) and at Path C Enterprise (25 acquirers × 12 network-programs × 5 contract-years = 1,500 cells) takes 30-60s per render. The fix is to parallelize across the N × M × K tensor using the per-acquirer-portfolio-context MCP tool's batch-fetch API — this scales as O(1) and at Path C Enterprise takes 1-3s per render.

P12. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-counter-proposal-walk-away-trigger-state MUST be per-acquirer × per-network-program × per-contract-year, NOT a single per-acquirer-portfolio-state.** A common pitfall is to fire the per-acquirer-multi-year-contract-network-program-isolation-portfolio-counter-proposal-walk-away-trigger at the per-acquirer-portfolio level — this means a single network-program (AmEx-MER) walk-away triggers walk-away for the entire per-acquirer-portfolio (VAMP + ECM + MER + DMP + JDRP + UPGD). The fix is to fire the trigger at the per-acquirer × per-network-program × per-contract-year level — only the cell that exceeds the per-acquirer-multi-year-contract-network-program-isolation-portfolio-walk-away-threshold walks away.

P13. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-brief MUST include the per-acquirer-multi-year-contract-renewal-history-evidence (proof of multi-year-contract-renewal-prior-5yr), NOT just the per-acquirer-rate-notice-portfolio-summary.** A common pitfall is to include only the per-acquirer-rate-notice-portfolio-summary in the per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-brief — this misses the per-acquirer-multi-year-contract-renewal-history-evidence which is a key per-acquirer-leverage signal. The fix is to include the per-acquirer-multi-year-contract-renewal-history-evidence (proof of multi-year-contract-renewal-prior-5yr × N acquirers) as a SEPARATE section in the per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-brief.

P14. **The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-ask-ladder MUST include the per-acquirer-multi-year-contract-pricing-band (a band between per-acquirer-rate-floor and per-acquirer-rate-cap with per-acquirer-rate-collar), NOT just per-acquirer-rate-floor and per-acquirer-rate-cap as separate asks.** A common pitfall is to treat per-acquirer-rate-floor and per-acquirer-rate-cap as separate asks — this misses the per-acquirer-rate-band which is the canonical industry pricing-instrument for multi-year-contracts. The fix is to include the per-acquirer-rate-band (a band between per-acquirer-rate-floor and per-acquirer-rate-cap with per-acquirer-rate-collar) as a separate ask 9 in the multi-year-contract variant of the ask-ladder.

P15. **Generalize to ANY per-acquirer-multi-year-contract-counter-proposal flow across ANY per-acquirer-rate-notice + per-acquirer-network-program + per-acquirer-multi-year-contract-renewal-ask combination.** The per-acquirer-rate-notice-counter-proposal-multi-year-contract-network-program-isolation-portfolio-template-library is the canonical multi-year-contract-network-program-isolation-portfolio-specialized extension for the per-acquirer-rate-notice-counter-proposal-portfolio-template-library.
