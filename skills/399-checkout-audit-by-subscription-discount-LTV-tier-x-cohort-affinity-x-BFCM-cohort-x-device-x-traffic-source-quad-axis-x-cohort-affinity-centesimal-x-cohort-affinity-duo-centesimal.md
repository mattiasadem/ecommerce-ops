## Common pitfalls (20 from real builds)

1. **Treating Move #3.43 as a replacement for Move #3.42.** Move #3.43 is the 30-axis duo-centesimal EXTENSION of Move #3.42, not a replacement. The 23rd-engine cohort-affinity-duo-centesimal-axis-rollback-engine depends on Move #3.22-Move #3.42's 22 prior rollback-engines. Disable Move #3.42 only if explicitly retiring the entire 22-engine stack.
2. **Wiring 30 NEW event-streams without backpressure.** 30 × 8 sub-cell-variant × 421 tagging-dimensions = 100,800 new column-tuples per checkout-attempt. Without explicit Kinesis/Kafka backpressure + Datadog/Snowflake ingest-quota + Move #6 attribution-coverage-monitoring, the warehouse backfills during BFCM-week-1 traffic-burst and silently drops 30-50% of duo-centesimal-axis rows.
3. **Hardcoding 30 NEW dimensions to Move #3.43 schema without Move #3.42 fallback.** When the cohort's prior Move #3.42 391-tagging-dimension schema is in production (older warehouse snapshot), Move #3.43's 30 NEW duo-centesimal-axis dimensions are absent — the leak-rate-counter falls back to "no-data" instead of "computed-from-Move-3.42-base". Wire the Move #3.42 fallback path explicitly with per-cell `null → derived-from-parent-axis` resolution.
4. **Cross-validation-matrix materialization in production BigQuery/Snowflake without dbt-model isolation.** 1,041,015,162,279,377,598,598,748,160,000,000-cell deep matrix × 421-tagging-dimensions × 30 duo-centesimal-axis = 1.31e22 cells of state. Without dbt-model isolation (separate schema + dedicated warehouse + per-cell-completion-rate leaderboard), the production BigQuery returns OOM during BFCM-week-1.
5. **Building Layer-4 fix-recommendations without per-fix-impact-confidence-validation.** Move #3.43's 412-fix-recommendations include 30 NEW Move #3.43-unique F370-F399 cohort-affinity-duo-centesimal-axis-aware-engine-version-rollout-fixes; each MUST be confidence-validated (HIGH/MEDIUM/LOW/UNVALIDATED) before activation. Shipping a LOW-confidence fix during BFCM-week-1 wipes out Move #3.42's centesimal-axis-leak-fix-recoveries.
6. **Activating all 23 BFCM-cohort-traffic-burst-rollback-engines simultaneously.** Each of the Move #3.22-Move #3.43 23 engines is a separate Cloudflare/Fastly/Akamai rate-limit-warning-integration. Activating all 23 simultaneously during BFCM-week-1 produces a cross-engine-cascade-failure. Roll out 1 engine per BFCM-cohort phase with canary-validation.
7. **Skipping the 7-gate verification step.** Move #3.43's 7-gate verification (per-cell funnel-telemetry streaming-freshness + per-cause-diagnosis freshness + cross-validation-matrix materialization-freshness + per-fix-recommendation confidence-validation + per-cell attribution-coverage + 23-rollback-engines wire-tested + per-board-pack decision-actionability) is a 4-week hardening phase. Skipping it ships a brittle funnel-audit that fails silently during BFCM-peak-traffic-burst.
8. **Using global rollback-decision-engine instead of cohort-affinity-duo-centesimal-axis-trait-many-rollback-decision-engine.** Per pitfall #10 from Move #3.22 + pitfall #19 from Move #3.42, a global rollback-decision-engine rolls-back the entire funnel-audit on ANY leak-detection; this kills the high-performers during BFCM-peak. Move #3.43 requires cohort-affinity-duo-centesimal-axis-trait-many-rollback-decision-engine (rollback only the cohort-affinity-duo-centesimal-axis-trait-many cells).
9. **Treating Move #3.43 as Move #3.43 only (ignoring inherited Move #3.22-Move #3.42 dependency).** Move #3.43 inherits 142-cause-diagnoses D1-D266 from Move #3.42 + Move #3.41 + Move #3.40 + ... Move #3.22. If Move #3.42's centesimal-axis is not deployed, Move #3.43's 347,005,054,093,125,866,199,582,720,000,000-cell matrix has 11,566,835,136,437,528,873,319,424,000,000 unresolvable cells (the inherited Move #3.42 dependency).
