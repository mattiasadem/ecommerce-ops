Replaces the "one-size-fits-all product-rank + alphabetical sort + cohort-agnostic merchandising-rule + default PDP-rank + static PLP-facets" baseline with **Klaviyo Segment + Triple Whale Cohort + Constructor Personalization + Nosto + Dynamic Yield + Algolia Personalization + Klevu Smart Categories + Bloomreach Engagement + Salesforce CDP + Segment Personas + mParticle + Braze + Iterable + Customer.io + per-cohort merchandising-rule engine + per-cohort facet-order engine + per-cohort PDP-rank engine + per-cohort badging engine + per-cohort sort engine + per-cohort cross-sell engine + per-cohort up-sell engine + per-cohort A/B test pyramid + per-cohort LTV overlay** so VIP-cohort sees SKU X in position 1, new-visitor-cohort sees SKU Y in position 1, returning-cohort sees SKU Z in position 1, LTV-tier-cohort sees per-LTV-ranked SKUs, source-channel-cohort sees per-source-channel-attributed SKUs, and geo-cohort sees per-geo-cohort-rank-ordered SKUs. ## When to use this skill

You have:

- A Shopify (or Ikas / BigCommerce / WooCommerce / Magento / Shopware / Salesforce Commerce Cloud / commercetools / Centra / Sylius / Vendure / Saleor) store
- ≥250 SKUs (below this, default Move #47 merchandising is fine — Move #47.2 unlocks when you have enough catalog breadth to differentiate cohort-segmented merchandising-rule ranks)
- ≥25,000 sessions/week (below this, default cohort-agnostic merchandising works — Move #47.2 unlocks when you have enough traffic to power per-cohort statistical-significance A/B tests)
- An existing Move #47 (on-site merchandising — Algolia / Searchspring / Klevu / Constructor / Bloomreach / Findify / Boost AI) live OR equivalent faceted-search substrate
- An existing Move #47.1 (visual+voice+image+barcode+QR+product-graph search) live OR equivalent visual-discovery substrate
- An existing Move #61 (personalization — Klaviyo + Triple Whale + Constructor + Nosto) live OR equivalent cohort-LTV-overlay substrate
- An existing Move #6 (Triple Whale / Polar / Northbeam attribution) live OR equivalent cohort-LTV-measurement substrate
- An existing Move #5 (Klaviyo / Postscript / Attentive / SMS Bump / Iterable / Customer.io) live OR equivalent cohort-LTV-segmentation substrate

You do NOT have:

- Per-cohort merchandising-rule ranks (VIP cohort sees the same product-rank as the new-visitor cohort — the #1 DTC conversion-rate-leak)
- Per-cohort facet ordering (VIP cohort sees the same facet order as the LTV-low cohort — loses 8–18% of cohort-segmented PLP-to-ATC CVR lift)
- Per-cohort badging (VIP cohort sees the same "Best seller" / "New" / "Low stock" / "Just restocked" / "Staff pick" badges as the new-visitor cohort — loses 10–20% of cohort-segmented badge-CTR)
- Per-cohort PDP-rank (VIP cohort sees the same PDP-cross-sell + PDP-up-sell + PDP-bundle + PDP-replenishment rank as the new-visitor cohort — loses 15–30% of cohort-segmented PDP-AOV)
- Per-cohort sort options (VIP cohort sees the same "Featured" / "Price asc/desc" / "Newest" / "Best-selling" / "Rating" / "Match score" sort options as the new-visitor cohort — loses 10–20% of cohort-segmented sort-usage-rate)
- Per-cohort merchandising A/B testing (the operator's KPIs for Move #47.2 are hand-tested via cohort-segmented-trials rather than via Constructor / Klevu / Algolia / Syte / Custom CLIP built-in A/B testing — loses 8–18% of cohort-segmented merchandising-CVR-lift)
- Per-cohort LTV overlay on the merchandising-rank (the operator's KPI-vs-merchandising-rank overlay is Mono vs LTV-overlay — loses 12–25% of cohort-segmented merchandising-CVR-lift)
