## The build (12-20 hours for a competent operator with $6k-15k setup cost)

Move #1.4 ships in 5 phases over 12-20 hours.

**Phase 1 (3 hours) — Move #1.3 per-creator-broadcast-confirmed-consumer + Move #1.2 dark-site-resolution-confirmed-consumer + Move #1 crisis-closure-event-consumer + per-creator-state-table**

- Wire Move #1.3 per-creator-broadcast-confirmed-consumer: consume `per_creator_broadcast_confirmed` within 60 sec; maintain per-creator-state-table (creator_id → paused_content_ids + paused_affiliate_link_ids + replaced_utm_link_ids + crisis_id); idempotency-key = `crisis_id` + `creator_id`.
- Wire Move #1.2 dark-site-resolution-confirmed-consumer: consume `dark_site_resolution_confirmed` within 60 sec; PRIMARY trigger for per-creator-resume-sequence; gated on `affected_sku_count === 0`; idempotency-key = `dark_site_deploy_id` + `resolution_timestamp`.
- Wire Move #1 crisis-closure-event-consumer: consume `crisis_closure_event` within 5 min; SECONDARY trigger for per-creator-resume-sequence; gated on `closure_severity_score < 40`; idempotency-key = `crisis_id` + `closure_timestamp`.
- Build per-creator-state-table: in-memory + Postgres-persistent (for restart-recovery); per-creator-state includes `paused_content_ids[]` + `paused_affiliate_link_ids[]` + `replaced_utm_link_ids[]` + `original_utm_link_ids[]` + `crisis_id` + `crisis_lane` + `paused_at_timestamp` + `resume_at_timestamp` (NULL until per-creator-resume-message-sent).

**Phase 2 (3 hours) — GRIN / Aspire / CreatorIQ API integration + per-creator-resume-checklist-renderer + per-creator-thank-you-renderer + per-creator-post-crisis-cohort-affinity-boost-renderer**

- Integrate with the brand's creator-marketing-platform API (GRIN / Aspire / CreatorIQ); if multiple, use the most-used one as primary and the others as fallback.
- Build per-creator-resume-checklist-renderer: 8 templates matched to Move #1's 8-scenario-vulnerability-matrix; LLM-personalized per-creator-handle + per-creator-platform; 3 baseline languages (English / Spanish / French).
- Build per-creator-thank-you-renderer: 4 templates matched to per-creator-tier (macro / mid-tier / micro / nano); LLM-personalized per-creator-handle + per-creator-platform + per-creator-pause-compliance-score; 3 baseline languages.

**Phase 3 (3 hours) — Per-creator-content-unpause-orchestrator + per-creator-affiliate-link-unpause-orchestrator + per-creator-utm-replace-back-orchestrator**

## Common pitfalls

The Move #1.4 build fails when any of these 16 pitfalls is hit:

1. **Per-creator-resume-without-Move-#1.3-per-creator-broadcast-confirmed-consumer** — the per-creator-resume-sequence is fired from a manual Slack-command or a manual PagerDuty-page instead of from Move #1.3's `per_creator_broadcast_confirmed` event. Without the Move #1.3 consumer the per-creator-state-table is empty (no paused_content_ids + no paused_affiliate_link_ids + no replaced_utm_link_ids) AND the per-creator-resume-sequence has nothing to unpause / unpause / replace-back. Fix: Move #1.4 consumes the Move #1.3 `per_creator_broadcast_confirmed` within 60 sec; maintains the per-creator-state-table for use when Move #1.2 dark-site-resolution-confirmed fires.
2. **Per-creator-resume-without-Move-#1.2-dark-site-resolution-confirmed-consumer-as-trigger** — the per-creator-resume-sequence is fired from a manual "operator-confirms-crisis-resolved" action instead of from Move #1.2's `dark_site_resolution_confirmed` event. Without the Move #1.2 consumer the per-creator-resume-sequence is missed (the operator forgets to fire it because they're focused on closing the crisis itself) AND creators stay paused 7-30 days after the crisis is resolved (the canonical creator-stays-paused-forever-after-crisis-resolution anti-pattern). Fix: Move #1.4 consumes the Move #1.2 `dark_site_resolution_confirmed` within 60 sec as the PRIMARY trigger; the consumer is idempotent.
3. **Per-creator-resume-without-Move-#1-crisis-closure-event-consumer-as-fallback-trigger** — the per-creator-resume-sequence is fired ONLY from Move #1.2's `dark_site_resolution_confirmed` event with no fallback to Move #1's `crisis_closure_event`. Without the Move #1 consumer the per-creator-resume-sequence is missed when the dark-site is taken down before resolution (e.g. dark-site is replaced by a permanent-FAQ-page). Fix: Move #1.4 consumes the Move #1 `crisis_closure_event` within 5 min as the SECONDARY trigger; gated on `closure_severity_score < 40`.
4. **Per-creator-resume-without-Move-#1-8-scenario-vulnerability-matrix-as-template-selector** — the per-creator-resume uses a single resume-checklist-template for all crises instead of mapping the crisis-resolution to 1 of 8 templates via Move #1's 8-scenario-vulnerability-matrix. Without the 8-template-engine a product-recall-resolved crisis gets the same resume-checklist as a viral-TikTok-resolved crisis (resume-tone + resume-checklist + per-creator-thank-you + post-crisis-cohort-affinity-boost are wrong by 60-80%). Fix: Move #1.4 maps the crisis-resolution to 1 of 8 templates; each template has a unique per-creator-resume-engine.
5. **Per-creator-resume-without-LLM-personalization-keeping-creator-voice** — the per-creator-resume-checklist is a generic "you can resume promoting" instead of an LLM-personalized resume-checklist that maintains the creator's voice. Without LLM-personalization the creator sees the resume as "corporate-spam" and ignores the checklist (per-creator-content-unpause-rate drops from 80% to <20%). Fix: Move #1.4 LLM-personalizes each resume-checklist with the creator's handle + platform + audience-size + recent-content-voice (read from the creator-marketing-platform's `creator_voice_profile` endpoint).
6. **Per-creator-resume-without-3-language-i18n** — the per-creator-resume-checklist is English-only instead of supporting Spanish + French + the brand's other top-3 creator-languages. Without i18n 30-50% of creators (those whose primary language is Spanish or French) misunderstand the resume-checklist AND may not re-engage with the brand. Fix: Move #1.4 supports 3 baseline languages (English / Spanish / French) matched to the creator's primary language; the LLM-personalization step auto-translates to the creator's primary language.
7. **Per-creator-content-unpause-orchestrator-without-per-platform-differentiation** — the orchestrator calls a single `unpause_scheduled_content` API for all platforms instead of per-platform APIs (TikTok/Instagram/YouTube/Snap/Pinterest each have their own unpause-API). Without per-platform-differentiation the orchestrator unpauses-content on the wrong platform (e.g. unpauses a TikTok creator's Instagram-Reel instead of their TikTok) or fails to unpause on the right platform (e.g. doesn't unpause a YouTube-Shorts creator's paused YouTube). Fix: Move #1.4 calls the creator-marketing-platform's per-platform `unpause_scheduled_content` API; per-creator-platform-routing.
8. **Per-creator-affiliate-link-unpause-orchestrator-without-UTM-replace-back** — the orchestrator unpauses the affiliate-link but doesn't replace the dark-site-link with the original-affiliate-link. Without the UTM-replace-back the creator's bio + scheduled-content still shows the dark-site-link (which leads to the dark-site, not the PDP), even after the unpause. Fix: Move #1.4 calls the creator-marketing-platform's `replace_utm_link` API to replace the dark-site-UTM with the original-UTM; the replacement is reversible.
9. **Per-creator-resume-without-Twilio-SMS-fallback** — the resume-broadcast uses only Slack + Email. Without the SMS-fallback 20-40% of macro+mid-tier creators (those who don't check Slack + Email frequently) miss the resume-broadcast AND don't unpause-content AND don't unpause-affiliate-link. Fix: Move #1.4 has a Twilio-SMS-fallback for P0 resume-broadcasts to macro+mid-tier; the SMS contains the resume-checklist-link + the per-creator-thank-you-summary.
10. **Per-creator-tier-decision-classifier-without-4-class-exclusive** — the classifier assigns MULTIPLE decision-classes to the same crisis-resolution (e.g. both `resume-all-4-tiers` AND `resume-macro-mid-only`). Without EXCLUSIVE first-match-wins the resume-broadcast fires 2x (once for all-4-tiers, once for macro-mid-only) → duplicate-messages to macro+mid-tier creators. Fix: 4 rules checked in order: resume-all-4-tiers → resume-macro-mid-only → resume-macro-only → no-resume-defer; first-match-wins.
11. **Per-creator-tier-isolation-test-not-run-on-deploy** — the test is run only manually, not on every Move #1.4 deploy + on every per-tier-count change. Without the on-deploy-isolation-test a per-tier-count change (e.g. adding a new micro-tier) silently breaks the summation (`sum(per-tier-counts) != total-resume-count`). Fix: Move #1.4 runs the isolation-test on every deploy + on every per-tier-count change; the test catches "double-counted" or "missing-tier" bugs.
12. **Per-creator-state-table-not-restart-recovery-safe** — the per-creator-state-table is in-memory only (no Postgres-persistence). Without Postgres-persistence a Move #1.4 restart loses the per-creator-state-table AND the per-creator-resume-sequence has nothing to unpause / unpause / replace-back. Fix: Move #1.4 persists the per-creator-state-table to Postgres (idempotency-key = `crisis_id` + `creator_id`); on restart, Move #1.4 re-loads the per-creator-state-table from Postgres.
13. **Per-creator-utm-replace-back-orchestrator-without-original-UTM-preservation** — the orchestrator replaces the dark-site-UTM with a new UTM (not the original UTM) because the original UTM was not preserved during the crisis. Without original-UTM-preservation the per-creator-traffic after the crisis uses a NEW UTM that doesn't match the per-creator-traffic before the crisis AND the Move #6 attribution-quality can't compare pre-crisis vs post-crisis per-creator-attribution. Fix: Move #1.4 preserves the original UTM in the per-creator-state-table (during the crisis, Move #1.3 records `original_utm_link_ids[]`); on resume, Move #1.4 replaces the dark-site-UTM with the original-UTM.
14. **Per-creator-content-unpause-orchestrator-without-Move-#28-return-flow-closure-gate** — the orchestrator unpauses content for SKUs whose return-flow hasn't been fully processed (i.e. the SKU is still being returned by customers). Without the Move #28 gate the orchestrator unpauses content for a SKU that the brand is still actively recalling, creating a brand-inconsistency (creator promotes the SKU while customers are still returning it). Fix: Move #1.4 gates the per-creator-content-unpause-orchestrator on Move #28's `per_sku_return_flow_closure_event` for the SKU; the SKU must be re-listed before content is unpaused.
15. **Per-creator-resume-without-Move-#6.15-attribution-ledger-emit** — the resume-broadcast is fired but not logged to Move #6.15's accuracy-ledger. Without the Move #6.15 emit the operator can't measure Move #1.4's impact on per-creator-content-unpause-rate + per-creator-affiliate-link-unpause-rate + per-creator-utm-replace-back-rate. Fix: Move #1.4 emits `per_creator_resume_latency` row + `per_creator_content_unpause_row` + `per_creator_affiliate_link_unpause_row` + `per_creator_utm_replace_back_row` + `per_creator_thank_you_confirmed_row` + `per_creator_cohort_affinity_boost_row` to Move #6.15's accuracy-ledger with `accuracy_layer="move_1_4_per_creator_post_crisis_recovery_orchestrator"` tag.
16. **Per-creator-resume-without-Move-#1.4's-production-readiness-test-before-BFCM-peak** — BFCM-peak 200-concurrent-Move #1.4-resume-batch with 2000 creators + 4-tier-resume + 8-template-resume-checklist + 4-template-thank-you + 1-template-cohort-affinity-boost + Slack-Block-Kit + Twilio-SMS-fallback load-test is REQUIRED; Move #1.4 must complete p95 < 60 min. Without load-test Move #1.4 silently fails on BFCM-peak days (a brand's 2000-creator resume takes 4-8 hours instead of <60 min during BFCM-peak traffic).
