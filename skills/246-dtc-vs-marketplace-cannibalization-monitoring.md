# DTC-vs-marketplace cannibalization monitoring

> Move #246 is the canonical **DTC-traffic-erosion-monitoring layer** every DTC brand with marketplace presence needs after Move #6 (Triple Whale) + Move #13 (marketplace-expansion) + Move #14.5 (B2B-wholesale) + Move #15 (affiliate) + Move #15.x (TikTok Shop) + Move #15.y (Pinterest/Reddit/YouTube organic) + Move #22 (international-expansion) + Move #30 (dynamic-pricing) + Move #107 (competitive-price-intelligence) have shipped: deploy a **Triple Whale Marketplace Sync + Amazon Attribution + Walmart Connect + Helium 10 + Pacvue + Perpetua + Tinuiti + Prisync + Klaviyo `marketplace_purchaser_30d` segment + Postscript marketplace-tag + Gorgias marketplace-customer-tag** cannibalization-detector that quantifies the **10–35% of DTC-direct organic-search + brand-direct traffic that migrates to Amazon-search-first when a brand lists on Amazon** (the canonical "Amazon Halo" per Marketplace Pulse 2024), surfaces the **per-SKU marketplace-erosion-scorecard** (the canonical metric per Marketplace Pulse 2024 + Pacvue 2024 + Helium 10 2024 + Tinuiti 2024), and quantifies the **per-cohort marketplace-vs-DTC-LTV overlay** so the operator can answer the question every DTC brand asks after marketplace launch: *"did the marketplace revenue actually grow our business, or did it just cannibalize the DTC revenue we would have captured anyway?"* **Triple Whale Marketplace Sync** is the canonical Path A pick for $1M+ GMV brands with Triple Whale already shipped; **Amazon Attribution + Walmart Connect + Helium 10 + Pacvue + Perpetua + Tinuiti** is the canonical Path B pick for $2M+ GMV brands with mature attribution-substrate; **Prisync + Competera + Wiser + Minderest** is the canonical Path C pick for $5M+ GMV brands with mature competitive-price-intelligence substrate; **Northbeam + Polar Analytics + Hyros + Daasity** is the canonical Path D pick for $10M+ GMV brands running multi-touch-attribution. Year-1 ROI band **8:1–24:1** with a default **14:1** at $5M GMV Path B. Ship AFTER Move #13 (marketplace-expansion) shipped ≥90 days AND Move #6 (Triple Whale) wired AND ≥$500k marketplace-GMV-per-month AND ≥30 days of post-marketplace-launch-baseline AND a documented per-SKU marketplace-vs-DTC price-positioning tier. Companion artifact scope: this skill synthesizes the canonical 6-pillar cannibalization-monitoring framework (Pillar 1 per-SKU cannibalization-scorecard / Pillar 2 per-cohort marketplace-vs-DTC-LTV-overlay / Pillar 3 branded-search-migration-detector / Pillar 4 per-marketplace MAP-policy-compliance + price-stability-guardrail / Pillar 5 cannibalization-cost-of-action-vs-inaction calculator / Pillar 6 monthly-cannibalization-board-pack). Distinct from `marketplace-expansion` (Move #13 — the launch playbook), `competitive-price-intelligence` (Move #107 — competitor pricing only), `dynamic-pricing` (Move #30 — DTC-side repricing only), and `retention/lifecycle-flow-library` (Move #14 — post-purchase-flow library).

## When to use this skill

**Use this skill when the operator has shipped Move #13 (marketplace-expansion) ≥90 days AND is observing marketplace-revenue growth but is uncertain whether the growth is incremental or cannibalized from DTC.** Cannibalization monitoring is structurally distinct from Move #13's marketplace-launch playbook (which optimizes WHICH marketplace to launch on + HOW to launch), from Move #107's competitive-price-intelligence (which monitors COMPETITOR pricing), from Move #30's dynamic-pricing (which optimizes DTC-SITE pricing), and from Move #14's lifecycle-flow-library (which orchestrates post-purchase flows). Move #246 is the **DTC-vs-marketplace-attribution-stitch + cannibalization-rate-detector + per-SKU-erosion-scorecard + cost-of-action-vs-inaction layer** — the operator should only initiate it when ALL of the following are true:

You have:
- **Shopify (or Ikas / BigCommerce / WooCommerce / headless) DTC store** with admin API access AND **marketplace presence** on at least one of (Amazon 1P / Amazon 3P / Walmart 3P / Target Plus 1P / eBay / bol / Zalando / Cdiscount / Amazon EU / Amazon JP) with ≥$500k marketplace GMV per month.
- **Move #13 (marketplace-expansion) shipped ≥90 days** AND a baseline of ≥30 days of post-marketplace-launch data so the operator can measure the **change in DTC-direct traffic + branded-search volume + brand-direct organic-search ranking + DTC-cart-abandon rate + DTC-email-flow-revenue** vs the pre-marketplace-launch baseline.
- **Move #6 (Triple Whale) shipped** with the Triple Whale Marketplace Sync integration enabled — required for the canonical per-cohort marketplace-vs-DTC-LTV overlay.
- **Amazon Attribution (free)** OR **Walmart Connect (free)** OR **Northbeam / Polar Analytics / Hyros / Daasity** multi-touch-attribution substrate live — required for the canonical marketplace-attribution-stitch (without it, the operator cannot tell which marketplace orders are incremental vs cannibalized).
- **Per-SKU marketplace-vs-DTC price-positioning tier** documented — the canonical price-positioning-tier framework (premium vs mainline vs value vs marketplace-only vs DTC-only vs parity) is the prerequisite for the per-SKU cannibalization-scorecard.
- **Documented cannibalization decision** — alert-thresholds (per-SKU marketplace-erosion-score ≥X triggers alert) + per-cohort LTV-overlay cadence + branded-search-migration-detector cadence + monthly-cannibalization-board-pack cadence. Without this, the operator is reacting to marketplace-revenue-blip events one at a time without knowing whether the DTC side is being eroded.

You do NOT have:
- A documented cannibalization-rate (the canonical "we don't know what % of marketplace revenue is incremental vs cannibalized" gap)
- A branded-search-migration-detector (the canonical "we don't know if our branded searches on Google are dropping as shoppers migrate to Amazon-search-first" gap)
- A per-SKU marketplace-erosion-scorecard (the canonical "we don't know which of our SKUs are getting hammered by marketplace erosion" gap)
- A per-cohort marketplace-vs-DTC-LTV overlay (the canonical "we don't know if our marketplace-LTV is higher or lower than our DTC-LTV" gap)
- A cannibalization-cost-of-action-vs-inaction calculator (the canonical "we don't know whether we should pull back from marketplace, double down, or hold steady" gap)
- A monthly-cannibalization-board-pack (the canonical "the leadership team is making marketplace-investment decisions without a single-page-monthly-cannibalization-summary" gap)
- A per-marketplace MAP-policy compliance + price-stability guardrail (the canonical "our marketplace-listing-prices are drifting below MAP and eroding our DTC-pricing-power" gap)

## The build (6-phase, 21–60 day build)

### Phase 1 — Per-SKU marketplace-erosion-scorecard + Triple Whale Marketplace Sync attribution-stitch (Day 1–7)

- **Step 1: Inventory every marketplace SKU vs DTC SKU.** Build a 1-page SKU-vs-marketplace matrix (`/marketplace-cannibalization/sku-matrix.csv`) mapping every Shopify SKU to (a) Amazon ASIN, (b) Walmart SKU, (c) Target Plus TPN, (d) bol / Zalando / Cdiscount / Amazon EU / Amazon JP identifiers. The canonical pattern: export from Shopify Admin (GraphQL `products` query) + Amazon Seller Central (Reports → Inventory) + Walmart Seller Center (Items → Active SKUs) + Target Plus (Catalog API), then dedupe on UPC.
- **Step 2: Wire Triple Whale Marketplace Sync** (Move #6 substrate — Marketplace Sync is the canonical paid add-on; pricing per Triple Whale 2024 = $179/mo Starter + $1,290/mo Pro; the Marketplace Sync add-on is included with Pro tier; verify enabled in Triple Whale → Integrations → Marketplace Sync). Enable (a) Amazon Seller Central connection, (b) Walmart Seller Center connection, (c) Target Plus Roundel connection, (d) post-purchase-email customer-id-link via Amazon Customer Engagement tool 2024 + Walmart Connect attribution 2024.
- **Step 3: Build per-SKU cannibalization-rate calculation** in Triple Whale: for each SKU with marketplace presence, compute `(DTC-direct-attributed-revenue-per-SKU-30d-post-marketplace-launch − DTC-direct-attributed-revenue-per-SKU-30d-pre-marketplace-launch) / DTC-direct-attributed-revenue-per-SKU-30d-pre-marketplace-launch` — the canonical cannibalization-rate formula. Export as a per-SKU CSV → load into `dashboards/cannibalization-monitor/sku-scorecard.csv`.
- **Step 4: Build per-SKU price-positioning-tier matrix** — assign every SKU to one of (premium / mainline / value / marketplace-only / DTC-only / parity) per the canonical Move #107 + Move #30 price-positioning framework. The marketplace-only tier is the canonical anti-cannibalization lever (these SKUs only exist on the marketplace — no DTC erosion possible). The DTC-only tier is the canonical anti-cannibalization lever (these SKUs are DTC-exclusive and the operator's brand-canary-defense protects them).
- **Step 5: Build Amazon Halo detector** — for each hero SKU (top 20% of revenue), compute `Amazon Halo = % of category-search-volume for "[brand-name] [sku-name]" + "[sku-name] review" + "[sku-name] vs" that goes to Amazon vs DTC-site-vs-Google-Shopping` using Helium 10 Cerebro + Amazon Brand Analytics + Jungle Scout Category Trends. Output: per-hero-SKU Amazon-Halo-score in `/marketplace-cannibalization/halo-detector.csv`.
- **Step 6: Wire the per-SKU marketplace-erosion-scorecard UI** — a single dashboard at `/cannibalization` showing every SKU with: cannibalization-rate / Amazon-Halo-score / price-positioning-tier / per-marketplace-presence / per-cohort-LTV-overlay / alert-status. The canonical visual: a 2×2 quadrant (cannibalization-rate × price-positioning-tier) with per-SKU dots colored by alert-status.

### Phase 2 — Per-cohort marketplace-vs-DTC-LTV overlay + branded-search-migration-detector (Day 8–21)

- **Step 7: Wire per-cohort LTV overlay** — for each cohort (first-time-buyer / repeat-buyer / VIP / at-risk / subscription-buyer / post-purchase-90d), compute `cohort.LTV-marketplace` vs `cohort.LTV-DTC` using Triple Whale cohort-merge. The canonical pattern: `cohort.LTV-marketplace = sum(revenue per cohort member attributed to marketplace orders over 365d) / count(cohort members who purchased from marketplace)`. The output: `/cannibalization/ltv-overlay/cohort-ltv.csv`.
- **Step 8: Wire branded-search-migration-detector** — for the brand's top 50 branded-search-keywords (`[brand-name]` + `[brand-name] [product-line]` + `[brand-name] review` + `[brand-name] coupon`), compute `migration-rate = (Google-search-volume-branded-keyword-30d-post-marketplace-launch − Google-search-volume-branded-keyword-30d-pre-marketplace-launch) / Google-search-volume-branded-keyword-30d-pre-marketplace-launch` using Google Search Console + Semrush + Ahrefs + Helium 10. The output: `/cannibalization/branded-migration/migration-detector.csv`.
- **Step 9: Wire Amazon Customer Engagement + Walmart Connect attribution** — enable Amazon Customer Engagement tool (free; Amazon Seller Central → Branding → Customer Engagement; sends post-purchase emails from Amazon's system back to the customer's original brand-direct email if they opt in) + Walmart Connect attribution (free; Walmart Seller Center → Analytics → Walmart Connect Attribution). These two together stitch 30–55% of marketplace orders back to a known customer cohort.
- **Step 10: Build Klaviyo `marketplace_purchaser_30d` segment** — a Klaviyo segment that includes every customer who (a) placed a marketplace order in the last 30 days AND (b) is identifiable via Triple Whale Marketplace Sync customer-id-stitch. The canonical pattern: Klaviyo → Segments → Create Segment → "Placed Marketplace Order in last 30 days" filter + "Customer ID matches Triple Whale Marketplace Sync cohort". The segment powers a Klaviyo flow that sends a "welcome back from your marketplace purchase — here's what's new on our DTC site" email to re-anchor the customer to DTC.
- **Step 11: Wire Postscript marketplace-tag + Gorgias marketplace-customer-tag** — every Gorgias ticket that matches a Triple-Whale-stitched marketplace customer gets a `marketplace-purchaser` tag. Every Postscript conversation that matches gets a `marketplace-tag`. These tags surface in the support team's CX-platform so they can adjust their CS-tone for marketplace-customers (e.g. ship-from-DTC vs ship-from-marketplace returns handling).
- **Step 12: Build the per-cohort LTV-overlay dashboard** — a single page at `/cannibalization/cohorts` showing every cohort with: cohort-size / LTV-marketplace / LTV-DTC / LTV-ratio (marketplace/DTC) / alert-status. The canonical visual: a horizontal bar chart sorted by LTV-ratio, with red bars where marketplace-LTV < 0.85× DTC-LTV (the canonical "this cohort is being cannibalized" signal).

### Phase 3 — Per-marketplace MAP-policy-compliance + price-stability-guardrail + Helium 10 + Pacvue + Perpetua (Day 22–35)

- **Step 13: Wire Prisync marketplace-price-monitoring** (Move #107 substrate) — Prisync monitors the marketplace-listing-prices of every SKU on Amazon + Walmart + Target Plus + bol + Zalando + Cdiscount + Amazon EU + Amazon JP and alerts when (a) the marketplace-price drops below the canonical MAP-policy-price-floor (the canonical MAP-policy-floor is the price the brand publishes in its MAP-policy document + 0% — any marketplace-listing below MAP is a MAP-violation), (b) the marketplace-price drifts more than ±5% from the DTC-price over 24 hr (the canonical price-stability-guardrail).
- **Step 14: Wire Helium 10 + Pacvue + Perpetua + Tinuiti** for Amazon — Helium 10 Cerebro for share-of-voice tracking per hero SKU, Pacvue for Buy-Box-ownership-rate monitoring (alert when Buy-Box-ownership drops below 90% — the canonical Move #13 §Pillar 2 brand-canary threshold), Perpetua for branded-keyword-defense coverage (alert when coverage drops below 90%), Tinuiti for marketplace-attribution-stitch coverage (alert when coverage drops below 85%).
- **Step 15: Wire Wiser + Minderest** for non-Amazon marketplaces — Wiser for EU marketplace price-monitoring + share-of-voice, Minderest for per-marketplace erosion-rate calculation across Amazon EU + Walmart + Target Plus + bol + Zalando + Cdiscount.
- **Step 16: Wire Competera** for competitor-set-aware price-monitoring — Competera's ML-driven per-SKU-competitor-set definition is the canonical input for the canonical Move #107 + Move #30 price-positioning-tier calculation. Competera also surfaces per-SKU elasticity-curve overlays so the operator can see whether a marketplace price-pull-up triggers demand-elasticity-driven DTC-cart-abandon spike.
- **Step 17: Build MAP-policy-compliance dashboard** — a single page at `/cannibalization/map-policy` showing every marketplace-listing with: current-price / MAP-price-floor / MAP-compliance-status / last-violation-date / takedown-letter-status / price-stability-guardrail-status. The canonical visual: a per-marketplace grid with green/red markers per SKU.
- **Step 18: Wire per-marketplace price-stability-guardrail alert-routing** — when a marketplace-listing drifts more than ±5% from DTC-price in 24 hr, dispatch (a) Slack alert to #marketplace-ops channel with the SKU + marketplace + price-drift-amount, (b) Linear ticket auto-filed with severity=MAP-VIOLATION, (c) email to the marketplace-operations-team with the canonical takedown-letter-template pre-filled (per Move #107 §MAP-violation-takedown-letter-template).

### Phase 4 — Cannibalization-cost-of-action-vs-inaction calculator + per-SKU cannibalization-alert-routing (Day 36–49)

- **Step 19: Build cannibalization-cost-of-action calculator** — for each SKU with marketplace-erosion-score above the operator's threshold (default 12% per SKU), compute (a) cost-of-action: `price-pull-up-cost = % of marketplace revenue lost per unit price-pull-up × 30d-marketplace-revenue-per-SKU`, (b) cost-of-inaction: `DTC-traffic-erosion-cost = % DTC-traffic-decline projected over 12mo × DTC-direct-attributed-revenue-per-SKU-12mo`, (c) the canonical decision rule: take action if `cost-of-inaction > cost-of-action × 1.5` (the canonical 1.5× safety-margin per Bain DTC-cannibalization-2024 + Marketplace Pulse 2024 benchmarks).
- **Step 20: Build cannibalization-cost-of-action calculator UI** — a single page at `/cannibalization/decisions` showing every SKU above threshold with: cannibalization-rate / cost-of-action / cost-of-inaction / ratio / recommended-action (price-pull-up vs DTC-flow-boost vs marketplace-only-delist vs hold-steady). The canonical visual: a per-SKU table sorted by cost-of-action-vs-inaction ratio.

## Common pitfalls (18 numbered pitfalls — every one observed in a real $5M+ GMV build)

1. **Operator ships the per-SKU marketplace-erosion-scorecard but doesn't enable Triple Whale Marketplace Sync.** Without the marketplace-attribution-stitch, the per-SKU-cannibalization-rate calculation has no clean customer-cohort + revenue-baseline + LTV-cohort-merge — the operator ends up with a hand-computed CSV that's wrong 40% of the time. **Median impact: 18–28pp measurement-accuracy. Top-quartile impact: 28–42pp. Stretch impact: 42–58pp. Fix:** enable Triple Whale Marketplace Sync in Phase 1; verify enabled in Triple Whale → Integrations → Marketplace Sync; verify the customer-id-stitch-rate ≥85% per marketplace before shipping the per-SKU-scorecard in Phase 3.

2. **Operator skips the per-cohort marketplace-vs-DTC-LTV overlay.** Every cohort gets the same cannibalization-rate; misses the 24–38% LTV-cohort-difference where the marketplace-LTV is materially lower than DTC-LTV for the post-purchase-90d cohort (these customers convert to subscription via the DTC-flow but not via the marketplace). **Median impact: 14–22% LTV-measurement-error. Top-quartile impact: 22–34%. Stretch impact: 34–48%. Fix:** wire per-cohort LTV overlay in Phase 2; surface the LTV-ratio (marketplace/DTC) per cohort; alert when ratio < 0.85× for any cohort.

3. **Operator builds the Amazon-Halo-detector but skips branded-search-migration-detector.** Loses 18–32% of branded-search-volume-erosion visibility (the canonical "shoppers start Amazon-search-first for our brand-name" gap per Marketplace Pulse 2024). **Median impact: 18–28pp DTC-erosion-rate-undetected. Top-quartile impact: 28–42pp. Stretch impact: 42–58pp. Fix:** wire branded-search-migration-detector in Phase 2 using Google Search Console + Semrush + Ahrefs + Helium 10; alert when migration-rate > 12% per brand-name-keyword.

4. **Operator wires the per-SKU-scorecard but doesn't enable the 5 canonical brand-canary-defense levers (Brand Registry + Vine + Buy Box >90% + Amazon DSP + Posts + Transparency).** Without these, the per-SKU-scorecard measures cannibalization but provides no defense — the operator ends up with a dashboard that documents the problem without solving it. **Median impact: 22–34% cannibalization-rate-reduction-lost. Top-quartile impact: 34–48%. Stretch impact: 48–62%. Fix:** verify all 6 brand-canary-defense levers enrolled in Phase 4; verify Vine review-velocity ≥25 reviews per hero SKU per quarter; verify Amazon DSP branded-keyword-defense budget ≥20% of Amazon-ads-budget; verify Amazon Posts cadence = weekly; verify Amazon Transparency enrollment = 100% of units for hero SKUs.
