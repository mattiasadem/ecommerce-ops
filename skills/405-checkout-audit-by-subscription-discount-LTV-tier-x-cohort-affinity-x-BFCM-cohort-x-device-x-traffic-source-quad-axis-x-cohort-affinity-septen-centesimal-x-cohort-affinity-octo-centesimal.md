## Common pitfalls (23)

1. **P1 — Shopping-cart-engine-version-stale is a cart-state-mismatch risk, not just a leak-rate risk.** When Shopify-ShoppingCart and Magento-ShoppingCart both hold a user's cart but the engine-version-stale risk manifests as the user sees a different cart than the checkout-step-entered-event records. Symptom: +37-89% cart-state-mismatch at the cart-page step. Fix: F525 octo-centesimal-axis-aware-shopping-cart-engine-version-bridge-engine.
2. **P2 — Wishlist-engine-version-stale is a price-out-of-sync risk.** When the wishlist-engine-version is stale, the wishlist shows the original price but the cart shows the discounted price, triggering a 67% drop in wishlist-to-cart conversion. Fix: F526.
3. **P3 — Gift-card-engine-version-stale is a balance-mismatch-on-mobile risk.** Mobile Safari's IndexedDB holds a stale gift-card balance; the cart-side gift-card-engine queries a different balance. Symptom: +42% gift-card-apply-failure on mobile. Fix: F527 with mobile-specific WebSocket-sync.
4. **P4 — Store-credit-engine-version-stale causes credit-application-on-promo-stack failure.** When the store-credit-engine-version doesn't sync with the discount-stacking-rules engine (Move #3.48), the credit is silently double-applied. Symptom: +48% credit-over-application. Fix: F528.
5. **P5 — Rewards-points-engine-version-stale causes points-balance-on-redeem failure.** When Smile.io-RewardsPoints engine-version is stale, the user sees 100 points but the redeem endpoint sees 80 points. Symptom: +44% points-redeem-failure. Fix: F529.
6. **P6 — Loyalty-tier-engine-version-stale causes tier-status-on-discount-application mismatch.** When LoyaltyLion-LoyaltyTier engine-version is stale, the user has Gold tier but the discount-engine sees Silver tier. Symptom: +39% loyalty-tier-discount-mismatch. Fix: F530.
7. **P7 — VIP-tier-engine-version-stale causes tier-expiry-during-checkout failure.** When VIP-tier engine-version doesn't refresh during a 5-step checkout, the user loses VIP status mid-checkout. Symptom: +34% vip-tier-expiry-during-checkout. Fix: F531 with mid-checkout-tier-refresh.
8. **P8 — Paid-membership-engine-version-stale causes membership-status-on-paywall-gate mismatch.** When Memberful-PaidMembership engine-version is stale, the paywall sees an active membership but the gate-page sees an expired one. Symptom: +41% paywall-gate-mismatch. Fix: F532.
9. **P9 — Subscription-billing-cycle-engine-version-stale causes cycle-on-renewal-attempt failure.** When Stripe-SubscriptionBillingCycle engine-version is stale, the renewal attempts at the wrong cycle. Symptom: +37% renewal-cycle-mismatch. Fix: F533.
10. **P10 — Per-octo-centesimal-axis-rollback-must-be-axis-specific-not-global.** When a regression fires in the Product-recommendation-engine-version-bridge-engine, the operator must NOT roll back ALL octo-centesimal-axis bridges — only the broken one. Global rollbacks break the 35 OTHER working axes. Verify via per-octane-centesimal-axis-synthetic-canary + per-octane-centesimal-axis-canary-rollout.
11. **P11 — Don't reach for Shopify-ShoppingCart as 1:1 substitute for Magento-ShoppingCart or BigCommerce-ShoppingCart.** Each platform has different cart-state-management primitives; Shopify's CartDrawer API is not the same as Magento's persistent-cart API. Fix: F525 bridge-engine per platform-pair.
12. **P12 — Subscription-dunning-engine-version-stale causes retry-count-on-card-decline failure.** When the dunning-engine-version is stale, the system retries a card that was already charged, causing a 6% chargeback rate. Fix: F534.
13. **P13 — Subscription-pause-engine-version-stale causes pause-window-on-restart failure.** When Recharge-SubscriptionPause engine-version is stale, the pause-window is miscalculated, leading to premature-restart. Fix: F535.
14. **P14 — Subscription-swap-engine-version-stale causes swap-state-on-inventory-check failure.** When the swap-engine-version is stale, the swap is attempted on out-of-stock variants. Fix: F536.
15. **P15 — Subscription-gift-engine-version-stale causes gift-balance-on-redemption failure.** When the gift-engine-version is stale, the gift balance is double-spent. Fix: F537.
16. **P16 — The 486,643,441,191,953,628,367,176,000,015,052,800,000,000-cell deep cross-validation matrix computation-budget is ~6-8× Move #3.48's 5-7× Move #3.47's 5× Move #3.46's 5× budget.** Materialize on BigQuery + Snowflake + Databricks with materialized-view + dbt-model; refresh-time 7-9 hours; storage-cost $440k-$715k/year; compute-cost $210k-$410k/year. Use incremental refresh: only refresh cells with state-changes since last refresh.
17. **P17 — 29th BFCM-cohort-traffic-burst-rollback-engine-required-for-octo-centesimal-axis-specific-traffic-burst.** When a single octo-centesimal-axis fires a traffic-burst (e.g. Product-feed-engine-version-stale triggers a 40× listing-push burst), the rollback must auto-promote per-octane-centesimal-axis-rollback, NOT a global rollback. 19. **P19 — Checkout-script-engine-version-stale causes script-version-on-discount-application failure.** When the script-engine-version is stale, the discount-application script runs the wrong version. Symptom: +52% discount-application-failure during BFCM. Fix: F539.
20. **P20 — Cart-persistent-engine-version-stale causes persisted-cart-on-cross-device failure.** When the cart-persistent-engine-version is stale, the cross-device cart doesn't sync. Symptom: +48% cross-device-cart-loss. Fix: F542.
21. **P21 — Product-recommendation-engine-version-stale causes recommendation-on-pdp-load failure.** When Nosto-ProductRecommendation engine-version is stale, the PDP shows recommendations from 30+ days ago. Symptom: +44% recommendation-ctr-loss. Fix: F544.
