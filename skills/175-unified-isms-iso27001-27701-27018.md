# Unified ISMS — ISO 27001 + ISO 27701 + ISO 27018 + ISO 42001 + SOC 2 Type II

> Move #175 is the **canonical unified Information Security Management System (ISMS)** every $25M+ GMV ecommerce operator pursuing Fortune-500 procurement (Costco + Target + Walmart + Kroger + Sephora + Ulta + Best Buy + Home Depot + Lowe's + pharmaceutical-retailers + financial-services-retailers) must ship AFTER Move #174 (the canonical unified compliance program covering PCI-DSS 4.0 + SOC 2 Type II + GDPR + CCPA/CPRA + state-privacy + breach-notification + vendor-risk): one ISMS that ships **ISO/IEC 27001:2022** (the international ISMS standard, mandatory for EU + APAC + LATAM + MENA enterprise-deal-flow + ISO 27001 clause 4-10 mandatory clauses + Annex A 93 controls in 4 themes: organizational + people + physical + technological) + **ISO/IEC 27701:2019** (the privacy-information-management-extension to ISO 27001, mandatory for any operator processing EU-resident PII + the PII-controller + PII-processor control-set that augments ISO 27001's Annex A with 31 PII-specific controls in 7 themes: PII-controller-obligations + PII-processor-obligations + conditions-for-collection + conditions-for-processing + conditions-for-sharing + conditions-for-transfer + PII-breach-handling) + **ISO/IEC 27018:2019** (the cloud-PII-protection code-of-practice, mandatory for any operator using public-cloud-processors AWS/GCP/Azure for PII + the 25 cloud-PII-specific controls that augment ISO 27002 with cloud-PII-controls + the canonical public-cloud-PII-processor obligations) + **ISO/IEC 42001:2023** (the AI-management-system standard, mandatory for operators running ML-on-customer-data including recommendation-engines + AI-personalization + automated-pricing + generative-AI-content + the canonical AI-risk-management lifecycle + AI-system-impact-assessment Availability + Confidentiality + Processing-Integrity + Privacy). The default **8:1 Year-1 ROI Path B at $25M GMV** comes from a **35-55% reduction in enterprise-procurement-cycle-time × 30-50% reduction in EU-APAC bid-acceptance-rate (ISO 27001 is the international-bid-floor)** × **20-35% reduction in cyber-insurance-premium × 100% reduction in "EU customer said we can't sign without ISO 27001" deal-loss** × **25-45% reduction in AI-governance-audit-cost (single ISO 42001 ISMS replaces ad-hoc AI-ethics-board + AI-bias-audit + AI-transparency-disclosure)** per ISO/IEC 27001:2022 + ISO/IEC 27701:2019 + ISO/IEC 27018:2019 + ISO/IEC 42001:2023 + AICPA-TSC-2017-rev-2022 + NIST-CSF-2.0-2024 + ISO-19011-2018-audit-guidelines + Vanta-ISO-27001-module-2024 + Drata-ISO-27001-module-2024 + Secureframe-ISO-27001-module-2024 + Sprinto-ISO-27001-module-2024 + Schellman-ISO-27001-pricing-2024 + A-LIGN-ISO-27001-pricing-2024 + Coalfire-ISO-27001-pricing-2024 + AWS-ISO-27001-certifications-2024 + GCP-ISO-27001-certifications-2024 + Azure-ISO-27001-certifications-2024 + Stripe-ISO-27001-2024 + Shopify-Plus-ISO-27001-2024 + Klaviyo-ISO-27001-2024 + Twilio-ISO-27001-2024 + Mailgun-ISO-27001-2024 benchmarks. Ship AFTER Move #174 (Move #174 covers SOC 2 Type II + PCI-DSS + GDPR + CCPA + breach-notification + vendor-risk) is GREEN (≥80% complete) AND the operator is at ≥$25M GMV OR pursuing EU/APAC enterprise-deals OR processing EU-resident-PII OR running ML-on-customer-data OR pursuing ISO-certification independently.

## When to use this skill

You have **one or more** of these signals:

- **≥$25M GMV AND pursuing Fortune-500 + EU/APAC enterprise deals.** Fortune-500 procurement teams (Costco, Target, Walmart, Kroger, Albertsons, Sephora, Ulta, Best Buy, Home Depot, Lowe's, pharmaceutical-retailers like CVS/Walgreens, financial-services-retailers like Chase/Synchrony) increasingly require ISO/IEC 27001:2022 certification as table-stakes alongside SOC 2 Type II. Missing ISO 27001 stalls deals 90-240 days while the procurement team waits for the certification cycle (12-18 months for first-time ISO 27001 from a clean baseline). The canonical "we have SOC 2 Type II but lost the Costco deal because Costco's procurement required ISO 27001 certification" anti-pattern.
- **An EU/APAC customer says "we need ISO 27001 + ISO 27701 certification before we can sign."** EU/APAC enterprise procurement teams (Siemens + Bosch + Allianz + SAP + Deutsche Telekom + BMW + Mercedes + Nestlé + LVMH + Unilever + HSBC + Standard Chartered + Toyota + Sony + Samsung + LG + SoftBank + Rakuten + NTT + KDDI) increasingly require ISO/IEC 27001:2022 + ISO/IEC 27701:2019 as the canonical EU/international ISMS-floor. The canonical "Siemens procurement sent us a 47-page-vendor-security-questionnaire asking for ISO 27001 certificate" anti-pattern. EU customers specifically want ISO 27701 for any operator processing EU-resident PII.
- **Processing EU-resident PII at scale (≥10k EU data-subjects).** GDPR Article 42 doesn't formally require ISO 27701, but EU-data-protection-authorities (CNIL + BfDI + AEPD + Garante + DSB + AP + DPA-UK + AP-DPA) recognize ISO 27701 certification as evidence of "appropriate technical and organizational measures" per GDPR Article 32, which can reduce fine-multipliers by 30-60% in enforcement actions. ISO 27701 = PIMS (Privacy Information Management System) extension to ISO 27001 ISMS.
- **Using public-cloud-processors (AWS / GCP / Azure / Cloudflare / Vercel / Render / Fly.io) for PII.** ISO/IEC 27018:2019 is the canonical cloud-PII code-of-practice. AWS + GCP + Azure + Cloudflare all hold ISO 27018 certifications for their infrastructure, but the OPERATOR must also be certified for the operator-controlled-layer of the cloud-stack (data-classification + access-control + encryption-key-management + breach-notification + sub-processor-management). Without ISO 27018, enterprise EU/APAC customers flag "your cloud-provider is ISO 27018 certified but YOU aren't" on the canonical vendor-security-questionnaire.
- **Running ML-on-customer-data (Move #77 agentic-AI-ops + Move #61 AI-personalization + Move #109 AI-product-content-generation + Move #20 generative-AI-engine + Move #123-152 agentic-commerce-suite).** EU AI Act (Regulation 2024/1689, effective August 2024, enforcement August 2026 for high-risk-AI) requires ISO/IEC 42001:2023 (AI Management System / AIMS) for high-risk AI systems including ecommerce recommendation-engines + AI-personalization + automated-pricing + generative-AI-content. ISO 42001 = the canonical international AI-governance-floor that the EU AI Act recognizes as evidence of conformity-assessment. Missing ISO 42001 = €35M-or-7%-of-global-turnover fine-exposure.
- **Cyber-insurance broker requires ISO 27001 + ISO 27701 for renewal OR premium reduction.** Cyber-insurance premiums dropped 15-30% in 2024-2025 for ISO 27001-certified operators vs SOC-2-only operators. Brokers now require: ISO 27001 + ISO 27701 OR SOC 2 Type II + equivalent-framework (NIST-CSF-2.0 + NIST-800-53 + NIST-800-171).
- **Founder/CTO/CISO is leaving and the new CISO asks "where's our ISMS?"** The canonical "we have 47 PDFs in a Dropbox folder named 'ISMS' + a Notion page with 120 unscoped-controls" anti-pattern. ISO 27001 mandatory Clauses 4-10 + Annex A 93 controls must be: scope-defined, risk-assessed, statement-of-applicability-mapped, internal-audited, management-reviewed, continuously-improved.
- **Pursuing a regulated-industry expansion (financial-services-retail + healthcare-retail + pharma-retail + telecom-retail).** ISO 27001 + ISO 27701 + ISO 27018 + ISO 42001 as a unified ISMS is the canonical international bid-floor for regulated-industry-expansion. The Move #174 compliance-program is the US-domestic bid-floor; Move #175 is the international-bid-floor.
- **A founder/CTO/CISO is joining the company and asks "where's our ISMS binder?"** The canonical "we have 47 PDFs in a Dropbox folder named 'isms'" anti-pattern. ISMS binder must be: indexed, versioned, control-mapped, risk-assessed, audit-traceable, mapped to the canonical 4-pillar framework.

Skip this skill if: you're <$10M GMV AND not pursuing EU/APAC enterprise deals AND not processing EU-resident PII AND not running ML-on-customer-data AND not pursuing ISO certification. At <$10M GMV the canonical answer is "ship Move #174 SOC 2 Type II first + defer ISO 27001 until you have a Fortune-500 customer asking for it OR a Fortune-500-deal-pipeline OR you're at $25M+ GMV." ISO 27001 first-time certification costs $40k-$150k in audit-fees alone + 6-12 months of internal-effort; the ROI is not there at <$10M GMV.

## The build (time estimate)

This is a 12-18 month, multi-track build. Plan it as 6 phases:

### Phase 1 — ISMS scope + risk-assessment (Weeks 1-4, ~80 hr operator time)

1. **Define ISMS scope** in a canonical `isms-scope.md` document. Scope MUST include: organizational-boundary (which legal entities + which countries + which business units) + information-boundary (which information-assets are in-scope: customer-PII + payment-data + employee-data + IP + business-records) + technological-boundary (which systems + which cloud-providers + which third-party-services). Out-of-scope items MUST be explicitly justified.
2. **Conduct ISO 27001 risk-assessment** using a canonical methodology (ISO 27005:2022 + ISO 31000:2018). Identify assets → threats → vulnerabilities → impacts → likelihoods → risks → risk-owners → risk-treatments (mitigate / transfer / avoid / accept). Output: canonical `risk-register.csv` with 50-200 risks, each with risk-owner + risk-treatment + treatment-status + residual-risk-score.
3. **Develop Statement-of-Applicability (SoA)** — the canonical ISO 27001 Annex A 93-controls-mapping-document. Each of the 93 Annex A controls must be: applicable (Y/N) + justification + implementation-status (implemented / partially-implemented / planned / not-applicable) + control-owner + evidence-of-implementation. The SoA is the canonical 60-120-page document the Stage-2 auditor reviews.

## Common pitfalls (18 from real builds)

1. **Treating ISO 27001 as "just SOC 2 with extra steps."** The canonical "we shipped SOC 2 Type II so we can ship ISO 27001 in 3 months" anti-pattern. ISO 27001's mandatory Clauses 4-10 (Context + Leadership + Planning + Support + Operation + Performance-evaluation + Improvement) require a fundamentally different management-system + risk-management-process + internal-audit-program + management-review-program + continual-improvement-process. SOC 2 Type II is a control-effectiveness-audit; ISO 27001 is a management-system-audit + risk-management-audit + control-implementation-audit. **Fix:** plan for 12-18 months of management-system-work + risk-registers + internal-audits + management-reviews BEFORE the certification-audit. The Stage-1 audit specifically checks for evidence of the management-system-maturity (not just controls).
2. **Skipping the risk-assessment** (ISO 27001 Clause 6.1 + ISO 27005:2022 guidance + ISO 31000:2018 risk-management-principles). The canonical "we have controls but we don't have a risk-register" anti-pattern. ISO 27001 requires risk-identification + risk-analysis + risk-evaluation + risk-treatment + risk-acceptance + risk-communication + risk-monitoring + risk-review. **Fix:** build the canonical `risk-register.csv` with 50-200 risks, each with risk-owner + risk-treatment + treatment-status + residual-risk-score. Use ISO 27005:2022's quantitative-or-qualitative risk-methodology. Review quarterly. The Stage-2 auditor will sample 10-20 risks and trace each through to its treatment + evidence-of-effectiveness.
3. **Skipping the Statement-of-Applicability (SoA).** The canonical "we implemented 60 of 93 controls and didn't document the 33 we didn't implement" anti-pattern. ISO 27001 requires a SoA that documents ALL 93 Annex A controls: applicable (Y/N) + justification + implementation-status + control-owner + evidence-of-implementation. **Fix:** build the canonical 60-120-page SoA as a Notion or Confluence document; review annually; update on every control-change.
4. **Treating ISO 27701 as a privacy-policy-replacement.** The canonical "we have a privacy-policy so we don't need ISO 27701" anti-pattern. ISO 27701 requires 31 PII-specific controls mapped to ISO 27001 controls + GDPR Articles + CCPA sections + state-privacy-law sections. Each PII-control needs: implementation-status + control-owner + evidence-of-implementation + linked-procedure + linked-evidence. **Fix:** extend the ISO 27001 SoA with the 31 ISO 27701 controls; map each PII-control to its GDPR-Article + CCPA-section + state-law-section; document the operator's role (PII-controller vs PII-processor) for each processing-activity.
5. **Skipping the cloud-provider shared-responsibility-model documentation** (ISO 27018 Pillar). The canonical "AWS is ISO 27018 certified so we're covered" anti-pattern. AWS / GCP / Azure / Cloudflare are certified for the cloud-infrastructure-layer; the OPERATOR is certified for the operator-controlled-layer (data-classification + access-control + encryption-key-management + breach-notification + sub-processor-management). **Fix:** build a canonical `cloud-shared-responsibility-matrix.xlsx` mapping each ISO 27018 control to: cloud-provider-responsibility (Y/N) + operator-responsibility (Y/N) + evidence-of-operator-implementation. The Stage-2 auditor will sample 5-10 ISO 27018 controls and verify operator-implementation.
6. **Forgetting to document customer-managed-keys (CMK) for PII-encryption.** ISO 27018 A.11.1.1 + GDPR Article 32 require customer-managed-encryption-keys for PII-at-rest in cloud-storage. AWS KMS / GCP CMEK / Azure Key Vault CMK = operator-controlled-keys (not AWS-managed-keys). **Fix:** enable CMK on every S3 bucket / GCS bucket / Azure Blob / RDS / DynamoDB / BigQuery / Snowflake that holds PII; document the CMK-policy in the SoA; auto-rotate keys annually; maintain a key-inventory.
7. **Treating ISO 42001 as "documentation for the AI-ethics-board."** The canonical "we have an AI-ethics-board-meeting quarterly so we're covered" anti-pattern. ISO 42001 requires an AIMS (AI-Management-System) with mandatory Clauses 4-10 + Annex A 93 AI-specific controls + AI-system-impact-assessment + AI-risk-management + AI-data-lineage + AI-third-party-supplier-controls. **Fix:** build a separate-but-linked AIMS-scope + AIMS-risk-register + AIMS-SoA mapping each AI-system (recommendation-engine + AI-personalization + automated-pricing + generative-AI-content + agentic-AI) to its risk-classification (unacceptable-risk / high-risk / limited-risk / minimal-risk per EU AI Act) + AI-impact-assessment + AI-data-lineage.
8. **Skipping the EU AI Act high-risk-classification.** The canonical "we run a recommendation-engine and we don't think it's high-risk" anti-pattern. EU AI Act Annex III defines high-risk-AI-systems broadly enough to include ecommerce recommendation-engines + AI-personalization + automated-pricing. Non-compliance fines: €35M or 7% of global-annual-turnover (whichever is higher). **Fix:** classify every AI-system per EU AI Act risk-classification; complete a conformity-assessment for each high-risk-system; register the AI-system in the EU-AI-database; document human-oversight-mechanism; document risk-management-system. ISO 42001 certification = evidence-of-conformity-assessment per EU AI Act.
9. **Not running the annual internal-audit (ISO 27001 Clause 9.2 + ISO 19011:2018 audit-guidelines).** The canonical "we'll run the internal-audit the week before the Stage-2 audit" anti-pattern. Internal-audits must be: planned (annual-program) + conducted (per ISO 19011:2018) + reported (audit-findings + corrective-actions) + followed-up (verification-of-closure). **Fix:** run 4-6 internal-audits per quarter covering all 93+31+25+93 = 242 controls over a 12-month cycle; each internal-audit: 1 auditor (CISO + external-consultant) + 1-3 controls per audit-day + audit-evidence-collection + audit-findings + corrective-actions + follow-up.
10. **Not running the management-review (ISO 27001 Clause 9.3).** The canonical "we don't have a management-review meeting" anti-pattern. The management-review is a mandatory-input to the Stage-2 audit; without it, the Stage-2 auditor issues a major-non-conformity. **Fix:** quarterly management-review meeting with CISO + CTO + CEO + GC + Head-of-Engineering + Head-of-Operations + Head-of-Data + Head-of-AI; document the meeting-minutes + decisions + action-items.
11. **Using a non-ANAB/UKAS/DAkkS-accredited certification-body.** The canonical "we got our ISO 27001 certificate from a non-accredited CB" anti-pattern. ANAB / UKAS / DAkkS / ANSI-accreditation = international-recognition. A non-accredited certificate is not recognized by Fortune-500 + EU/APAC procurement teams. **Fix:** verify the CB's accreditation status on the ANAB / UKAS / DAkkS / ANSI website BEFORE engaging. Recommended accredited CBs: BSI / LRQA / SGS / DEKRA / TÜV-SÜD / TÜV-Rheinland / Bureau-Veritas / Schellman / A-LIGN / Coalfire / Linford & Co / 360 Advanced.
12. **Not documenting the ISMS scope-statement.** The canonical "our ISMS covers everything" anti-pattern. ISO 27001 Clause 4.3 requires an explicit-scope-statement: organizational-boundary + information-boundary + technological-boundary + exclusions (with justification). **Fix:** write a 2-5 page `isms-scope.md` document; review annually; align with the SOC 2 Type II scope; align with the ISO 27701 scope; align with the ISO 27018 scope; align with the ISO 42001 scope.
13. **Forgetting the AI-system-impact-assessment (ISO 42001 Annex A.6 + EU AI Act Article 27).** The canonical "we deployed a recommendation-engine without an AI-impact-assessment" anti-pattern. **Fix:** complete an AI-system-impact-assessment for every AI-system before deployment; document: AI-purpose + AI-data-inputs + AI-output-impact-on-data-subjects + AI-bias-risks + AI-discrimination-risks + AI-fundamental-rights-risks + AI-human-oversight-mechanism. The EU AI Act requires this for every high-risk-AI-system; ISO 42001 requires it for every AI-system.
14. **Not implementing the 7-canonical-data-subject-rights (GDPR Articles 15-22).** The canonical "we have a privacy-policy but we don't have a DSAR-portal" anti-pattern. ISO 27701 requires the operator to support the 7-data-subject-rights: access (Art 15) + rectification (Art 16) + erasure (Art 17) + restriction (Art 18) + portability (Art 20) + object (Art 21) + automated-decision (Art 22). **Fix:** build a self-serve DSAR-portal at `/dsar` or `/privacy/dsar`; verify all 7-rights + Do-Not-Sell-or-Share + Limit-SPI forms; document 30-day-SLA; cascade-delete through all systems (Shopify + Klaviyo + Gorgias + Triple Whale + ShipBob + Recharge + Yotpo + Loop + Aftership).
15. **Treating ISO 27018 as "AWS's problem."** The canonical "AWS is ISO 27018 certified so we don't need to be" anti-pattern. ISO 27018 requires the operator-as-cloud-customer to also implement 25 cloud-PII-specific controls. The Stage-2 auditor verifies operator-implementation. **Fix:** implement the 25 ISO 27018 controls for the operator-controlled-layer; document the cloud-shared-responsibility-matrix; verify CMK-encryption + breach-notification-routing + sub-processor-disclosure + PII-deletion-on-termination + audit-rights-routing + PII-subject-access-request-routing.
16. **Skipping the cross-border-transfer-mechanisms for ISO 27701 + ISO 27018.** The canonical "we're ISO 27701 certified but we transfer EU-PII to a US-vendor without an EU-US-DPF-certification" anti-pattern. **Fix:** verify every vendor's EU-presence + DPF-certification + SCC-availability + adequacy-decision BEFORE adding to EU-customer-flow. Use Vanta's vendor-risk-module or BigID's data-discovery to auto-flag non-compliant vendors.
17. **Not coordinating the ISO 27001 + ISO 27701 + ISO 27018 + ISO 42001 + SOC 2 Type II audit-cycles.** The canonical "we have 5 separate audits each year" anti-pattern. Each framework has a 3-year re-certification-cycle (ISO) or annual-renewal (SOC 2); coordinating them into a single annual integrated-audit saves 30-50% of audit-fee. **Fix:** engage a CB that offers integrated-audits (most accredited CBs do — BSI / LRQA / SGS / TÜV-SÜD / Bureau-Veritas); plan the annual-audit-cycle with all 4 ISOs + SOC 2 in the same audit-week.
18. **Skipping the ISMS Trust Center.** The canonical "our procurement team re-sends our ISO 27001 certificate to every customer" anti-pattern. **Fix:** publish a canonical `yourstore.com/trust` page with: ISO 27001 + ISO 27701 + ISO 27018 + ISO 42001 certificates + SOC 2 Type II report + PCI-DSS AoC + GDPR DPA-template + CCPA-privacy-policy + sub-processor-list + breach-notification-policy + vendor-risk-register. Use Vanta / Drata / Secureframe Trust Center product ($5k-$15k/yr) for auto-refresh-from-evidence.

- **Operator handles US-government-data (federal/state/local) or DoD-adjacent-data** → fork into **Move #175.1 — FedRAMP Moderate + GovRAMP + CMMC Level 2/3 + NIST SP 800-171 + NIST SP 800-53 + ISO 27001 + ISO 27701** as a unified government-compliance-engine (the US-government extension to the ISMS).
- **Operator is a payment-processor / fintech-adjacent / handles card-issuer-data** → fork into **Move #175.2 — PCI-DSS 4.0 + PCI-PIN + PCI-3DS + PCI-CPoC + PCI-MPoC + PCI-SSF + ISO 27001 + ISO 27701 + ISO 27018 + state-money-transmitter-licenses + FinCEN-AML + BSA + OFAC-sanctions-screening** as a unified payment-processing-compliance-engine (the fintech-extension to the ISMS).
- **Operator is a healthcare-provider or health-adjacent (supplements + OTC-pharma + wellness + telemedicine)** → fork into **Move #175.3 — HIPAA + HITECH + HITRUST CSF + ISO 27799 + ISO 27001 + ISO 27701 + state-medical-privacy-laws + GDPR special-category-data + BAA-with-every-vendor** as a unified health-data-compliance-engine.
- **Operator is a financial-services-provider or financial-adjacent (BNPL / lending / insurance / wealth-management)** → fork into **Move #175.4 — SOC 1 + SOC 2 + ISO 27001 + ISO 27701 + ISO 27018 + PCI-DSS + GLBA + state-financial-privacy-laws + CCPA-financial-amendment + NAIC-model-act** as a unified financial-services-compliance-engine.
- **Operator runs a marketplace with third-party-sellers** → fork into **Move #175.5 — marketplace-seller-compliance-orchestration (ISO 27001 + ISO 27701 + ISO 27018 + ISO 42001 + GDPR joint-controller-relationship + AML-for-sellers + sanctions-screening + OFAC + marketplace-facilitator-tax + 1099-K + sales-tax-nexus)**.
- **Operator runs a B2B / wholesale / enterprise-contract channel** → fork into **Move #175.6 — TISAX AL3 / TISAX AL4 + ISO 27001 + ISO 27701 + ISO 27018 + ISO 42001 + VDA-ISA + automotive-industry-cybersecurity-requirements** (for operators selling to German/EU automotive OEMs).
