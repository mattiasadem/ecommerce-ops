## Common pitfalls (15 from real builds)

P1. **Don't reach for Move #167.5.12.1.6.4.2.1 first** — the parent per-acquirer template-library rate-notice-letter-counter-proposal-letter extension is a SINGLE-acquirer counter-proposal flow; the Move #167.5.12.1.6.4.2.1.1 portfolio extension is a PORTFOLIO-counter-proposal flow (2+ acquirers in parallel). Without the parent first, the portfolio extension has no per-acquirer-rate-notice-counter-proposal-letter-template-library to extend.

P2. **Don't reach for Move #167.5.12.1.6.4.2 first** — the Move #167.5.12.1.6.4.2 per-acquirer template-library rate-notice-letter extension is a REBUTTAL flow (responding to a per-acquirer-rate-notice WITHOUT counter-proposing); the Move #167.5.12.1.6.4.2.1 counter-proposal-letter extension is a COUNTER-PROPOSAL flow (responding to a per-acquirer-rate-notice WITH a counter-proposal); the Move #167.5.12.1.6.4.2.1.1 portfolio extension is a PORTFOLIO-COUNTER-PROPOSAL flow (responding to 2+ per-acquirer-rate-notices WITH a SINGLE PORTFOLIO-WIDE counter-proposal).

P3. **Don't skip the per-acquirer-portfolio-context row in the per-acquirer-rate-notice-counter-proposal-portfolio-leverage matrix** — without the per-acquirer-portfolio-share dimension, the per-acquirer-portfolio-leverage-score is unweighted (treats Stripe and Braintree equally regardless of per-acquirer-portfolio-share of 40% vs 5%) and produces misleading per-acquirer-portfolio-counter-proposal-advice.

P4. **Don't use a per-acquirer-portfolio-aligned-window = min(objection-deadlines) instead of max** — the per-acquirer-portfolio-aligned-window should be the LATEST acceptance-deadline across N acquirers (so the per-acquirer-portfolio-counter-proposal-response has time to negotiate with the LATEST acquirer), NOT the EARLIEST (which would force the operator to submit before the EARLIEST acquirer's deadline, leaving NO time for the LATEST acquirer).

P5. **Don't hardcode per-acquirer-portfolio-walk-away-threshold = -0.10% net discount** — the per-acquirer-portfolio-walk-away-threshold varies by per-acquirer-portfolio-size (Path A 2 acquirers: -0.05% / Path B 3-5 acquirers: -0.10% / Path C 7-13 acquirers: -0.15% / Path D 25+ acquirers: -0.20% / Path E 50+ acquirers: -0.30%) and by per-acquirer-portfolio-multi-region (NORAM-only: -0.10% / multi-region: -0.15% / global: -0.25%).

P6. **Don't skip the per-acquirer-portfolio-counter-proposal-BAFO-process for 25+ acquirers** — at Path D 25+ acquirers, the per-acquirer-portfolio-counter-proposal-BAFO-process must run in parallel for ALL 25 acquirers (not just the 5 canonical acquirers), and the per-acquirer-portfolio-counter-proposal-walk-away-trigger must be calibrated per-acquirer (different per-acquirer-walk-away-thresholds per acquirer based on per-acquirer-portfolio-share).

P7. **Don't hardcode the per-acquirer-portfolio-counter-proposal-ask-mix** — the per-acquirer-portfolio-optimal-ask-mix should be computed per-acquirer-portfolio from the per-acquirer-rate-notice-counter-proposal-portfolio-ask-ladder + the per-acquirer-rate-notice-counter-proposal-portfolio-leverage matrix, NOT hardcoded (a hardcoded ask-mix would treat all N acquirers the same regardless of per-acquirer-portfolio-share + per-acquirer-leverage-score + per-acquirer-pass-through-type).

P8. **Don't ignore per-acquirer-portfolio-multi-region context** — at Path C/D/E with multi-region acquirers (NORAM + EU + APAC), the per-acquirer-rate-notice-counter-proposal-portfolio-leverage matrix must include per-acquirer-multi-region-leverage-dimension (NORAM = Visa VAMP 2026 + MasterCard ECM 2026 + AmEx MER 2026 + Discover DMP 2026 / EU = BaFin ZAG + PSD2-RTS + DSGVO + BDSG + TTDSG + GwG + MICA + DORA / APAC = JCB JDRP 2026 + UnionPay UPGD 2026 + region-bucks-PE/AR/CL/MX/BR/CO 2026).

P9. **Don't skip the per-acquirer-portfolio-counter-proposal-brief template** — without the per-acquirer-rate-notice-counter-proposal-portfolio-brief template (the canonical 4-section CFO-board-pack brief: Per-Acquirer-Rate-Notice-Portfolio-Counter-Summary → Per-Acquirer-Rate-Notice-Portfolio-Counter-Asks (Top-3 per acquirer) → Per-Acquirer-Rate-Notice-Portfolio-Counter-Proposal-Leverage-Bundle (Top-3 dim) → Per-Acquirer-Rate-Notice-Portfolio-Counter-Proposal-Window + Per-Acquirer-Rate-Notice-Portfolio-Counter-BAFO-Process), the CFO + board + audit committee has no 1-pager summary to consume in 5 minutes.

P11. **Don't ignore per-acquirer-portfolio-network-program-passthrough-isolation** — at Path B/C/D with 3+ acquirers, the per-acquirer-portfolio-network-program-passthrough-isolation-dimension should be per-acquirer-network-program-passthrough-isolation (Visa VAMP 2026 +0.02% / MasterCard ECM 2026 +0.015% / AmEx MER 2026 +0.01% / Discover DMP 2026 +0.01% / JCB JDRP 2026 +0.005% / UnionPay UPGD 2026 +0.01% / 6 region-bucks-PE/AR/CL/MX/BR/CO 2026 +0.005-0.02%) — without it, the per-acquirer-portfolio-counter-proposal-advice is naive to network-program updates.

P12. **Don't skip the per-acquirer-portfolio-counter-proposal-window-bundle for multi-acquirer-portfolio with staggered deadlines** — at Path B with 3-5 acquirers, the per-acquirer-portfolio-counter-proposal-window-bundle must compute per-acquirer-portfolio-aligned-window = max(per-acquirer-counter-proposal-acceptance-deadline across N acquirers), NOT min — and the per-acquirer-portfolio-counter-proposal-acceptance-window must be the SUM of per-acquirer-counter-proposal-acceptance-windows across N acquirers (so the operator has time to negotiate with all N acquirers).

P13. **Don't hardcode per-acquirer-portfolio-counter-proposal-render time = 1-3s** — at Path E 50+ acquirers, the per-acquirer-portfolio-counter-proposal-render time grows linearly with N (N=50 acquirers → 5-15s render time; N=25 acquirers → 2-7s render time). Use lazy evaluation per-acquirer-portfolio-segment to keep the canonical per-acquirer render time at 1-3s for Path B mid-market case.

P14. **Don't skip the per-acquirer-portfolio-counter-proposal-walk-away-trigger state per acquirer** — without the per-acquirer-portfolio-counter-proposal-walk-away-trigger state per acquirer, the operator has no visibility into which acquirers to SUBMIT a counter-counter-counter (BAFO) vs which to WALK AWAY from. Without per-acquirer-portfolio-walk-away-state-per-acquirer, the operator risks submitting BAFO to acquirers that have already exceeded the per-acquirer-portfolio-walk-away-threshold.

P15. **Generalize to ANY per-acquirer-rate-notice-counter-proposal-portfolio flow** — the per-acquirer-rate-notice-counter-proposal-portfolio-template-library generalizes to ANY per-acquirer-rate-notice-counter-proposal-portfolio flow (1 acquirer / 2 acquirers / 3 acquirers / 5 acquirers / 7 acquirers / 10 acquirers / 13 acquirers / 25 acquirers / 50+ acquirers × USD / EUR / GBP / JPY / AUD / BRL / INR / CNY × NORAM-US-CA-MX / EU-DE-FR-IT-ES-NL-PL-CZ-HU-RO / UK / APAC-AU-NZ-JP-KR-SG-HK / LATAM-BR-MX-AR-CL-CO-PE × micro / mid / enterprise / global / hyper-scale). The same 5-template-family + 10-step render pipeline + 8 question-intent-detection regex rules apply.
