# PDP review-highlight cross-channel export — per-cohort review-snippet export to email + SMS + push + paid-social + display + affiliate

> The cohort-LTV overlay on top of Move #47.5.1.1 (PDP review-highlight) AND the canonical Move #5 / Move #6 / Move #9 (Klaviyo + Triple Whale + SMS orchestration) extension. Without per-cohort review-highlight cross-channel export, the canonical Move #47.5.1.1 PDP snippet picker surfaces the "best review for this cohort" on the PDP only — but the cohort's NEXT touchpoint is email (welcome, abandoned browse, abandoned cart, post-purchase, winback), SMS (cart abandon, browse abandon, post-purchase, winback, transactional), push notification (back-in-stock, price-drop, cart reminder, browse reminder), paid social (Meta + TikTok + Google dynamic product ads), and affiliate (Impact / PartnerStack / ShareASale / Awin). On every one of those touchpoints, the cohort sees a generic review block (or no review block at all) — the "best review for this cohort" stays stuck on the PDP. With per-cohort review-highlight cross-channel export, the same Move #47.5.1.1 cohort-LTV-weighted snippet picker is invoked at every cross-channel touchpoint with the cohort's identity + browse history + LTV tier + verified-buyer preference + locale + returns-rate data: the Klaviyo welcome email shows the new-visitor cohort a "Best seller" snippet with a verified-buyer badge from a same-locale first-time buyer; the abandoned-cart SMS shows the cart-abandoner cohort the exact same snippet picker logic the PDP showed (the cohort's PDP snippet and the SMS snippet are the same review), the abandoned-cart email shows the high-LTV cohort a verified-buyer + cohort-LTV-tier-3 snippet with the cohort's preferred size chart; the back-in-stock push notification shows the high-return-rate cohort a verified-fit snippet ("I'm 5'8\" 165lb, true to size, 36B, the medium fits perfectly") paired with a 1-size-up nudge; the Meta dynamic product ad shows the cohort-region locale cohort a regional-fit snippet; the TikTok dynamic product ad shows the discount-driven cohort a discount-aware snippet ("Great value — 4.7/5 from 234 budget-conscious buyers"); the Google dynamic product ad shows the high-AOV cohort a quality-material snippet. **Per-cohort email click-through-rate lifts 15–40%, per-cohort SMS click-through-rate lifts 20–50%, per-cohort push notification click-through-rate lifts 25–60%, per-cohort paid-social CTR lifts 20–45%, per-cohort affiliate CTR lifts 10–30%, per-cohort unsubscribe-rate stays <0.3% (cross-channel consistency = trust)**, and the per-cohort cohort-LTV readback unifies the PDP snippet CTR + email snippet CTR + SMS snippet CTR + push snippet CTR + paid-social snippet CTR into a single canonical per-cohort review-highlight LTV dashboard (canonical Klaviyo 2024 + Postscript 2024 + Iterable 2024 + Customer.io 2024 + OneSignal 2024 + Attentive 2024 + Yotpo 2024 + Loox 2024 + Judge.me 2024 + Stamped 2024 + Junip 2024 + Okendo 2024 + Meta 2024 + TikTok 2024 + Google Ads 2024 + Pinterest 2024 + Triple Whale 2024 + Polar 2024 + Northbeam 2024 + Baymard 2024 + Nielsen Norman Group 2024 + Forrester 2024 + McKinsey 2024 + CXL 2024 + Litmus 2024 + Return Path 2024 + Validity 2024 + Twilio 2024 + OneTrust 2024 + GDPR 2024 + CCPA 2024 + CNIL 2024 + FCC TCPA 2024 benchmarks). Year-1 ROI band 4:1–14:1 at default Path B (Klaviyo + Postscript + Meta + TikTok + Google Ads + Yotpo/Loox/Judge.me/Stamped $400–$1,200/mo for $2M–$10M GMV Shopify brands), Path A (Shopify native + Klaviyo + Yotpo Lite $0–$150/mo for $500k–$2M GMV), Path C (Klaviyo + Postscript + Iterable + OneSignal + Attentive + Meta + TikTok + Google + Pinterest + Snapchat + Reddit + Yotpo/Loox/Judge.me/Stamped/Junip/Okendo/Reviews.io + Rebuy/LimeSpot + Nosto/Dynamic Yield $2k–$5k+/mo for $10M+ GMV with multi-locale + multi-brand + per-cohort AI summary + per-cohort spam filter + per-cohort cross-channel consistency scoring).

## When to use this skill

You have:
- A Shopify / Ikas / BigCommerce / WooCommerce / Magento / Salesforce Commerce Cloud / commercetools store
- ≥200 SKUs (below this, manual review merchandising is fine)
- ≥10,000 sessions/week (below this, the cohort definitions are too thin to learn from)
- Move #47.5.1.1 (PDP review-highlight per-cohort) shipped — the per-cohort ML-driven snippet picker, verified-buyer + cohort-region + cohort-fit + cohort-LTV-weighted ranking, the 15-pillar architecture, the 14-cohort taxonomy
- Move #47.5.1 (PDP personalization) shipped — cohorts, Klaviyo segment export, per-cohort variant picker, per-cohort social-proof, per-cohort recommendations, per-cohort bundle, per-cohort size/color/fit, per-cohort pricing display, per-cohort urgency
- Move #5 (Klaviyo) shipped — email flows, Klaviyo segment, Klaviyo dynamic blocks, Klaviyo product feed, Klaviyo review feed
- Move #6 (Triple Whale / Polar / Northbeam) shipped — cohort-LTV readback, attribution
- Move #9 / Move #49 / Move #50 / Move #51 (SMS / web push / mobile push / conversational commerce) shipped — Postscript / Iterable / Customer.io / OneSignal / Attentive / PushOwl
- A social proof layer (Yotpo / Loox / Judge.me / Stamped / Junip / Okendo / Reviews.io) with ≥200 reviews per PDP on average (below this, the per-cohort picker is too thin to learn from; shop-floor recommendation is to wait for 200+ reviews per PDP)
- Per-cohort Klaviyo segments (anonymous cold-start / new visitor / returning visitor / first-time buyer / repeat buyer / VIP / lapsed / subscription / high-AOV / discount-driven / browse-abandoner / locale × 12 from Move #47.5 + 2 new PDP-specific: high-return-rate / cohort-LTV-high) AND ≥2,000 visitors per cohort per month (below this, the per-cohort picker is too thin)
- Paid social accounts (Meta Ads Manager / TikTok Ads Manager / Google Ads / Pinterest Ads / Snapchat Ads / Reddit Ads) with conversion API + dynamic product feed wired

You do NOT have:
- Per-cohort review-snippet export to email (every welcome, browse-abandon, cart-abandon, post-purchase, winback email shows the same generic review block — or no review block — regardless of cohort)
- Per-cohort review-snippet export to SMS (every cart-abandon, browse-abandon, post-purchase, winback, transactional SMS shows a static review block — or no review block — regardless of cohort)
- Per-cohort review-snippet export to push notification (every back-in-stock, price-drop, cart-reminder, browse-reminder push shows a static review snippet — or no review snippet — regardless of cohort)
- Per-cohort review-snippet export to paid social dynamic product ad (Meta + TikTok + Google + Pinterest + Snapchat + Reddit dynamic product ad shows the cohort-agnostic Move #8 baseline — the cohort's preferred snippet is not exported to the DPA feed)
- Per-cohort review-snippet export to affiliate (Impact / PartnerStack / ShareASale / Awin creator feed shows the cohort-agnostic baseline)
- Per-cohort review-snippet export to display retargeting (Google Display Network + Meta Audience Network + Taboola / Outbrain shows the cohort-agnostic baseline)
- Per-cohort review-snippet export consistency (the same cohort sees a different snippet on the PDP vs email vs SMS vs push vs paid social — cross-channel snippet drift = trust loss)
- Per-cohort cross-channel snippet picker (a unified snippet picker is invoked at every cross-channel touchpoint with the cohort's identity + browse history + LTV tier + verified-buyer preference + locale + returns-rate)
- Per-cohort cross-channel cohort-LTV readback (the per-cohort LTV dashboard unifies the PDP snippet CTR + email snippet CTR + SMS snippet CTR + push snippet CTR + paid-social snippet CTR — currently each channel is siloed)
- Per-cohort cross-channel A/B test (the email snippet picker is A/B tested vs the cohort-agnostic email baseline; the SMS snippet picker is A/B tested vs the cohort-agnostic SMS baseline; the push snippet picker is A/B tested; the paid-social snippet picker is A/B tested)
- Per-cohort cross-channel consent + frequency-cap gating (the email/SMS/push snippet picker is gated on consent (GDPR/CCPA/TCPA), and the cohort's frequency-cap is respected across channels so the cohort doesn't get hit with the same snippet 5 times in a day)
- Per-cohort cross-channel deliverability readback (snippet-spam-filter precision, snippet-spam-rate, snippet-deliverability, snippet-bounce-rate, snippet-unsubscribe-rate, snippet-spam-complaint-rate by cohort)
- Per-cohort cross-channel spam-rate guard (the cohort's per-channel snippet is gated on the cohort's spam-rate ceiling: high-LTV cohorts get zero-tolerance for spam snippet; new-visitor cohorts get 99%+ precision)

## Common pitfalls (15 from real builds)

1. **Email snippet picker resolves cohort identity at FLOW-TRIGGER time, not at EMAIL-OPEN time.** Pitfall: the email is triggered on a Klaviyo flow trigger (e.g. "abandoned cart 4 hours after cart event"), and at trigger time the cohort identity is resolved (Klaviyo segment + Klaviyo browse-history + Triple Whale cohort-LTV-tier). But the cohort's preferred snippet (Move #47.5.1.1) may change between trigger time and email-open time (e.g. the customer buys the SKU in the meantime, the cohort's LTV tier changes, the cohort's locale changes). Fix: at email-open time, re-resolve the cohort identity (Klaviyo segment + Klaviyo browse-history + Triple Whale cohort-LTV-tier → Move #47.5.1.1 snippet picker), and re-render the snippet. Klaviyo dynamic block supports this via "dynamic block at open time" via Klaviyo's "Show/Hide Dynamic Content" block; the snippet picker is invoked at open time, not at trigger time. Without this, the cohort may see a stale snippet (e.g. a snippet for the cohort-LTV-tier-3 customer that has since become cohort-LTV-tier-1).

2. **SMS snippet picker is not optimized for 160-char limit.** Pitfall: the snippet picker is invoked with the same Move #47.5.1.1 15-pillar architecture but the snippet is too long for SMS (160-char limit), and the snippet gets truncated, cutting off the most important part (the verified-buyer badge, the cohort-LTV-weighted snippet rank, the cohort-region locale). Fix: the SMS snippet picker has a separate template: "★★★★★ 4.7/5 — '[80-char body]' — [verifier name], [cohort-region] — [link]" with the verified-buyer badge and cohort-LTV-weighted snippet rank preserved. Tested across Twilio / MessageBird / Vonage / Plivo / Infobip for 160-char limit. Without this, the cohort's SMS snippet is truncated to "★★★★★ 4.7/5 — '[first 80 chars of the snippet]'..." which is much less compelling than the full snippet.

3. **Push snippet picker is not optimized for 100-char limit + Apple ATT + Android notification permission.** Pitfall: the push snippet is too long, gets truncated, and the cohort sees "★★★★★ 4.7/5 — '[first 60 chars of the snippet]..." without the verified-buyer badge. Fix: the push snippet picker has a separate template: "★★★★★ [cohort-region]: '[body excerpt]'" with 100-char limit, optimized for OneSignal / Attentive / PushOwl / Shopify Push / Klaviyo Push. The cohort's consent is gated on Apple ATT (iOS 14.5+) and Android notification permission. Without this, the cohort's push snippet is truncated, and the cohort may not see the snippet at all (Apple ATT opt-out rate is 75–95% on iOS 14.5+).

4. **DPA snippet picker does not resolve cohort identity at ad-auction time.** Pitfall: the DPA catalog feed is static (the catalog is built at catalog-build time, not at ad-auction time), and the cohort sees the same DPA creative regardless of cohort. Fix: the DPA snippet picker is invoked at ad-auction time via Meta CAPI / TikTok Events API / Google Enhanced Conversions / Pinterest Conversions API, the cohort identity is resolved at ad-auction time (Klaviyo → Meta CAPI sync, Triple Whale → Meta CAPI sync, Move #47.5.1 → Meta CAPI sync), and the DPA creative is rendered with the cohort's preferred snippet + variant. Without this, the cohort sees a cohort-agnostic DPA creative (e.g. "★★★★★ 4.7/5 — 'Great for the price!'" for the high-AOV cohort, which trains the cohort to expect a budget product).

5. **Affiliate / creator / display retargeting snippet picker does not resolve cohort identity at click-time / impression-time.** Pitfall: the affiliate / creator / display creative is static (the creative is built at creative-build time, not at click-time / impression-time), and the cohort sees the same creative regardless of cohort. Fix: the affiliate / creator / display snippet picker is invoked at click-time / impression-time via Impact / PartnerStack / ShareASale / Awin click ID + Google Enhanced Conversions / Meta CAPI, the cohort identity is resolved at click-time / impression-time, and the creative is rendered with the cohort's preferred snippet + variant. Without this, the cohort sees a cohort-agnostic affiliate / creator / display creative.

6. **Per-cohort cross-channel snippet consistency is not enforced.** Pitfall: the cohort's PDP snippet and email snippet and SMS snippet and push snippet and DPA snippet and affiliate snippet and display snippet are all different (snippet drift = trust loss). Fix: the per-cohort cross-channel snippet picker is invoked at every cross-channel touchpoint with the cohort's identity + browse history + LTV tier + verified-buyer preference + locale + returns-rate, and the same Move #47.5.1.1 snippet is selected on every channel. The cohort's cross-channel-trust-score is tracked (Klaviyo cross-channel-cohort-report + Triple Whale cross-channel-cohort-report). Without this, the cohort sees different snippets on different channels, and the cohort's cross-channel-trust-score drops, and the cohort's LTV drops (cross-channel consistency = trust = LTV).

7. **Per-cohort cross-channel frequency cap is not enforced.** Pitfall: the cohort gets hit with the same snippet 5× per day (email at 9am, SMS at 11am, push at 2pm, DPA at 4pm, affiliate at 6pm, display at 8pm = 5× per day). Fix: per-cohort cross-channel frequency cap is enforced (the cohort's snippet is shown at most 1× per day across channels, gated on consent, with per-channel frequency cap: email 1× per cohort, SMS 1× per cohort, push 1× per cohort, DPA unlimited but cohort-DPA-frequency-capped, affiliate unlimited but creator-feed-frequency-capped, display unlimited but retargeting-frequency-capped). Without this, the cohort experiences snippet fatigue, and the cohort's per-channel unsubscribe-rate / opt-out-rate / DPA-frequency-cap-violation-rate climbs, and the cohort's LTV drops.

8. **Per-cohort cross-channel consent + privacy is not enforced.** Pitfall: the snippet picker ignores consent (GDPR / CCPA / LGPD / PIPEDA / TCPA / CTIA / Apple ATT), and the cohort's snippet is sent to a non-consented cohort member, which is a GDPR fine (€20M / 4% of global revenue) + TCPA fine ($500–$1,500 per SMS) + Apple App Store rejection. Fix: per-cohort per-channel consent is enforced (email consent (CAN-SPAM / GDPR), SMS consent (TCPA / CTIA / GDPR), push consent (GDPR / Apple ATT), DPA consent (Meta CAPI / TikTok Events API / Google Enhanced Conversions), affiliate consent (FTC / influencer-disclosure)). The snippet picker is gated on the cohort's per-channel consent. Without this, the cohort's snippet is sent to a non-consented cohort member, which is a regulatory fine.

9. **Per-cohort cross-channel deliverability is not monitored.** Pitfall: the cohort's email snippet has a snippet-spam-rate of 0.5% (above the 0.1% Gmail / Yahoo / Microsoft spam threshold), the cohort's SMS snippet has a snippet-bounce-rate of 8% (above the 5% Twilio / MessageBird / Vonage / Plivo / Infobip threshold), the cohort's push snippet has a snippet-opt-out-rate of 2% (above the 0.5% OneSignal / Attentive / PushOwl threshold), and the cohort's DPA snippet has a DPA-frequency-cap-violation-rate of 5% (above the 2% Meta / TikTok / Google threshold). Result: the cohort's email is filtered to spam, the cohort's SMS is blocked, the cohort's push is opt-out'd, the cohort's DPA is rejected. Fix: per-cohort per-channel deliverability is monitored (Litmus / Email on Acid / Return Path / Validity for email, Twilio / MessageBird / Vonage / Plivo / Infobip for SMS, OneSignal / Attentive / PushOwl for push, Meta / TikTok / Google for DPA), and the cohort's snippet picker is paused when the cohort's per-channel deliverability drops below threshold. Without this, the cohort's snippet is filtered to spam / blocked / opt-out'd / rejected, and the cohort's per-channel LTV drops.

10. **Per-cohort cross-channel A/B test does not account for cross-channel interaction effects.** Pitfall: the email snippet picker A/B test vs the cohort-agnostic email baseline shows +35% lift, the SMS snippet picker A/B test vs the cohort-agnostic SMS baseline shows +50% lift, the push snippet picker A/B test vs the cohort-agnostic push baseline shows +60% lift. But the cohort sees the same snippet on all 3 channels (cross-channel consistency), so the cohort's actual LTV lift is +12% (the channels are interacting, not independent). Fix: per-cohort cross-channel A/B test (the cohort's email + SMS + push snippet pickers are A/B tested together as a single cross-channel treatment vs a cohort-agnostic cross-channel control), with cross-channel interaction-effect modeling. Without this, the per-channel A/B test overestimates the cohort's LTV lift, and the cohort's actual LTV lift is much lower than the per-channel A/B test suggests.
