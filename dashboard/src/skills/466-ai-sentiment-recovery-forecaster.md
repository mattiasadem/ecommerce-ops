## Common pitfalls

1. **Sentiment-recovery-forecast-without-Move-#1.4-per-creator-resume-confirmed-consumer** — the sentiment-recovery-forecast is fired from a manual "operator-confirms-brand-recovered" action instead of from Move #1.4's `per_creator_resume_confirmed` event. Without the Move #1.4 consumer the per-creator-resume-state-table is empty (no resume_at_timestamp + no per_creator_thank_you_confirmed + no per_creator_cohort_affinity_boost) AND the sentiment-recovery-forecast-model has no per-creator-resume-features AND the predicted-sentiment-recovery-time is wrong by 30-50%. Fix: Move #1.5 consumes the Move #1.4 `per_creator_resume_confirmed` within 5 min; maintains the per-creator-resume-state-table for use as a sentiment-recovery-forecast-feature.
2. **Sentiment-recovery-forecast-without-Move-#1.2-dark-site-resolution-confirmed-consumer-as-trigger** — the sentiment-recovery-forecast is fired from a manual "operator-confirms-crisis-resolved" action instead of from Move #1.2's `dark_site_resolution_confirmed` event. Without the Move #1.2 consumer the sentiment-recovery-forecast is missed (the operator forgets to fire it because they're focused on closing the crisis itself) AND the brand-recovery is unmeasured for 14-60 days. Fix: Move #1.5 consumes the Move #1.2 `dark_site_resolution_confirmed` within 5 min as the PRIMARY trigger; the consumer is idempotent.
3. **Sentiment-recovery-forecast-without-Move-#1.1-severity-scorer-consumer-as-feature** — the sentiment-recovery-forecast uses only Move #1.2 dark-site-resolution-latency + Move #1.3 creator-broadcast-latency + Move #1.4 creator-resume-latency as features (no severity-scorer-time-series). Without the Move #1.1 consumer the sentiment-recovery-forecast-model has no severity-time-series AND the predicted-sentiment-recovery-time is wrong by 20-40% (a severity-score=80 crisis recovers 30-50% slower than a severity-score=40 crisis, but the model doesn't know that). Fix: Move #1.5 consumes the Move #1.1 severity-scorer (0-100) at crisis-detection-time + at Move #1.2 dark-site-resolution-confirmed-time + at Move #1.4 per-creator-resume-confirmed-time; maintains a severity-time-series-table.
4. **Sentiment-recovery-forecast-without-Move-#1-8-scenario-vulnerability-matrix-as-template-anchor** — the sentiment-recovery-forecast uses a single forecast-template for all crises instead of mapping the current crisis to 1 of 8 templates via Move #1's 8-scenario-vulnerability-matrix. Without the 8-template-engine a product-recall-crisis gets the same sentiment-recovery-curve-anchor as a viral-TikTok-crisis (the curve-anchor is wrong by 50-100%, because product-recall-crises have 14-30 day recovery-floor while viral-TikTok-crises have 7-14 day recovery-floor). Without Brandwatch / Talkwalker / Mention / Sprout-Social / Hootsuite / Sprinklr / Meltwater / Lexalytics the sentiment-recovery-forecast-model has 0% coverage of TikTok-organic + Instagram-Reels + YouTube-Shorts + Twitter/X + Reddit + press-coverage (which drive 70-90% of post-crisis sentiment) AND the predicted-sentiment-recovery-time is wrong by 50-80%. Fix: Move #1.5 integrates with the brand's existing social-listening platform API; if multiple, use the most-used one as primary and the others as fallback.
