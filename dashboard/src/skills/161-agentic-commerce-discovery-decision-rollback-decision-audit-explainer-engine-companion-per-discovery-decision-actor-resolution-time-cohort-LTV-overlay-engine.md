## Common pitfalls (18 from real builds)

1. **Cohort-LTV-overlay-window-bucket-assignment using Move-#160-router-timestamp instead of Move-#160-overlay-event-cohort-LTV-overlay-tier-timestamp.** Pillar B's cohort-LTV-overlay-window-bucket-assignment buckets the per-discovery-decision-actor-resolution-time-overlay event into the 5-resolution-time-cohort-LTV-overlay-windows using the Move #160 router's `Date.now()` timestamp, but the Move #160 router-timestamp is when Move #160 RECEIVED the event, not when the Klaviyo Predictive Segments + Triple Whale Cohort LTV tagged the customer's LTV-band — so a customer whose LTV-band just transitioned from mid-LTV to high-LTV can land in the mid-LTV-overlay-window incorrectly. **Fix:** use the canonical per-discovery-decision-actor-resolution-time-overlay-event-cohort-LTV-overlay-tier-timestamp from the Move #160 event payload (which itself is the canonical Klaviyo Predictive Segments `Predicted Customer Lifetime Value` tier-timestamp + Triple Whale Cohort LTV band-timestamp + Move #154 churn-score-timestamp), NOT the Move #161 router-timestamp; compute `age = now - cohort-LTV-overlay-tier-timestamp` and bucket into the 5-cohort-LTV-overlay-windows using canonical thresholds (whale-LTV: tier=whale / high-LTV: tier=high / mid-LTV: tier=mid / low-LTV: tier=low / churn-risk-LTV: churn_score>0.70).

2. **Per-resolution-time-cohort-LTV-overlay-p99 latency computed over wrong cohort-LTV-overlay-window.** Pillar B's cohort-LTV-overlay-window-freshness-staleness-computation computes p99 latency over the whale-LTV-resolution-time-cohort-LTV-overlay-window using only the whale-LTV-bucketed events, but the whale-LTV-overlay-window has too few samples for a stable p99 (whale-LTV customers are <5% of total per Triple Whale 2024), so the per-resolution-time-cohort-LTV-overlay-p99 noise dominates the operator-UX-flow. **Fix:** compute per-resolution-time-cohort-LTV-overlay-p99 over the high-LTV-resolution-time-cohort-LTV-overlay-window minimum (canonical 30-second-stream-processing-latency-target), and surface a "low-sample-size" warning when the whale-LTV-resolution-time-cohort-LTV-overlay-window has <1,000 events; the canonical whale-LTV-resolution-time-cohort-LTV-overlay-window-p99 is a moving-target indicator, NOT a stable latency measurement.
