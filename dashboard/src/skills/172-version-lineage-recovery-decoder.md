## Common pitfalls (18 from real builds)

1. **Instant-replay buffer overflow on burst loss.** The 60-second in-memory buffer for `recovery-decoder-1-instant-replay` overflows when a single burst loses more than 60 seconds of `per-version-lineage` tuples. **Fix:** size the buffer at the canonical `5 × peak-pps` rule (peak per-discovery-decision-actor-id tuples per second × 5) per UCP-version-lineage-recovery-decoder-instant-replay-2026; add a watermark metric that fires before overflow.
2. **Batch-rebuild double-counting on shared window.** The 5-minute BigQuery/Snowflake `recovery-decoder-2-batch-rebuild` job double-counts tuples that were ALSO replayed by `recovery-decoder-1-instant-replay` when the instant-replay buffer's 60-second window overlaps the batch window. **Fix:** tag every tuple with the canonical `recovery-decoder-source: instant-replay|batch-rebuild|catchup-stream|historical-snapshot|manual-backfill` per UCP-version-lineage-recovery-decoder-classifier-2026; the batch-rebuild query joins against `recovery-decoder-source != 'instant-replay'` to dedupe.
3. **Catchup-stream consumer-group rebalance during schema-version bump.** The Kafka/Confluent/Pulsar `recovery-decoder-3-catchup-stream` consumer-group rebalances during a schema-version-1.0.0 → schema-version-2.0.0 rollback-bump, dropping in-flight tuples. **Fix:** pin the consumer-group's `auto.offset.reset` to `earliest` and re-emit from the per-version-lineage topic origin; never bump the schema-version without first pausing the consumer-group.
4. **Historical-snapshot Parquet/Avro/Iceberg schema mismatch on version-5-deprecation.** The daily Parquet/Avro/Iceberg `recovery-decoder-4-historical-snapshot` write fails when `version-5-deprecation` tuples carry a different schema-version than the snapshot schema-version-1.0.0 expects. **Fix:** the snapshot writer reads `Move-#171-version-lineage-overlay` to dispatch to the correct schema-version writer; the snapshot reader tolerates all 5 schema-versions via the canonical Move-#171-version-lineage-overlay-classifier-2026.
5. **Manual-backfill UI rejects schema-version-2-rollback tuples.** The operator-UX-flow `/version-lineage-recovery-decoder` rejects uploads of `version-2-rollback` tuples because the upload form only accepts `schema-version-1.0.0`. **Fix:** the upload form reads the canonical `version-lineage-overlay` field from the uploaded JSON and dispatches to the correct validator per Move-#171-version-lineage-overlay-classifier-2026.
6. **Per-version-lineage-recovery-decoder-freshness drops below SLA on catchup-stream failure.** When `recovery-decoder-3-catchup-stream` fails for >1 hour, the per-version-lineage-recovery-decoder-freshness metric drops below the canonical UCP-tier-3 SLA (`≤1h`). **Fix:** the freshness metric auto-promotes to `recovery-decoder-4-historical-snapshot` when `recovery-decoder-3-catchup-stream` is unhealthy for >30min, per UCP-version-lineage-recovery-decoder-fallback-2026.
