## Common pitfalls (15 from real builds)

1. **Snippets over the 8.4-second mobile bounce window.** Mobile PDP loses a visitor within 8.4 seconds if three specific friction points are present (per Callout: Baymard 2026 + Katelyn Bourgoin via onlinestorenews.com): slow image loading, a below-the-fold add-to-cart button, and the absence of social proof near the top of the page. If the LLM-generated device-bias snippet is 80-160 char (the desktop canonical length), mobile-bounce-window compliance drops to 0.3-0.5 and the snippet reads as truncated / cut-off. ALWAYS generate the LLM snippet in TWO variants per device: a 30-60 char headline variant for D1 mobile + a 50-80 char mid variant for D2 tablet + the canonical 80-160 char long-form variant for D3 desktop. The bandit picks the device-appropriate variant per cohort per channel. The L11 device-context prompt layer MUST inject the device-form-factor constraints into the LLM prompt (snippet-length-target + bounce-window-budget + carousel-swipe-budget + tap-target-floor) — without it, the LLM defaults to the canonical 80-160 char desktop long-form snippet and the mobile bounce window collapses.

2. **CTA placement above the bottom-30% thumb-zone on mobile.** Mobile ATC button must be in the bottom 30% of the screen (thumb-zone). If the CTA is at 55% scroll position, mobile add-to-cart rate drops 14% (per Callout: Inflow CRO agency via onlinestorenews.com). The PDP design must include a sticky-bottom-thumb-zone CTA for D1 mobile. LLM-generated snippets cannot fix the CTA-placement bug — the PDP template must ship the sticky-bottom-thumb-zone CTA. ALWAYS audit the PDP template with a real-device 390px-wide viewport (per Callout: Ryan Garrow / Logical Position via onlinestorenews.com "one-screen document" framework) and confirm the CTA is reachable in one scroll / grip-shift.

3. **Treating mobile as a shrunken desktop rather than a separate experience.** The most common mobile-PDP mistake is treating mobile as a shrunken desktop rather than a separate experience with different constraints: thumb zone, keyboard behavior, network conditions, scroll patterns. The second most common is hiding COD and BNPL options behind taps or scrolls on mobile checkout, which destroys trust with GCC buyers (per Callout: ConvFetti via convfetti.com). The device-bias picker must NOT just truncate the desktop canonical snippet — it must REGENERATE the snippet in the device-native form-factor (30-60 char for D1 mobile with thumb-zone CTA vs 80-160 char for D3 desktop with inline-below-fold CTA). ALWAYS render a device-native variant per cohort per channel per device, not a truncated copy of the desktop canonical.

4. **Tap targets under 44×44pt.** Apple Human Interface Guidelines 2026 + Web Content Accessibility Guidelines WCAG 2.2 (enhanced target-size criterion) require touch targets ≥44×44 points (Apple HIG) or 44×44 CSS pixels (WCAG 2.2). If the LLM-generated snippet button is <44×44pt, mobile mis-tap rate jumps 20-40% and ATC rate drops. ALWAYS render the LLM-generated snippet CTA at ≥44×44pt for D1 mobile + D2 tablet. Desktop can be ≥32×32pt (smaller OK).

5. **Sticky add-to-cart bar that scrolls instead of adds.** A sticky ATC bar should keep the primary purchase action within reach after the shopper scrolls past the main buy box. If tapping the sticky ATC scrolls the shopper back to the main buy box instead of adding to cart, session recordings show users repeatedly tapping the sticky button trying to trigger the add-to-cart action — a component intended to shorten the purchase path introduces another step (per Callout: tmogroup.asia). ALWAYS verify the sticky ATC behavior post-tap with a real-device session recording.

6. **Promotional overlays covering price + CTA on mobile.** Full-screen subscription prompts / floating promotional banners / widgets that repeatedly expand as the user moves through the page cover pricing, product configuration, or the primary CTA, and a marketing mechanic intended to capture leads starts competing with the purchase itself. The fix is the xBloom pattern: the popup collapses into a compact vertical tab at the edge of the screen after dismissal — price and "Add to Cart" stay visible, and the offer remains one tap away (per Callout: tmogroup.asia). ALWAYS ensure promotional elements remain secondary to the purchase path on mobile.

7. **Variant / size / inventory UX broken on mobile.** Variant, size and inventory UX breaks PDPs on mobile because selection friction compounds language, size system, and stock uncertainty into abandonment. Dropdowns for color and size, hidden size guides, and inaccurate stock messaging are the three most common defects in 50+ store audits. Stores using visible swatches instead of dropdowns average 1.4 taps to complete variant selection on mobile versus 2.4 taps with dropdowns, and that extra tap correlates with a 12% lower mobile add-to-cart rate (per Callout: ConvFetti via convfetti.com). ALWAYS pair the LLM-generated device-bias snippet with mobile-native variant UX: visible swatches + collapsible size-guide + accurate stock messaging at the top of the PDP. The LLM snippet cannot fix the variant-UX bug — the PDP template must ship mobile-native variant UX.

8. **Returning traffic-rate-DSP-vendor-mobile-attribution gap.** Meta CAPI + TikTok Events API + Google Enhanced Conversions + Pinterest Conversions API must send device-class context to the ad-platform attribution. If the ad-platform doesn't know the click was mobile, the post-click mobile-LTV under-counts and the ad-bidding-model under-bids mobile. ALWAYS send device-class context to all 4 ad-platform conversion APIs (per Move #13 / skill/13 Triple Whale attribution).

9. **BNPL messaging hidden on PDP / below-fold on mobile.** Showing BNPL payment amounts on the product page is critical on mobile. BNPL messaging on the mobile PDP ("AED 149 or 4 payments of AED 37.25 with Tabby") reduced mobile checkout abandonment by 18% across five UAE stores. The messaging works because it answers the price question before the buyer reaches checkout; on mobile, buyers are less willing to navigate to checkout to discover payment options (per Callout: ConvFetti via convfetti.com). GCC stores with BNPL at the PDP level see 23% higher checkout completion. ALWAYS surface the BNPL installment amount directly under the price on the mobile PDP, paired with the device-bias snippet. The LLM snippet must NOT reference "free returns" or "fast shipping" alone — it should reference the BNPL installment amount when applicable, formatted in 30-60 char for D1 mobile.

10. **Mobile PDP with no first-image-carousel-swipe-budget.** Baymard 2026 mobile-PDP-usability study tracked 2,400 real shopping sessions across 40 U.S. DTC stores and found that 58% of mobile shoppers never scroll past the first image carousel on a PDP — meaning all the carefully written size guides, sustainability pledges, and UGC carousels placed below the fold were effectively invisible to more than half of potential buyers (per Callout: Kristin Naragon / Yotpo via onlinestorenews.com). ALWAYS ship the LLM-generated device-bias snippet in the first-image-carousel frame (frame 1) on mobile + tablet, and use the LLM snippet's battle-tested narrative for the carousel-frame-2/3 follow-on frames.

11. **Ignoring vertical-video-swatch for color/size variants.** Replacing static color swatch images with 3-5 second looping video clips of each colorway in use lifts time-on-page by 34% for apparel merchants (per Callout: Nosto Q2 2026 via onlinestorenews.com). If the LLM-generated device-bias snippet recommends a specific colorway, the PDP should render a vertical-video-swatch for that colorway on mobile. ALWAYS pair the LLM-generated colorway recommendation with a Nosto-style 3-5 second vertical-video-swatch on mobile.

12. **Cart abandonment at 83.6% mobile vs 73% desktop.** Mobile cart abandonment is 10.6pp higher than desktop (per Callout: Monetate Q3 2024 via tapcart.com). The LLM-generated device-bias snippet + device-aware checkout flow can close 30-50% of that gap. ALWAYS ship the device-bias snippet AT cart-page-load (not just at PDP) + the device-aware checkout (mobile = single-column + 44×44pt tap targets + Google Places autocomplete + Google 2026 address validation 47 seconds + iOS/Android keyboard autofill + collapsed order-summary toggle; desktop = multi-column + hover-to-reveal + multi-line trust footer) per Move #22 / skill/22 (checkout audit Baymard).

13. **Trust signals in footer on mobile.** On desktop, a buyer can glance at the footer to see SSL badges, return policy links, and payment logos. On mobile, the footer is invisible unless the user scrolls past the Place Order button — which they will not do before deciding whether to trust the payment step. The fix is to embed trust signals directly adjacent to the Place Order button. Placing a one-line trust statement "🔒 Secure payment. Free returns within 14 days." directly above the Place Order button lifted mobile checkout completion by 7% compared to having the same trust badges in the footer (per Callout: ConvFetti via convfetti.com). ALWAYS render the trust-signal one-liner directly above the Place Order button on mobile.

14. **Returning device-LTV -9.09% gap unmitigated.** Mobile adds-to-cart 51.8% more often than desktop, but mobile conversion is 9.09% lower (per Callout: Tapcart / Capital One Shopping 2024 via tapcart.com). The device-bias picker alone closes the gap to -3-5% by biasing the cohort's LLM snippet toward device-natural review pools. ALWAYS measure per-cohort per-device LTV + per-cohort per-device ATC-share + per-cohort per-device cart-abandonment-delta in the per-cohort per-channel × per-device cohort-LTV readback v3.

15. **AVIF/WebP image format not deployed.** Stores migrating product photos to AVIF or WebP at the Shopify CDN layer see Core Web Vitals scores improve enough to affect both paid and organic traffic quality scores (per Callout: onlinestorenews.com). If the mobile PDP loads >3s, the bounce window collapses and the LLM-generated snippet is unread. ALWAYS deploy AVIF + WebP next-gen formats with progressive image loading + dominant color placeholders (per Callout: onlinestorenews.com) before the device-bias picker is benchmarked. Mobile PDP loses visitor in 8.4s if slow image loading is one of 3 friction points.
