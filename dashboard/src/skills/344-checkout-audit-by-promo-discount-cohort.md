## Common pitfalls (18 from real builds)

**Pitfall #1 — Shipping the canonical 12-promo-discount-cohort engine without Layer-1 promo-discount-cohort-funnel-telemetry.** Symptom: Layer-2 leak-rate-counter has no input data → leak-rate-renders-as-NaN. Fix: Phase 1 Layer-1 funnel-telemetry is the highest-priority prerequisite; do NOT skip Layer-1 wiring even for the smallest 12-cohort setup.

**Pitfall #2 — Tagging the wrong 12-promo-discount-cohort.** Symptom: percentage-off-5-percent-attempts tagged-as-percentage-off-10-percent-attempts → cohort-completion-rate-leaderboard-shows-percentage-off-10-percent-as-50%-higher-completion-rate-when-actually-50%-of-attempts-were-percentage-off-5-percent. Fix: Shopify-Automatic-Discounts-API + Shopify-Script-Discount-API + Shopify-Price-Rule-API webhook payload includes the canonical discount-amount-pct + discount-amount-fixed + free-shipping-flag + bogo-flag fields; use ALL 4 fields in the 12-cohort-detection rule, never just one.

**Pitfall #3 — Shipping without 12-promo-discount-cohort-completion-rate-benchmarks.** Symptom: Layer-2 leak-rate-counter returns raw-rate without comparing to benchmark → operator cannot tell if 15% leak-rate is good or bad. Fix: load the canonical 12 benchmarks from `benchmarks/promo-discount-cohort-2024.json` in Phase 2; without benchmarks the engine is meaningless.

**Pitfall #4 — Shipping without 12-promo-discount-cohort-leak-rate-benchmarks.** Symptom: Layer-2 leak-rate-counter cannot compute leak-rate-vs-benchmark delta → operator cannot identify WHICH-cohort-is-leaking-most. Fix: load the canonical 12 leak-rate-benchmarks in Phase 2; the delta-vs-benchmark is the canonical Move #3.16 operator-output.

**Pitfall #5 — Shipping without the 18-cause-diagnosis-engine.** Symptom: per-promo-discount-cohort-leak-rate-spike auto-tagged with `unknown` cause → operator cannot triage. Fix: Phase 2 includes the 18-cause-diagnosis-engine; each leak-rate-spike auto-tagged with top-1 cause-diagnosis (promo-discount-cohort-prominence-gap / etc.).

**Pitfall #6 — Forgetting to enable Move #47 A/B-testing-instrumentation on the 42 fix-recommendations.** Symptom: Layer-4 42-fix-recommendations ship without statistical-significance-validation → operator ships fixes that may regress. Fix: every fix-recommendation routes through Move #47 growth-experimentation-engine for A/B runtime + confidence-threshold validation; without Move #47, the 42 fixes are uninstrumented guesses.

**Pitfall #7 — Treating the 12-promo-discount-cohort as a single global-engine.** Symptom: rollback-decision-engine fires globally → kills high-performing cohorts (percentage-off-5-percent at 88% completion-rate) because another cohort (bogo-buy-one-get-one at 60% completion-rate) failed. Fix: per-promo-discount-cohort-is-per-promo-discount-cohort-NOT-global per pitfall #18; each cohort has its own benchmark-floor + rollback-trigger.

**Pitfall #8 — Treating Layer-5 per-promo-discount-cohort-attribution-loop as a per-day-aggregation-only.** Symptom: attribution-stream-only-aggregates-daily → operator misses the per-checkout-step-attribution signal. Fix: stream per-promo-discount-cohort-event per checkout-step-attempt; per-day-aggregation is the OPTIONAL rollup, not the default.

**Pitfall #9 — Shipping without per-promo-discount-cohort-A/B-testing-instrumentation routed through Move #47.** Symptom: Layer-4 42-fix-recommendations are deployed without A/B testing → operator cannot tell which fix recovered revenue. Fix: every fix routes through Move #47 for statistical-significance validation; without Move #47, the fixes are uninstrumented.

**Pitfall #10 — Shipping without per-cohort × per-promo-discount-cohort = 768-cell cross-validation matrix.** Symptom: Layer-3 missing → operator cannot decompose which cohort × promo-discount-cohort combination is the highest-LTV.
