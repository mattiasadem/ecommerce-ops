## Common pitfalls (18 from real builds)

1. **Single "cancel" button with no reason-tree and no save-action.** The operator's product page has a one-click cancel button, the customer clicks cancel, the customer churns, the operator never knows why. **Fix:** wire a per-reason reason-tree (price / value / convenience / product-fit / shipping / seasonal / competitor / life-event) with per-reason save-action (offer / discount / pause / skip / swap / downgrade / gift-subscription) into the cancellation flow; instrument per-reason save-rate; A/B test per-reason offer-discount-pause-skip-swap-downgrade combinations.

2. **Single retry + 1-3 email sequence for failed payments (no smart-retry, no 50%-off winback, no pause-skip-swap-downgrade option).** The operator has a single retry on day-3, a 1-3 email sequence, no 50%-off winback offer, no pause-skip-swap-downgrade option, the customer churns on day-5. **Fix:** wire an 11-stage smart-retry (day-1 / day-3 / day-5 / day-7 / day-10 / day-14 / day-21 / day-28 / day-35 / day-45 / day-60) with per-stage email/SMS/push/voice/in-app reminder + per-stage card-update-CTA + per-stage 50%-off winback offer + per-stage pause-skip-swap-downgrade option; benchmark recovery-rate to 60-75%.

3. **Every retry uses the same processor, same network, same hour-of-day.** The operator's retry logic is "send the same charge again at the same hour-of-day on the same processor and same network" — when the decline-code is `insufficient_funds` at 3am, retrying the same `insufficient_funds` charge at 4am hits the same `insufficient_funds` decline. **Fix:** wire per-network cascade (Visa → Mastercard → Amex → Discover → Diners → JCB → UnionPay → Cartes Bancaires → iDEAL → SEPA → ACH → BACS → Interac → eftpos) and per-decline-code routing (insufficient_funds → next-payday-window, card_declined → customer-action-required, expired_card → card-update-CTA, processing_error → next-processor-network).

4. **No involuntary-churn-risk-prediction, no pre-failure save-intervention.** The operator finds out about a failed payment 30 days after it failed, the customer has already churned, the customer-service rep has no context, the rep can't save them. **Fix:** wire an agentic-AI-billing-agent that monitors each subscriber's billing-health, predicts involuntary-churn-risk (1-30 day forward-look) using Klaviyo/Iterable/Braze AI segments + Mixpanel/Amplitude cohorts + Triple Whale/Polar cohort-LTV-overlay, triggers a 3-stage save-intervention (gentle email → SMS reminder → live-agent handoff) before the charge fails.
