## Common pitfalls (15 from real builds)

1. **Shipping per-cohort × per-channel × per-returns-risk-tier LLM + bandit picker without the returns-risk taxonomy first.** The 8-tier returns-risk taxonomy (R1 ultra-low + R2 low + R3 moderate + R4 elevated + R5 high + R6 very-high + R7 extreme + R8 disposable) MUST be defined and instrumented BEFORE the LLM prompt stack. Shipping the LLM without the returns-risk-tier signal is a "string-template" anti-pattern — the LLM hallucinates returns-resilience claims ("True to size" on a high-returns-risk SKU) and the operator gets an FTC + state-AG + EU UCPD letter. Diagnostic: `node -e "console.log(Object.keys(skuReturnsRisk || {}))"` — if the taxonomy is undefined, halt and instrument. The 8-tier taxonomy requires ≥ 30 returns per cohort per SKU per month for per-SKU return-rate computation; below that threshold, the per-SKU return-rate is too noisy and the operator should fall back to per-category return-rate.

2. **Using size/fit/color/quality claims without verified-reviewer cohort-resilience weight.** Any returns-resilience-aware snippet that says "True to size" / "Sizing: size up" / "Fits true to color" / "Patch test first" MUST be backed by a verified-reviewer with low-lifetime-return-rate + low-chargeback-rate + photo-rich + helpful-rich. The `reviewer_lifetime_return_rate` + `reviewer_chargeback_rate` fields in the LLM output schema are MANDATORY; the LLM-as-judge ensemble MUST verify the verified-buyer cohort-resilience weight (2x on low-lifetime-return-rate + low-chargeback-rate reviewers) before the snippet is allowed into the bandit arm space.
