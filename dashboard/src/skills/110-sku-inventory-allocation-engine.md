## When to use this skill

Use this skill when the operator is doing **≥$1M GMV** with **≥2 inventory nodes** (multi-warehouse + 3PL OR multi-storefront + marketplace OR DTC + B2B-wholesale OR DTC + subscription OR DTC + marketplace) AND the inventory-allocation friction curve has started to compound: stockouts on hero SKUs at one node while the same SKUs are overstocked at another node (the canonical "warehouse A is out, warehouse B has 800 units" failure mode), split-shipment rate exceeds 15% (the canonical "one order ships from 2-3 nodes because no single node has full inventory" anti-pattern), 3PL transfer cost between nodes exceeds 5% of COGS (the canonical "we keep shuttling inventory between 3PLs to keep every channel in-stock" friction), shipping cost per order exceeds the demand-proximity-adjusted target (the canonical "we ship from East-Coast warehouse to West-Coast customers when West-Coast warehouse has 200 units of the same SKU" leak), per-channel allocation-cap violations (the canonical "Amazon out-of-stock penalty + Walmart out-of-stock penalty + DTC stockout + B2B backorder all hit on the same SKU in the same week"), subscription-cohort fulfillment-failure-rate exceeds 5%, BOPIS in-stock-rate below 90% on A-SKUs, preorder-fulfillment-rate below 80%, B2B-wholesale allocation-shortfall-rate exceeds 10%, marketplace-channel-allocation-cap is breached (the canonical "Amazon takes everything, DTC has nothing" anti-pattern), OR the operator cannot answer "which 20 SKUs are over-allocated to channel X and under-allocated to channel Y?" within 60 seconds.

You have:

- **Multi-node inventory state** — at minimum 2 inventory locations (DTC-warehouse + 3PL-1, OR DTC-East + DTC-West, OR DTC + Amazon-FBA, OR DTC + B2B-warehouse), with on-hand + on-order + inbound + committed + available per SKU per node visible via API (Shopify Locations API + Cin7 + NetSuite WMS + ShipBob WMS + Amazon SP-API + Walmart WFS + TikTok Shop Seller API + Faire API + Etsy API).
- **Per-channel demand data** — at minimum 90 days of per-channel per-SKU sales velocity (DTC, Amazon, Walmart, TikTok Shop, Faire, Etsy, eBay, B2B-wholesale, subscription) with cohort overlays (per-cohort-LTV × per-channel-velocity) per Triple Whale + Polar + Northbeam + Daasity + Glew benchmarks.
- **3PL/WMS real-time sync** — at minimum one of: Cin7, NetSuite WMS, ShipBob WMS, ShipHero WMS, ShipMonk WMS, Stord, Cart.com, Flowspace, Red Stag, GEODIS, DHL Supply Chain, Körber WMS, Manhattan Active WM, Blue Yonder, HighJump, Made4net, Extensiv, Brightpearl, Linnworks, Orderhive, Skubana — with inventory-API + inbound-receipt-webhook + outbound-shipment-webhook + transfer-webhook + cycle-count-webhook.
- **Channel-allocation-cap engine** — at minimum one allocation-cap definition per channel (Amazon max-cap + Walmart max-cap + TikTok Shop max-cap + Faire max-cap + DTC priority + B2B-wholesale priority + subscription-cohort priority + BOPIS-store priority + ship-from-store priority + preorder priority) computed weekly from per-channel-cohort-LTV-overlays.
- **Demand-forecast substrate** — Move #12.5 (Inventory Planner + Cogsy + Netstock + SoStocked + Cin7 + Shopify Stocky) MUST be live before Move #110 ships; the allocation engine reads Move #12.5's per-SKU 30/60/90-day forecast + per-SKU safety-stock + per-SKU-reorder-point to compute per-node-allocation.
- **Working-capital substrate** — Move #12.6 (inventory-financing + dead-stock-liquidation + multi-warehouse-cash-flow-allocation) MUST be live before Move #110 ships; the allocation engine reads Move #12.6's per-SKU carrying-cost + per-SKU-dead-stock-flag + per-SKU-markdown-cadence to compute per-node-allocation-cost.
- **Back-in-stock flow substrate** — Klaviyo (or Postscript + Attentive + Iterable + Braze + Cordial + HubSpot + Salesforce Marketing Cloud + Customer.io) back-in-stock flow on a paid plan, per Move #12.5 Pillar 5; the allocation engine reads back-in-stock-demand-signals to rebalance allocation toward the highest-converting channel.
- **Attribution substrate** — Triple Whale (or Polar + Northbeam + Daasity + Glew) wired so the operator can measure whether allocation-driven in-stock-rate lifts flow to per-channel-cohort-LTV (the canonical "Amazon allocation cap lifted, DTC stockout avoided, cohort-LTV maintained" success mode).
- **BOPIS / ship-from-store / endless-aisle substrate** — at minimum one of Move #84 (BOPIS-curbside-store-fulfillment) + ship-from-store + endless-aisle live, OR Move #80 (omnichannel-storefront-operations) live, OR Shopify Plus Locations API enabled.
- **Subscription-channel substrate** — Recharge + Skio + Bold + Stay AI + Loop + Appstle + Subbly + Smartrr + Awtomic + Stripe Billing + Recurly + Chargebee live OR Move #5 / Move #97 / Move #98 live so per-subscription-cycle allocation can be computed.
- **Marketplace substrate** — at minimum one of Amazon SP-API + Walmart WFS + TikTok Shop Seller API + Faire API + Etsy API + eBay Seller Center API + Target Plus API live so per-marketplace-channel-allocation can be computed.
- **B2B-wholesale substrate** — at minimum one of Shopify B2B + Shopify B2B Markets + Faire + Handshake + Tundra + Ankorstore + RangeMe + Abound + Alibaba B2B live so per-B2B-channel-allocation can be computed.
- **Preorder-allocation substrate** — Move #73 (preorder-backorder-allocation-operations) live OR preorder-engine enabled (Shopify Pre-Order + Back in Stock + Notify Me + Waitlist).
- **Budget for: $0–$1,500/month in platform fees** (Shopify Stocky free Path A, Cin7 Core $299/mo Path B default at $1M-$5M GMV, NetSuite WMS custom enterprise, ShipBob WMS free for ShipBob customers, Klaviyo back-in-stock free on paid plan, Cogsy $249/mo for forecasting layer, Inventory Planner $249/mo) **+ 8-16 hours/week in operator time for the first 8 weeks** (per-node allocation-cap build, per-channel-allocation-cap build, per-SKU rebalance-trigger-threshold calibration, per-channel-cohort-LTV-overlay build, allocation-decision-audit setup, allocation-rollback playbook, back-in-stock flow wiring, attribution wiring, dead-stock liquidation planning).

Do **not** use it when:

- The store is doing **<$1M GMV OR <2 inventory nodes**. Defer Move #110, ship Move #12.5 + Move #12.6 first, and revisit when volume + node count justify the platform fee + operational complexity.
- The store is **single-node single-channel**. Allocation-engine complexity is wasted when there is only one inventory location and one channel; ship Move #12.5 + #12.6 first, defer Move #110 until the operator adds a 3PL or a second channel.
- The brand has **no per-channel demand data with at least 90 days of history**. The allocation engine's per-channel-allocation-cap math needs per-channel-velocity-cohort-LTV-overlays; without them, the engine produces "we have no idea which channel deserves more" output and the operator is back to manual spreadsheet math.
- The brand cannot commit to **per-channel-allocation-cap governance** (treating every channel as equal priority is the canonical "Amazon takes everything, DTC has nothing" anti-pattern; allocation-cap governance lets the operator apply per-channel priority weights and rebalance weekly).
- The brand has **no per-SKU cohort-LTV data** (Move #103 product-analytics + Triple Whale + Polar + Northbeam + Daasity + Glew). Without per-SKU-cohort-LTV, the allocation engine cannot rank channels by LTV-per-unit-shipped and defaults to "first-come-first-served by sales velocity" which systematically over-allocates to Amazon + Walmart (high-velocity, low-LTV) and under-allocates to DTC (lower-velocity, high-LTV).
- The brand is in a **regulated vertical** (supplements, CBD, beauty with lot/date tracking, food) where lot-tracking-and-expiry-allocation matters more than per-channel-allocation-cap. Most WMS support lot-tracking via Cin7 + NetSuite, but the operator must configure them BEFORE the allocation engine goes live.
- The brand has **no channel-allocation-cap decision authority** (e.g. Amazon-Vendor-Central where Amazon controls allocation). Allocation-engine helps the operator forecast demand and pre-position inventory, but Amazon ultimately decides what ships to Prime customers; the engine can compute the cap but cannot enforce it.

### Per-node stockout cost (the canonical "cost of running out at one node while overstocked at another")

- **Per-node stockout on a hero A-SKU during a Meta campaign:** 12-25% of per-node-campaign-spend goes to zero-conversion PDP-views over the per-node-stockout window (the canonical "East-Coast-warehouse stockout while West-Coast-warehouse has 800 units" failure mode). At a $5M DTC brand running $50k/mo Meta + a 5-day East-Coast-stockout on a hero SKU = ~$2k in wasted ad-spend per per-node-stockout event.
- **Per-node stockout cost on a non-campaign day:** 8-15% of would-be-per-node-daily-revenue evaporates; the customer goes to a competitor or substitutes within the brand's catalog (substitution recoups 30-50% of the lost sale per per-node).
- **Per-node back-in-stock email converts 8-15%** of waitlisted per-node-visitors to purchase within 24 hours of per-node-inventory-restore (vs 1-3% baseline of fresh PDP traffic) per Klaviyo 2024 back-in-stock flow benchmarks. At 500 waitlisted visitors per per-node-A-SKU-stockout, that's $4k-$7.5k recovered per per-node-stockout event at $75 AOV.
- **Per-node cross-node-stockout** (Node A out + Node B has 800 units of same SKU): the canonical 0-100% overstock at one node paired with 0% stock at another node is the #1 source of 3PL-transfer-cost and split-shipment-rate waste. At a $5M DTC brand with 4 nodes, cross-node-stockout happens on 5-15% of A-SKUs and contributes to 30-50% of 3PL-transfer-cost.

### Per-channel allocation-cap impact

- **Per-channel allocation-cap enforcement:** typical 0-50% of channels have explicit allocation-caps at the start of Move #110 deployment; Move #110 raises this to 80-95% within 8 weeks. At a $5M DTC brand running DTC + Amazon + Walmart + TikTok Shop + Faire + B2B-wholesale + subscription, the canonical per-channel-allocation-cap matrix is: DTC priority (40-60%), Amazon (15-25%), Walmart (5-10%), TikTok Shop (5-10%), Faire (3-5%), B2B-wholesale (5-10%), subscription (5-15%).
- **Per-channel-cohort-LTV × per-channel-velocity mismatch:** the canonical "Amazon takes 80% of inventory because Amazon velocity is highest but Amazon cohort-LTV is 30-50% of DTC cohort-LTV" anti-pattern. Move #110 enforces per-channel-cap-with-cohort-LTV-overlay and lifts DTC cohort-LTV by 10-25% via rebalanced allocation.
- **Per-marketplace allocation-cap penalty:** Amazon out-of-stock-penalty + Walmart out-of-stock-penalty + TikTok Shop out-of-stock-penalty + Faire out-of-stock-penalty + Etsy out-of-stock-penalty collectively cost 1-3% of marketplace-GMV per year at brands that don't enforce per-marketplace-allocation-caps; Move #110 reduces this by 50-90% via proactive allocation-cap-management.

### Split-shipment cost

- **Split-shipment-rate:** typical 15-30% at brands with 2+ nodes and no allocation-engine, dropping to 5-10% with Move #110 + Cin7 + NetSuite WMS + Shopify Functions real-time-allocation. At a $5M DTC brand with 4 nodes + 15% split-shipment-rate, the per-order shipping-cost overhead is $3-$8 per split-shipped order × 25k orders/year = $75k-$200k/year in excess shipping-cost.
- **Per-order 3PL-transfer-cost:** typical $5-$15 per transfer between nodes; Move #110 reduces transfer-frequency by 30-50% via per-node demand-proximity-aware allocation.

### Working-capital impact

- **Per-SKU safety-stock-tied-up across nodes:** typical 15-25% of total inventory value per IHL 2024 + Cin7 2024 + NetSuite 2024 benchmarks. At a $5M DTC brand with $1.25M inventory, per-SKU-safety-stock-tied-up across nodes = $187k-$312k of cash locked up. Move #110 reduces this by 15-30% via per-node demand-share-aware safety-stock calculation.
- **Per-node carrying cost per dollar of inventory per year:** 20-30% (cost of capital 8-12% + warehouse cost 5-8% + shrinkage/insurance 3-5% + obsolescence 4-7%) per NRF 2024 + Cin7 2024 + NetSuite 2024 benchmarks. So $100k of per-node-slow-moving inventory costs $20k-$30k/yr to carry.
- **Per-node inventory-days-of-supply:** typical 60-120 days at single-node brands; Move #110 reduces this to 30-60 days via per-node demand-proximity-aware allocation + per-channel-allocation-cap governance.

## The build (time estimate)

A canonical Move #110 sku-inventory-allocation-engine deployment takes **16-24 weeks** of operator time + **$0-$1,500/month in platform fees** for $1M-$10M GMV brands. The build is split into 8 phases:

### Phase 0 — Pre-build (Week 0, 24 hr)

1. **Per-node-inventory-state-baseline** — establish on-hand + on-order + inbound + committed + available per SKU per node visible via API for at minimum 2 nodes (DTC + 3PL-1, OR DTC-East + DTC-West, OR DTC + Amazon-FBA, OR DTC + B2B-warehouse). Without this, the engine is blind. Output: per-SKU-per-node-inventory-state-baseline.
2. **Per-channel-demand-data-baseline** — pull 90 days of per-channel per-SKU sales velocity (DTC, Amazon, Walmart, TikTok Shop, Faire, Etsy, eBay, B2B-wholesale, subscription) + per-channel-cohort-LTV × per-channel-fulfillment-cost × per-channel-margin. Output: per-channel-demand-data-baseline.
3. **Per-channel-allocation-cap-baseline** — define initial per-channel-allocation-cap matrix (DTC priority + Amazon max + Walmart max + TikTok Shop max + Faire max + B2B-wholesale priority + subscription priority + BOPIS-store priority + ship-from-store priority + preorder priority + marketplace priority) computed from per-channel-cohort-LTV-overlay. Output: per-channel-allocation-cap-baseline.
4. **Per-SKU-cohort-LTV-overlay-baseline** — build per-SKU-cohort-LTV matrix from Triple Whale + Polar + Northbeam + Daasity + Glew benchmarks. Output: per-SKU-cohort-LTV-overlay-baseline.

### Phase 1 — Engine selection + onboarding (Weeks 1-2, 16-24 hr)
