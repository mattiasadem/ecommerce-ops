# AI tier-2 customer service deflection

> Move #20.2 is the canonical **tier-2-complex-ticket deflection engine** that sits on top of Move #20.1 (skill/11 ai-customer-service-automation) tier-1 self-serve + AI-completion layer and handles the **hard middle** — the 30–40% of inbound DTC tickets that tier-1 deflects poorly on: returns/exchanges (15–25% of all tickets), sizing/fit disputes (5–10%), warranty/defect claims (5–8%), billing disputes + subscription-cancellation (4–7%), shipping-damage + lost-package claims (3–6%), and the "agentic-resolution" cases where the customer expects the AI to **actually resolve the issue end-to-end** (issue refund, generate return label, escalate to human if policy-blocked) rather than just answer a question. Built on **5 layers**: (Layer 1) **ticket-classifier + intent-routing** — GPT-4o / Claude 3.5 Sonnet classifies inbound ticket into 12 tier-2-intents with a **canonical-tier-2-classifier-prompt-template** + low-temperature (0.1) + structured-output + per-intent-confidence-threshold (≥0.85 to auto-route, 0.5–0.85 to AI-assist-human, <0.5 to human-only); (Layer 2) **per-intent-deflection-engine** — each of the 12 intents has its own dedicated deflection workflow: returns → Loop/ReturnGO API self-serve-portal; sizing-fit → True Fit / Fit Finder / Fit Analytics AI size-quiz + per-product fit-data +24%; warranty → image-vision defect-classifier + auto-approve RMA under $50 OR escalate; billing-disputes → Stripe/Adyen/Checkout.com/Shopify-Functions refund-automation-with-policy-ladder + dispute-evidence-packet-generation; shipping-damage → carrier-claim-API + Loop-photo-evidence-collection + auto-route refund/exchange/reorder-by-value; subscription-cancellation → Recharge/Stay-AI save-offer-ladder +1-tier-downgrade-or-pause-or-skip vs cancel + retention-discount-if-LTV>threshold + graceful-cancel-if-all-paths-refused; (Layer 3) **agentic-resolution layer** — the AI doesn't just answer, it takes the action: calls Loop API to generate the return label, calls Stripe API to issue the refund, calls Recharge API to pause/cancel, calls Gorgias API to close the ticket with resolution-summary, calls Triple Whale API to record the tier-2-touch-attribution (returns/exchanges/refunds/cancellations all have a tier-2-touch-attribution-cost that compounds into per-cohort-LTV model); (Layer 4) **policy-engine + escalation-ladder** — every tier-2 deflection is gated by a policy-document the operator owns: max-refund-amount without human-approval ($50 default), max-shipping-cost-waived-without-approval ($15 default), max-discount-on-save-offer without approval (20% default), max-vip-tier-compensation without approval (free-shipping+10%-off default), max-chargeback-pre-arbitration-evidence-budget ($25/case default), 7-tier human-escalation-ladder (Tier 0 = macro-template, Tier 1 = AI-suggest, Tier 2 = AI-action-with-confidence-X, Tier 3 = human-action-with-AI-coaching, Tier 4 = senior-human, Tier 5 = manager, Tier 6 = owner/CEO-on-call), and a **tier-2-deflection-rate floor** (≥55% of tier-2 tickets auto-resolved end-to-end — below this, fall back to AI-assist-human mode); (Layer 5) **per-cohort-LTV-overlay + tier-2-cost-attribution** — every tier-2 touch is attributed to the per-cohort-LTV-model: a $50 goodwill-refund for a VIP-tier customer with 24-month-LTV-of-$1,200 = 0.04 × LTV = $50 → ROI-positive; the same $50 goodwill-refund for a 30-day-old-customer with $40-predicted-LTV = 1.25 × LTV = unprofitable. Tier-2 cost-aware-deflection routes each tier-2 touch through the per-cohort-LTV-aware-policy-engine so the operator captures the canonical **40–60% reduction in tier-2-cost-per-resolution** vs the no-tier-2-engine baseline (Gorgias + Forrester 2024 + Triple Whale 2024). The 5-layer build ships in **8–12 weeks (Layer 1–3 = 4 weeks, Layer 4 = 2 weeks, Layer 5 = 4 weeks)** with **5-path decision matrix** [Path A: solo-operator <$1M GMV → Gorgias-Automate-tier-2 + Recharge-stay-ai + Loop-returns-self-serve-portal / Path B: Shopify-DTC $1M–$10M GMV → Gorgias + GPT-4o + Loop + Recharge + Triple Whale + Stripe (the canonical default) / Path C: Shopify-Plus $10M+ GMV → Kustomer + Claude-3.5-Sonnet + Loop + Triple Whale + Stripe + custom-policy-engine / Path D: non-Shopify → Zendesk-Advanced-AI + bespoke-Loop-equivalent + Stripe + Triple Whale / Path E: pre-revenue → defer] and lands at **5.5:1–22:1 Year-1 ROI** with default **8.5:1 Path B** at $1M–$10M US DTC base ($120k–$480k Year-1 incremental net vs $30k–$55k operator + AI-vendor cost). Gated on Move #20.1 (skill/11 ai-customer-service-automation) shipped ≥90 days + Gorgias-Automate-baseline ≥40% deflection rate + ≥1000 tickets/mo on tier-2-intents (returns + exchanges + warranty + sizing-fit + billing + shipping-damage) + Move #6 (Triple Whale attribution) shipped + Move #40 (financial-operations) shipped + Stripe/Adyen/Checkout.com admin access + Loop/ReturnGO/Happy-Returns subscription + Recharge/Stay-AI subscription + 4 hr/week operator time during the 8-12 week build + willingness to ship on the lowest-traffic window (02:00–06:00 local) per the canonical published-publish SOP. Companion `dashboard/src/lib/ai-tier-2-deflection.ts` (Archetype-D agentic-orchestration + 12-intent-classifier + policy-engine + escalation-ladder + per-cohort-LTV-overlay). Distinct from `retention/ai-customer-service-automation` (Move #20.1, skill/11) which is the **tier-1 self-serve + AI-completion layer** that handles the easy 60-70% of tickets; Move #20.2 is the **tier-2-agentic-resolution layer** that handles the hard 30-40% and the 12-tier-2-intent-classification system + per-cohort-LTV-aware-policy-engine + agentic-action-layer. Distinct from `subscription/subscription-billing-infrastructure` (Move #37) which is the **subscription-recurring-revenue layer**; Move #20.2 Layer 2 reads Move #37's pause-skip-swap-engine + adds the canonical AI-tier-2-subscription-cancellation-save-offer-ladder (predict-LTV-of-this-subscriber → if LTV > 6× monthly-subscription-cost, offer 50%-off-next-3-months + pause-for-90-days options; if LTV between 1× and 6×, offer 25%-off-next-2-months + skip-next-2-months; if LTV < 1×, graceful-cancel-confirmation + win-back-email-flow).

## When to use this skill

**Use this skill when the operator has live Gorgias/Kustomer/Zendesk ticket volume ≥1000 tickets/mo on tier-2-intents AND the tier-1 deflection layer (skill/11 ai-customer-service-automation or equivalent Gorgias-Automate/Ada/NetoMI/Help-Scout-AI) is shipping ≥40% deflection rate but the residual 30-40% of tier-2-complex-tickets (returns/exchanges/warranty-defect-claims/sizing-fit/billing-disputes/shipping-damage/subscription-cancellation) is consuming 60-70% of operator-time + the canonical tier-2-cost-per-resolution (per Gorgias + Forrester 2024 benchmarks = $8–$15/ticket fully-loaded-cost at $1M GMV with the operator + Gorgias + Triple Whale + per-ticket-LLM-cost) is consuming $60k–$180k/yr at $1M GMV (the canonical 5–10% of GMV tier-2-cost-of-revolution that's reducible to 2–4% via the tier-2-engine).** Per `research/02-top-10-leverage-moves.md` ranking rationale + the canonical tier-2-deflection ROI table at $1M–$10M GMV: **"Move #20.2 captures the $60k–$180k/yr tier-2-cost that the canonical Move #20.1 tier-1 layer cannot deflect (returns + exchanges + warranty-defect + sizing-fit + billing-disputes + shipping-damage + subscription-cancellation = 30-40% of inbound tickets that tier-1 deflects <40% on); tier-2-agentic-resolution + per-cohort-LTV-aware-policy-engine reduces tier-2-cost-per-resolution from $8-15 to $3-7 = 40-60% reduction = $30k-$100k/yr savings at $1M GMV = 5.5:1-22:1 Year-1 ROI at $30k-$55k operator + AI-vendor cost."** The operator should only initiate a Move #20.2 tier-2-deflection build cycle when ALL of the following are true:

- **Move #20.1 (skill/11 ai-customer-service-automation) shipped ≥90 days AND reporting ≥40% deflection rate on tier-1-tickets.** Move #20.2 reads Move #20.1's macro-template-match + AI-completion-engine + Gorgias-Automate-baseline-rate; without Move #20.1 the tier-2 layer has no upstream context to inherit (no customer-tier, no LTV-bucket, no prior-resolution-summary). Verify: Gorgias-Automate-dashboard reporting ≥40% deflection rate AND Move #20.1 has been live ≥90 days.
- **Gorgias-Automate-baseline ≥40% deflection rate AND ≥1000 tickets/mo on tier-2-intents (returns + exchanges + warranty + sizing-fit + billing + shipping-damage).** The 30-40% tier-2-ticket volume is the substrate the engine reads; below 1000 tickets/mo on tier-2-intents the AI training data is too sparse to train a per-intent-classifier with ≥85% confidence. Verify: Gorgias-tags-analytics reporting ≥1000 tickets/mo on the tier-2-intent-tags (`return_request` / `exchange_request` / `warranty_claim` / `sizing_fit_question` / `billing_dispute` / `subscription_cancel_request` / `shipping_damage_claim` / `lost_package_claim` / `wrong_item_received` / `defective_item` / `chargeback_request` / `address_change_request`).
- **Move #6 (Triple Whale attribution) shipped + Move #40 (financial-operations) shipped.** Layer 5 per-cohort-LTV-overlay reads Triple Whale's per-cohort-LTV-data + Move #40's per-SKU-per-cohort-contribution-margin + per-cohort-LTV-model; without these the policy-engine has no tier-2-cost-aware-deflection input and over-refunds / over-discounts. Verify: Triple Whale (or Polar) installed AND Move #40 financial-operations-playbook shipped with per-cohort-LTV-model.
- **Stripe / Adyen / Checkout.com admin access (refund-automation) + Loop / ReturnGO / Happy-Returns subscription (return-label-generation) + Recharge / Stay-AI / Ordergroove subscription (subscription-pause/cancel-save-offer).** Layer 3 agentic-resolution requires API access to these 3 systems to actually issue the refund / generate the return label / pause the subscription. Verify: Stripe-Dashboard-admin access + Loop-or-ReturnGO subscription + Recharge-or-equivalent subscription.
- **4 hr/week operator time during the 8-12 week build.** The canonical cadence is 1 Layer per 2 weeks (Layer 1 ticket-classifier + Layer 2 per-intent-deflection-engine = 4 weeks, Layer 3 agentic-resolution + Layer 4 policy-engine = 4 weeks, Layer 5 per-cohort-LTV-overlay = 4 weeks). Total: 32-48 hours over 8-12 weeks. Verify: operator has committed 4 hr/week for 8-12 weeks.
- **Willingness to ship on the lowest-traffic window (02:00–06:00 local).** Per the canonical published-publish SOP, every staging-to-live promotion happens at 02:00–06:00 in the operator's lowest-traffic time-zone to minimize the blast radius if a fix introduces a regression. Verify: operator has documented a published-publish SOP that schedules staging-to-live at 02:00–06:00 + has a rollback plan (disable AI-agentic-resolution + fall back to AI-assist-human-only).

**Don't use this skill when:**

- **<1000 tickets/mo on tier-2-intents OR no Gorgias-Automate-baseline.** Below 1000 tickets/mo on tier-2-intents the per-intent-classifier training data is too sparse. Without Gorgias-Automate-baseline the operator has no measurement substrate for the tier-2-cost-per-resolution delta. Defer until ticket-volume AND Gorgias-Automate-baseline both exist.
- **Move #20.1 (skill/11) not shipped OR <90 days old.** Move #20.2 inherits Move #20.1's customer-tier + LTV-bucket + prior-resolution-summary. Without Move #20.1 the tier-2 layer has no upstream context and the per-cohort-LTV-aware-policy-engine produces incorrect refund amounts.
- **No Stripe/Adyen admin OR no Loop/ReturnGO subscription OR no Recharge subscription.** Layer 3 agentic-resolution requires all 3 API surfaces; without any of them the AI cannot actually issue the refund / generate the return label / pause the subscription, and the deflection-rate stays at 40-50% instead of the target 55-70%.
- **No Move #6 Triple Whale attribution OR no Move #40 financial-operations.** Layer 5 per-cohort-LTV-overlay requires Move #6 + Move #40 inputs; without them the policy-engine has no per-cohort-LTV-aware-deflection input and over-refunds / over-discounts.
- **Pre-launch or <$100k GMV.** Below $100k GMV the tier-2-ticket volume is too low to train the classifier AND the operator-time-budget for 8-12 weeks of build is better spent on Move #1 cart-abandon + Move #3 checkout-audit + Move #6 attribution.

## The build (8–12 weeks, 5 layers, 4 hr/week operator)

**Week 1-2 (Layer 1 ticket-classifier + intent-routing):**

1. **Inventory the tier-2-ticket-volume.** Open Gorgias → Analytics → Tags → filter on tier-2-intent-tags (return_request / exchange_request / warranty_claim / sizing_fit_question / billing_dispute / subscription_cancel_request / shipping_damage_claim / lost_package_claim / wrong_item_received / defective_item / chargeback_request / address_change_request). Confirm ≥1000 tickets/mo on tier-2-intents. If <1000/mo, defer until ticket-volume grows.
2. **Build the canonical-tier-2-classifier-prompt-template.** 12-intent label set + low-temperature (0.1) + structured-output (JSON mode). Use the canonical prompt-template below as starting point:
   ```
   You are a tier-2-ticket-classifier for a DTC ecommerce store.
   Classify the following inbound customer message into ONE of the following 12 intents:
   - return_request (customer wants to return an item for refund)
   - exchange_request (customer wants to exchange an item for different variant)
   - warranty_claim (customer reports a defect within warranty period)
   - sizing_fit_question (customer asks about sizing, fit, or measurement)
   - billing_dispute (customer disputes a charge, requests refund outside return window)
   - subscription_cancel_request (customer wants to cancel or pause subscription)
   - shipping_damage_claim (customer reports shipping damage)
   - lost_package_claim (customer reports package never arrived)
   - wrong_item_received (customer received wrong item)
   - defective_item (customer reports defect, may or may not be warranty-eligible)
   - chargeback_request (customer mentions chargeback, dispute, or bank reversal)
   - address_change_request (customer wants to change shipping address)
   Respond with JSON: {"intent": <one of the 12>, "confidence": <0.0-1.0>, "reasoning": "<one sentence>"}
   ```
3. **Train the classifier on 100 examples/intent minimum (1200 total).** Pull historical tickets from Gorgias tagged with the 12 tier-2-intent-tags, deduplicate, hand-verify 100/intent (or use GPT-4o to auto-label and hand-verify 20% sample). If <100/intent available, the classifier will underperform — defer until you have ≥100/intent or augment with synthetic data (have the operator write 50 synthetic examples/intent).
4. **Eval the classifier on holdout-set (20% of data).** Run on 240-example holdout-set, confirm ≥85% accuracy. If <85%, ship AI-assist-human-only mode (not auto-route) — this is critical because tier-2 errors are customer-experience-degrading (refunding wrong item, processing wrong exchange, cancelling subscription the customer wanted to keep).
5. **Wire Layer 1 to Gorgias via webhook + Gorgias Flow + Gorgias-Automate-AI.** When a new ticket arrives, webhook → classifier → if confidence ≥0.85, route to Layer 2 per-intent-deflection-engine; if 0.5-0.85, route to AI-assist-human; if <0.5, route to human-only.

**Week 3-4 (Layer 2 per-intent-deflection-engine):**

6. **Build per-intent workflows.** For each of the 12 intents, build the canonical deflection workflow:
   - **returns** → Loop API self-serve-portal link in ticket reply + auto-generate return label if customer confirms
   - **exchanges** → Loop Exchange Incentive (offer 10-15% bonus credit to exchange vs return)
   - **sizing_fit** → True Fit / Fit Finder / Fit Analytics AI size-quiz link + per-product-fit-data
   - **warranty** → image-vision defect-classifier (GPT-4o vision) + auto-approve RMA under $50 if confidence ≥85%
   - **billing_disputes** → Stripe-refund-API call (if within policy) + dispute-evidence-packet generation (Loop + Stripe order data)
   - **shipping_damage** → Loop photo-evidence-collection + carrier-claim-API call + auto-refund/exchange/reorder by value
   - **lost_package** → AfterShip tracking webhook → check last-tracking-event → if "lost in transit" >7 days, auto-refund
   - **wrong_item** → Loop exchange self-serve (95% deflect to exchange, no refund needed)
   - **defective_item** → GPT-4o vision + Loop return + warehouse-grade-A-for-restock
   - **subscription_cancel** → Recharge save-offer-ladder (pause/skip/discount) before cancel
   - **chargeback** → Stripe-disputes chargeback-doc upload within 10-day-window
   - **address_change** → Shippo address-update-API call (before fulfillment)
7. **Wire Layer 2 to Layer 1 via Gorgias Flows.** When Layer 1 routes intent X, Gorgias Flow triggers the Layer 2 workflow for intent X. Each workflow has its own template, its own API calls, its own customer-facing copy.
8. **Test Layer 2 on holdout-set of historical tickets (50 tickets per intent).** Run the 12 workflows on 600 historical tickets (50 per intent), confirm deflection-rate ≥50% on each intent. If <50%, ship Layer 2 in AI-assist-human-mode (AI suggests the action, human executes).

**Week 5-6 (Layer 3 agentic-resolution):**

9. **Build the agentic-resolution layer.** The AI doesn't just answer the ticket, it takes the action: calls Loop API to generate the return label, calls Stripe API to issue the refund, calls Recharge API to pause/cancel, calls Gorgias API to close the ticket with resolution-summary, calls Triple Whale API to record the tier-2-touch-attribution.
10. **Wire the policy-engine (Layer 4) BEFORE the action-execution.** Every action is gated by Layer 4: max-refund-amount without human-approval ($50), max-shipping-cost-waived ($15), max-discount-on-save-offer (20%), max-vip-tier-compensation, max-chargeback-pre-arbitration-budget ($25/case). If the action exceeds the ceiling, route to human-approval (Slack notification with 1-click approve/deny).
11. **Add idempotency-keys to every action-call.** Stripe idempotency-key + Loop idempotency-key + Recharge idempotency-key + Gorgias idempotency-key. This prevents double-refunds, double-returns, double-pauses if the action-call is retried.
12. **Test Layer 3 on synthetic-test-mode (don't actually issue refunds).** All 3 vendors have test-mode: Stripe-test-mode + Loop-sandbox + Recharge-sandbox. Run 100 end-to-end agentic-resolutions on synthetic-test-mode, confirm zero double-execution, zero policy-violations, zero API-errors.

**Week 7-8 (Layer 4 policy-engine + escalation-ladder):**

13. **Document the policy-engine.** Single source of truth for all policy-gates: max-refund-without-approval, max-shipping-waived, max-save-offer-discount, max-vip-compensation, max-chargeback-budget. Use a markdown-file in the operator's repo, version-controlled, with a date-stamp on every change.
14. **Build the 7-tier escalation-ladder.** Tier 0 (macro-template auto-resolve) → Tier 1 (AI-suggest human-action) → Tier 2 (AI-action-with-confidence-X) → Tier 3 (human-action-with-AI-coaching) → Tier 4 (senior-human) → Tier 5 (manager) → Tier 6 (owner/CEO-on-call). Map each ticket to its starting tier based on confidence + LTV-bucket + sentiment-score + policy-block.
15. **Wire the escalation-triggers.** Confidence <0.85 → AI-assist-human (Tier 1) → Tier 3. Policy-blocked → human-action (Tier 3) → Tier 5. High-LTV-customer (>$1500 LTV) → human-action Tier 3 → Tier 4 even if AI could resolve. Negative-sentiment (<0.3) → human-action Tier 3 → Tier 5.
16. **Set the tier-2-deflection-rate floor (≥55% default).** If the weekly deflection-rate drops below 55%, automatically fall back to AI-assist-human-mode (Layer 3 disabled, Layer 2 active in AI-suggest mode). This is the canonical "safety net" — the engine never degrades CX below baseline.

**Week 9-12 (Layer 5 per-cohort-LTV-overlay):**

17. **Build the 6-bucket LTV-segmentation.** Read Triple Whale's per-cohort-LTV-data → bucket customers into 6 LTV-cohorts (<$100 / $100-300 / $300-700 / $700-1500 / $1500-3000 / $3000+). Each bucket gets its own refund-ceiling, save-offer-cap, chargeback-budget, VIP-tier-compensation-default.
18. **Wire LTV-aware-refund-cap.** Before issuing any refund, check (refund-amount) ≤ (10% × cohort-LTV). If exceeds, escalate to human-approval (Layer 4 Tier 5 manager). This is the canonical "don't refund more than customer is worth" gate.
19. **Wire LTV-aware-save-offer-ladder (subscription-cancel).** Before cancelling any subscription, check (subscriber-LTV) > 6× (monthly-subscription-cost). If yes, offer save-tier-downgrade + 50%-off-next-3-months + pause-for-90-days before cancel. If between 1× and 6×, offer 25%-off-next-2-months + skip-next-2-months. If <1×, graceful-cancel-confirmation + win-back-email-flow at 30/60/90-day-intervals.
20. **Wire LTV-aware-chargeback-defence.** Before submitting dispute evidence, check (customer-LTV) > 5× (chargeback-amount). If yes, auto-submit-evidence + escalate to senior-human. If >10×, escalate to manager. If >20×, escalate to owner-CEO + custom-evidence-packet (Loop photo + Stripe order + carrier-claim + Gorgias full-history).
21. **Wire the tier-2-touch-attribution-cost loop back to Triple Whale.** Every tier-2 touch (refund issued / return label generated / subscription paused / exchange processed / chargeback fought) is logged to Triple Whale as a `tier_2_touch` event with cost ($8 default) + customer-cohort + LTV-bucket. This feeds back into the per-cohort-LTV-model so future refund/save-offer/chargeback decisions are calibrated to the actual tier-2-touch-cost.

## Common pitfalls (15 from real builds)

1. **Shipping Layer 1 without ≥100 training examples/intent.** The 12-intent classifier needs ≥100 examples/intent (1200 total) to hit ≥85% accuracy. Below 100/intent, the classifier routes the wrong intent 25-40% of the time, refunds the wrong item, processes the wrong exchange, cancels subscriptions the customer wanted to keep, and degrades CX below baseline. **Fix:** if <100/intent available, defer Layer 1 until ticket-volume grows OR augment with synthetic-data (have the operator write 50 synthetic examples/intent) + GPT-4o auto-label the rest + hand-verify 20% sample.
2. **Setting the confidence threshold too low (<0.85).** Tier-2 routing on confidence <0.85 routes wrong intents 15-25% of the time. **Fix:** ship with confidence ≥0.85 to auto-route, 0.5-0.85 to AI-assist-human, <0.5 to human-only. If your classifier can't hit ≥85% on most intents, ship in AI-assist-human-only mode (Layer 1 routes, Layer 2-3 disabled, Layer 4 active).
3. **Skipping the holdout-set eval.** Shipping Layer 1 without holdout-set eval = shipping blind. **Fix:** always run 20% holdout-set eval before wiring to Gorgias webhook. If accuracy <85%, ship AI-assist-human-only mode.
4. **Wiring Layer 3 (agentic-resolution) without idempotency-keys.** Stripe without idempotency-key = double-refund on retry. Loop without idempotency-key = double-return-label. Recharge without idempotency-key = double-pause. **Fix:** every action-call uses vendor-specific idempotency-key (Stripe `Idempotency-Key` header, Loop `Idempotency-Key` header, Recharge `Idempotency-Key` header). Test with retry-simulation (kill the API call mid-flight, confirm no double-execution).
5. **Wiring Layer 3 without the policy-engine (Layer 4) gate.** AI issuing $500 refunds without human-approval = customer-service-debt-bomb. **Fix:** every Layer 3 action goes through Layer 4 policy-engine BEFORE execution. Max-refund-without-approval = $50 default. Above ceiling → route to human-approval (Slack 1-click).
6. **Setting max-refund-without-approval too high ($500+).** The whole point of the policy-engine is to cap AI action without human-oversight. **Fix:** start at $50, expand only after 90 days of data showing AI calibration is solid. Never exceed 2% × average-order-value.
7. **Setting max-shipping-cost-waived-without-approval too high ($50+).** Same issue. **Fix:** start at $15, expand after 90 days. Never exceed 10% × average-order-value.
8. **Setting max-save-offer-discount too high (50%+).** Save-offer-discount erodes margin on retained subscriptions. **Fix:** start at 20%, expand after 90 days. Never exceed 30%.
9. **Not adding the escalation-trigger for high-LTV-customers.** VIP-tier customer with 24-month-LTV-of-$5000 gets auto-resolved by AI = lost relationship. **Fix:** LTV-bucket > $1500 always routes to human-action Tier 3, even if AI confidence is ≥0.85. The high-LTV customer always gets human touch.
10. **Not adding the escalation-trigger for negative-sentiment.** Customer is upset, AI responds with a templated deflection = customer escalates to social media. **Fix:** sentiment-score <0.3 (or whatever your sentiment-classifier threshold is) = always route to human-action Tier 3 → Tier 5.
11. **Not setting the tier-2-deflection-rate floor.** Without the floor, the engine can degrade CX below baseline silently. **Fix:** if weekly deflection-rate drops below 55% (or 60% / 70% depending on path), automatically fall back to AI-assist-human-mode. This is the canonical "safety net."
12. **Not setting the tier-2-cost-per-resolution floor.** Without the cost floor, the engine can over-refund / over-discount silently. **Fix:** if weekly tier-2-cost-per-resolution exceeds $7 (or $5 / $3 depending on path), Layer 5 per-cohort-LTV-overlay kicks in to gate refunds above the LTV-aware-refund-cap.
13. **Not attributing tier-2-touch-cost back to Triple Whale.** Without the attribution loop, the per-cohort-LTV-model doesn't reflect the actual tier-2-cost, and future refund/save-offer/chargeback decisions are mis-calibrated. **Fix:** every tier-2 touch logs to Triple Whale as `tier_2_touch` event with cost + cohort + LTV-bucket. Validate weekly that Triple Whale's per-cohort-LTV reflects tier-2-cost.
14. **Shipping Layer 5 (per-cohort-LTV-overlay) before Move #6 (Triple Whale) + Move #40 (financial-operations).** Layer 5 reads Triple Whale's per-cohort-LTV-data + Move #40's per-SKU-per-cohort-contribution-margin. Without these, Layer 5 produces incorrect refund-amounts. **Fix:** Move #20.2 ships AFTER Move #6 + Move #40 are live.
15. **Shipping on weekday peak-hours instead of lowest-traffic-window.** Tier-2-deflection-engine regressions during peak-hours = CX-disaster (refunds not processing, exchanges stuck, subscriptions paused wrong). **Fix:** ship at 02:00–06:00 local in the operator's lowest-traffic time-zone. Have a rollback-plan ready (disable AI-agentic-resolution + fall back to AI-assist-human-only with 1-flag-flip).
