## When to use this skill

Use Move #3.1 when **any** of these apply:

1. **You've shipped Move #3 (Baymard 24-guideline checkout-UX audit) but conversion-rate is still below vertical benchmark.** Move #3 fixes the UX-friction layer (guest-checkout / sticky-CTA / mobile-touch-targets / trust-badges / address-autocomplete); Move #3.1 fixes the payment-method-funnel layer that Move #3 does NOT cover. Without Move #3.1, the operator knows checkout-elements-fail but does NOT know per-payment-method-leak-rate.
2. **You've shipped Move #38 (BNPL optimization) but BNPL-completion-rate is below 60% on cart-values >$150.** Move #3.1's per-payment-method-funnel-instrumentation + per-card-BIN-decline-code-mapping + per-3DS-decline-rate-instrumentation surfaces WHY BNPL is dropping (BNPL-issuer-decline / BNPL-credit-check-decline / BNPL-3DS-decline / BNPL-fraud-engine-decline / BNPL-KYC-incomplete / BNPL-cart-value-above-BNPL-limit) + WHICH segment is dropping (per-AOV-band / per-region / per-customer-LTV-tier / per-cart-value-band).
3. **You're seeing a divergence between Triple Whale attribution (showing $X revenue) and Shopify order-export (showing $X-$Y revenue) AND you suspect payment-method-declines are silently eating orders.** Move #3.1's per-payment-method-attempt-instrumentation vs per-payment-method-confirmed-order-count surfaces the canonical "decline-attribution-gap" that Move #6 Triple-Whale-mismatch-Trap-#15 (the canonical "Triple-Whale-vs-GA4-mismatch-trap" the operator hits in the first 30 days) does NOT cover.
4. **You're launching into a new region (Move #25 international-expansion) and need to know WHICH local-payment-method to enable for ≥75%-share-coverage.** Move #3.1's per-region-payment-method-affinity + per-payment-method-completion-rate-by-region surfaces the canonical per-region-payment-method-priority-rank (e.g. for DE = Klarna-pay-in-3 + iDEAL + SEPA-direct-debit + SOFORT + Klarna-pay-in-4 ranked by completion-rate-vs-share-coverage).
5. **You're seeing a 30%+ checkout-funnel-leak-rate on mobile (the canonical 73%-of-traffic-but-only-1.8%-mobile-CVR-vs-3.9%-desktop-CVR per Triple Whale 2025) AND you want to know WHICH payment-method is the leak driver.** Move #3.1's per-device-payment-method-affinity + per-payment-method-funnel-step-drop-off-instrumentation surfaces whether the mobile-leak is in Step-1-reached-payment (form-friction / mobile-keyboard-friction / no-wallet-button) or Step-2-entered-card-details (mobile-card-entry-friction / no-Apple-Pay-button / no-Google-Pay-button) or Step-3-passed-3DS (mobile-3DS-friction / SMS-OTP-not-delivered-to-mobile-number) or Step-4-submitted (mobile-submit-button-friction).
6. **You're seeing a 30%+ decline-rate on credit-card-default + 70%+ approval-rate on credit-card-network-token for the SAME customer-cohort.** Move #3.1's per-card-BIN-network-token-coverage-instrumentation + per-issuer-network-token-coverage-instrumentation surfaces the canonical network-token-coverage-gap (the canonical Move #95 pitfall: "credit-card-default has 60-75%-completion-rate vs credit-card-network-token has 78-88%-completion-rate; the gap is 18-13%-points = $Xk/yr revenue-leak at $1M GMV").
7. **You want to surface "which payment-method should I deprecate" decisions.** Move #3.1's per-payment-method-completion-rate-board-pack + per-payment-method-cost-per-attempt + per-payment-method-cost-per-completed-order surfaces the canonical per-payment-method-keep-vs-deprecate-decision (e.g. PayPal might be completing 65-78%-of-attempts BUT the cost-per-completed-order = ¥0.42 vs Shop Pay's ¥0.18 — PayPal might be unprofitable-after-cost-of-friction-and-Move-#95-cascading-fallback-rules).

DO NOT use Move #3.1 for: simple theme-UX-changes (use Move #3), PDP-A/B-testing (use Move #9.5), AI-generated-product-content (use Move #12), ad-creative iteration (use Move #10), or PDP-performance (use Move #9). Move #3.1 sits specifically on the **payment-method-funnel layer** between checkout-UX (Move #3) and PSP-orchestration (Move #95).

## What "best in class" looks like
