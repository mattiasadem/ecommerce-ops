# BOPIS & Store Fulfillment Operations (Move #84)

> A 5-pillar Path A/B/C/D/E BOPIS-fulfillment-engine that wires **Buy Online Pickup In Store (BOPIS) + curbside pickup + locker pickup + drive-thru pickup + same-day delivery + ship-from-store + endless-aisle + split-cart fulfillment** into the inventory-of-record, the OMS, the picker-mobile-app, the customer-mobile-app, the geofencing-arrival-pipeline, the per-store SLA scorecard, the per-store cohort-LTV-overlay, and the per-store return-and-exchange-handoff — making the store a first-class node in the fulfillment network, not a marketing icon.

## When to use this skill

You are running a DTC ecommerce operator with **1+ physical store(s)**, marketplace-seller with FBM-from-warehouse that could ship-from-store, omnichannel retailer with regional distribution centers, or pure DTC brand that just signed its first retail pop-up / showroom / brand experience store. You have an inventory-of-record spread across warehouse + 1-store + 1-DC + 1-pop-up and customers expect "is this in my store?" + "pick it up today" + "deliver it from a nearby store in 2 hours". You need a single canonical runbook that wires the **per-store real-time inventory visibility + per-store pick-pack-hand-off + per-store picker-productivity-quota + per-store customer-arrival-prediction + per-store parking-lot-geofencing + per-store ID-verification + per-store fraud-prevention + per-store locker-pickup-handoff + per-store drive-thru-pickup + per-store same-day-delivery-orchestration + per-store ship-from-store-engine + per-store endless-aisle-engine + per-store split-cart-fulfillment (some items ship from DC, some from store 1, some from store 2) + per-store cohort-LTV-overlay** and **does NOT** leave it as 17-point-of-sale-tools-glued-together-operational-debt. You have already mastered Move #71 OMS (which gives you the cart-routing rules) + Move #29 inventory-forecasting (which gives you the per-SKU allocation) + Move #45 warehouse-management (which gives you pick-pack-hand-off) + Move #59 shipping-carrier-mix (which gives you the routing engine) but those skills **explicitly punt on the store-as-fulfillment-node problem** (Move #71 covers BOPIS conceptually but not the per-store operational depth, Move #45 covers a DC, not a retail floor with aisles, Move #59 covers parcel-carriers not walk-up customers). And Move #80 omnichannel-storefront-operations covers the customer-facing unified-commerce POS + per-channel-customer-journey-stitch but does **NOT** cover the operational fulfillment-of-orders-from-store depth. You need Move #84 to wire all of the above into a single canonical 5-pillar Path A/B/C/D/E BOPIS-fulfillment-engine so the merchant ships 60-min pickup + 2-hour same-day-delivery + ship-from-store-economics-and-SLA + endless-aisle-bopis-bopis-cross-stock-visibility + locker pickup + drive-thru pickup + split-cart fulfillment + per-store AI-picker-routing + per-store mobile-pickering-app + per-store customer-arrival-prediction + per-store parking-lot-geofencing + per-store ID-verification + per-store fraud-prevention + per-store labor-scheduling-overlay + per-store basket-attribution + per-store cohort-LTV-overlay + per-store return-and-exchange-handoff to Move #28 returns-portal — all powered by a Per-store inventory-of-record pipeline against the merchant's existing OMS + warehouse + carrier + storefront + payment + CRM + CDP + BigQuery/Snowflake warehouse + dashboards + Tier-1-P0-with-18-pitfalls-and-10-verification-gates canonical Move #84.

**Trigger this skill when ANY of:**
- Customer NPS feedback shows "I checked online, it said in-stock at the [flagship] store, but when I showed up it was sold / wrong size / not on the rack"
- Pickup-rate is <30% of store-capable orders because the inventory-of-record is stale
- Same-day-delivery-conversion is <5% because the per-store SLA is unmonitored
- Curbside operation is "bring the order to the car" with paper printout, not a real geofence-arrival-triggered-pipeline
- Drive-thru or locker pickup is on roadmap but you don't have the per-store deployment template
- Store managers are dropping orders because the OMS isn't real-time, they're pulling from a 4-hour-stale snapshot
- Customer-complaint ticket queue has "the order wasn't ready when I arrived" in top-3
- CFO can't model ship-from-store-economics against DC-ship-economics to decide which orders to route where
- Per-store-attribution is invisible because the cart-level BOPIS flag is not in the CDP
- Per-store-cohort-LTV is invisible because the store-pickup-customer is not tagged as `pickup_local` in Move #13
- Endless-aisle is on roadmap (catalog-bigger-than-store) but the cross-stock-visibility plumbing doesn't exist
- You just opened a new store and need to onboard it to the BOPIS-engine in 30 days
- You're a marketplace-seller with FBM-from-warehouse considering FBM-from-store for seller-prime-2-day-eligibility
- Pops up at the [BFCM] Friday and the store-pickup-rate is going to 80% — warehouse can't handle it
- You're building Q4 inventory buffers with per-store-rebalancing and the OMS can't show store-stock at the SKU-bin level

**Do NOT trigger this skill when:**
- You have no physical store. (Pure DTC / pure marketplace-Pure-FBA / pure 3PL-only — skip and use Move #71 OMS + Move #45 warehouse-management + Move #59 shipping-carrier-mix directly.)
- You have <50 stores and most orders ship-from-DC. (Move #84 still applies but at much smaller scope — use Path A lightweight.)
- You only do ship-from-store, never customer-facing pickup. (Skip the geofencing + ID-verification + locker + drive-thru pillars, lean into Pillar 3 only.)
- You have a single distribution center and no retail presence. (Skip entirely.)
- You want to add BOPIS for the first time. (Move #84's Path A explicitly covers cold-start from zero stores — read on.)

**Move #84 is the canonical first-pillar of the omnichannel-storefront-operations stack of skills.** It pairs with Move #80 (omnichannel-storefront-operations) on the customer-facing side and Move #71 (order-management) on the cart-routing side. Together the three form the unified-commerce operational-stack: **Move #80 = customer-facing**, **Move #71 = cart-routing**, **Move #84 = store-side operational depth**. Customers experience Move #80's storefront, the OMS uses Move #71's routing rules, the store executes Move #84's per-store operational playbook.

## What "best in class" BOPIS-curbside-store-fulfillment-operations looks like

A best-in-class BOPIS-curbside-store-fulfillment-operations operation runs on a **single 5-pillar Path A/B/C/D/E BOPIS-fulfillment-engine substrate** built on top of the merchant's existing OMS (Move #71) + inventory (Move #29) + warehouse (Move #45) + carrier (Move #59) + storefront (Move #80) — adding the per-store operational depth none of those give you, with measurable operational primitives:

**Per-store inventory-of-record pipeline:**
- Per-store real-time inventory-visibility with **per-SKU-per-bin** granularity (not per-store-broadcast-blob)
- Per-SKU inventory-allocation-rules: reserve-on-online-purchase-vs-walk-in-tradeoff
- Per-store inventory-reserve-window: 30-min standard, 4-hr for BFCM, 24-hr for ship-from-store-cohort
- Per-store perpetual-inventory reconciliation against the POS daily close
- Per-store in-transit-from-DC-to-store visibility with ETA + receiving-SLA
- Per-store in-transit-from-store-to-customer visibility with same-day-delivery-ETA
- Per-store in-store pickup window: pickup-after-2-hrs-minimum-rule
- Per-store return-back-to-store-inventory pipeline
- Per-store endless-aisle cross-stock-visibility against the DC-pool (catalog > store-shelf)

**Per-store picker operations:**
- Per-store mobile-pickering-app with aisle-bin-SKU-scanning
- Per-store picker-productivity-quota: 30-picks/hr standard, 50-picks/hr BFCM-peak
- Per-store picker-replacement-cost awareness (Move #53 financial-operations)
- Per-store picker-queue-management with FIFO + priority (high-AOV + subscription-subscriber-first)
- Per-store picker-route-optimization with category-cluster + temperature-zone + hazardous-materials Move #72 isolation
- Per-store picker-task-batch optimization: batch 5-orders-per-pick vs 1-order-per-pick tradeoff
- Per-store AI-picker-routing with reinforcement learning (Move #47 experimentation A/B)
- Per-store QC-station with photo-capture for fashion/beauty/food/pet

**Per-store customer-handoff operations:**
- Per-customer arrival-prediction via mobile-app-foreground + geofence-pipeline
- Per-customer parking-spot-allocation if curbside
- Per-customer ID-verification-pipeline at handoff (driver-license / QR-code / order-confirmation-email)
- Per-customer hand-off-with-greeting template + script + gift-add-on recommendation engine
- Per-customer order-substitution-options if SKU out-of-stock at pickup (auto-coupon-coded)
- Per-customer SMS-arrival-instructions + push-notification + email-ITW inbound
- Per-customer pickup-SLA-monitor with no-show-handling (auto-release-after-72-hr)

**Per-store same-day-delivery orchestration:**
- Per-store same-day-delivery-radius (3mi / 5mi / 10mi / 20mi) by ZIP-code-cluster
- Per-store same-day-delivery-promise-options: 2-hour / 4-hour / same-evening
- Per-store same-day-delivery-pricing-engine with dynamic-pricing for BFCM-peak surge
- Per-store same-day-delivery-route-optimization with multi-stop-batching
- Per-store same-day-delivery-driver-pool: in-house + 3PL (Roadie/DoorDash/Uber/Gojek/Lalamove/Pickupp)
- Per-store same-day-delivery-driver-tracking with real-time-customer-tracking-link (Move #59 carrier-mix substrate)
- Per-store same-day-delivery-SLA-monitor with on-time-delivery-rate target ≥95%

**Per-store ship-from-store / endless-aisle operations:**
- Per-store ship-from-store-cost-vs-DC-ship-cost decision-tree per ZIP-code-cluster
- Per-store ship-from-store-SLA: 24-hr pick + pack + hand-off + standard-transit vs same-day
- Per-store ship-from-store-economics-model: per-order $7.50-DC-savings × orders/month × margin-multiplier
- Per-store ship-from-store-carrier-rate-card-aggregator (USPS Priority Cubic / UPS Ground Saver / FedEx Ground Economy / DHL eCommerce / Mondial Relay)
- Per-store ship-from-store-pick-station with carrier-pickup-cubbies
- Per-store endless-aisle-cross-stock-visibility against the central DC pool (catalog > store-shelf)
- Per-store endless-aisle-shipping-cost-zero-impact routing (orders-eligible-to-ship-from-store: catalog-SKU-store-SKU-difference-margin-positive)

**Per-store locker / drive-thru / curbside-SLA operations:**
- Per-store locker-pickup with smart-locker-network (Parcel Pending / Luxer One / Amazon Hub / Walmart Pickup Tower / CVS / Best Buy Geek Squad Lockers)
- Per-store drive-thru-pickup with bay-camera + license-plate-recognition
- Per-store curbside-geofencing with customer-arrival-prediction + auto-pull-order
- Per-store curbside-SLA-monitor: average-arrival-to-handoff <2-min target
- Per-store locker-capacity-management with overflow-pipeline (auto-route-to-curbside if locker-full)
- Per-store locker-and-drive-thru-CAPA-alert when utilization >80%

**Per-store labor + space + financial operations:**
- Per-store labor-budget-allocator: pickers-Monday vs Friday vs BFCM
- Per-store labor-forecasting with historical-traffic-pattern + pickup-rate-trajectory
- Per-store space-allocator: square-footage-pickup-zone + QC-station + locker-bank + drive-thru-bay

## Common pitfalls (18 from real builds)

1. **Ship-without-per-store-real-time-inventory-of-record-pipeline-with-per-SKU-per-bin-granularity.** The canonical #1 BOPIS-curbside-store-fulfillment-operations pitfall: broadcasting "in-stock at [flagship] store" from a 4-hour-stale OMS snapshot against a POS that doesn't reconcile, leading to "I drove to the store and they didn't have it" customer-complaints that drive pickup-NPS into the floor and pickup-conversion-rate to <30%. The customer sees "in-stock" on PDP; the picker sees "out-of-stock" on aisle; the OPS-team can't tell who's right. **Fix:** ship **per-store real-time-inventory-of-record-pipeline with per-SKU-per-bin granularity** with per-store-perpetual-inventory-reconciliation-against-POS-daily-close + per-store-SKU-bin-mapping-data-migration + per-store in-transit-from-DC-to-store-ETA + per-store inventory-reserve-window-of-30-min + per-SKU inventory-allocation-rules-that-balance-reserve-on-online-purchase-vs-walk-in; ship the canonical Move #29 inventory-forecasting substrate AND a per-store perpetual-inventory-ledger-pipeline that atomically-commits-pick-station-shrink-to-inventory; per-store SKU-availability-true-rate target ≥97% (not "in-stock-at-store" lies).

2. **Ship-without-per-store-picker-mobile-app-with-picker-productivity-quota.** The canonical #2 BOPIS-curbside-store-fulfillment-operations pitfall: paper-picklists, no real-time picker-queue, no AI-routing, no productivity-quota — pickers average 15-picks/hr instead of 50-picks/hr, BFCM-pickup-rate-queue builds up to 4-hour backlogs, NPS-collapses-as-customer-waits-in-store-for-pickup. **Fix:** ship **per-store picker-mobile-app with picker-productivity-quota** with per-store mobile-pickering-app-with-aisle-bin-SKU-scanning (Manhattan-Store-Fulfillment-2026 or Blue-Yonder-Store-Fulfillment-2026) + per-store picker-productivity-quota-of-30-picks-hr-standard-50-picks-hr-BFCM-peak + per-store picker-queue-management-FIFO-with-priority-high-AOV-subscribers-first + per-store AI-picker-routing with reinforcement-learning (Move #47 experimentation-A/B-variant) + per-store QC-station-with-photo-capture (fashion-beauty-food-pet) + per-store picker-route-optimization-with-category-cluster-temperature-zone-hazardous-materials-Move-72-isolation; per-store picker-task-batch-optimization (5-orders-per-pick vs 1-order-per-pick tradeoff).

3. **Ship-without-per-customer-arrival-prediction-pipeline-with-geofencing-arrival-pull.** The canonical #3 BOPIS-curbside-store-fulfillment-operations pitfall: customer pulls into parking lot, calls the store, associate runs out with bag — average-arrival-to-handoff is 8 minutes instead of 2 minutes, customer-wait-time-climbs-and-NPS-falls; the operation is "bring the order to the car" with paper-printout-and-cellphone-call, not a real geofence-arrival-triggered-pipeline. **Fix:** ship **per-customer arrival-prediction-pipeline-with-geofencing-arrival-pull** with per-customer mobile-app-foreground-detect + per-customer geofence-pipeline-with-100m-radius-trigger + per-customer parking-spot-allocation if curbside + per-customer parking-lot-camera-feed-license-plate-recognition + per-customer arrival-SMS-push-notification-email-inbound + per-customer auto-pull-order-when-customer-enters-100m-radius; ship the canonical Move #59 carrier-mix substrate for parking-lot-camera-feed-license-plate-recognition (Samsara-2026 + Foursquare-2026 + Geotab-2026).
