**Template family 2 — Per-acquirer-rate-change-analysis algorithm (the cost-impact calculator):**

The per-acquirer-rate-change-analysis algorithm takes a per-acquirer-rate-notice input and returns the per-acquirer-cost-impact (annual $) + per-acquirer-rate-floor-status + per-acquirer-rate-collar-status + per-acquirer-rate-band-status + per-acquirer-rate-cap-status + per-acquirer-rate-ratchet-trigger-status + per-acquirer-pass-through-cost-recovery-status + per-acquirer-network-program-context-isolation (the network-program delta vs the acquirer-only delta) + per-acquirer-multi-currency-context + per-acquirer-multi-region-context.

The 8-step pipeline:

1. Parse per-acquirer rate-notice into `{current, new}` + acquire flags (rate-floor, rate-collar, rate-band, rate-cap, rate-ratchet, pass-through).
2. Compute per-acquirer-rate-delta-per-transaction (e.g., +$0.02) AND per-acquirer-rate-delta-on-volume (e.g., +0.02%).
3. Pull per-acquirer-volume from Move #167.5.12 per-acquirer governance dashboard (annual transaction count × average transaction value).
4. Compute per-acquirer-cost-impact-annual = (rate-delta-per-transaction × annual-transaction-count) + (rate-delta-on-volume × annual-volume).
5. Pull per-acquirer-network-program-updates (Visa VAMP + MasterCard ECM + AmEx MER + Discover DMP + JCB Ref + UnionPay UPGD) from Move #167.5.12 per-acquirer network-program-update-alert (Move #167.5.12.1.6.4 Component 7).
6. Compute per-acquirer-network-program-context-isolation = per-acquirer-rate-delta MINUS per-acquirer-network-program-updates-delta (the residual is the acquirer-only delta, which is what the operator should object to; the network-program passthrough is industry-wide and harder to fight).
7. Pull per-acquirer-multi-currency + per-acquirer-multi-region context from Move #167.5.12.1.6.2 + Move #167.5.12.1.6.3.
8. Return per-acquirer-rate-change-analysis report (markdown + .pdf + Slack-block).

**Template family 3 — Per-acquirer-rate-notice-response-window tracker (the deadline tracker):**

The per-acquirer-rate-notice-response-window tracker takes a per-acquirer-rate-notice input and returns the per-acquirer-rate-notice-response-window (days remaining to object) + per-acquirer-rate-notice-decision-packet-date + per-acquirer-rate-notice-QBR-coupling-option + per-acquirer-rate-notice-counter-proposal-leverage-window.

The 5-step pipeline:

1. Pull per-acquirer-rate-notice-effective-date + per-acquirer-rate-notice-objection-deadline from Move #167.5.12 per-acquirer rate-notice alerter (Move #167.5.12 Component 4).
2. Compute per-acquirer-rate-notice-days-remaining = per-acquirer-rate-notice-objection-deadline MINUS today.
3. Pull per-acquirer-rate-notice-decision-packet-date (the date by which the CFO must decide) from Move #167.5.12 per-acquirer QBR deck (Move #167.5.12 Component 5).
4. Determine per-acquirer-rate-notice-QBR-coupling-option (if the rate-notice-decision-packet-date falls within 14 days of the per-acquirer QBR, couple the response with the QBR for portfolio-leverage).
5. Return per-acquirer-rate-notice-response-window tracker (markdown + Slack-block + email).

**Template family 4 — Per-acquirer-rate-notice-response-action-plan template (the strategy selector):**

The per-acquirer-rate-notice-response-action-plan template takes a per-acquirer-rate-change-analysis + per-acquirer-rate-notice-response-window + per-acquirer-portfolio-context + per-acquirer-network-program-context input and returns the recommended per-acquirer-rate-notice-response-action-plan (object / accept / renegotiate / migrate / counter-propose / pass-through) + the per-acquirer-rate-notice-objection-letter-template + the per-acquirer-rate-notice-counter-proposal-leverage matrix (5-7 dimension × 5-acquirer matrix) + the per-acquirer-rate-notice-portfolio-defense-strategy.

The 6-step pipeline:

1. Pull per-acquirer-rate-change-analysis from Component 2.
2. Pull per-acquirer-rate-notice-response-window from Component 3.
3. Pull per-acquirer-portfolio-context (per-acquirer-volume × per-acquirer-profitability × per-acquirer-strategic-importance) from Move #167.5.12 per-acquirer portfolio dashboard (Move #167.5.12 Component 7).
4. Pull per-acquirer-network-program-context (per-acquirer-VAMP + per-acquirer-ECM + per-acquirer-MER + per-acquirer-DMP + per-acquirer-Ref + per-acquirer-UPGD) from Move #167.5.12.1.6.4 Component 7.
5. Compute per-acquirer-rate-notice-response-action-plan via 6-rule algorithm:
   - if per-acquirer-network-program-context-isolation-delta > 0.05% AND per-acquirer-portfolio-volume > $1M/yr → recommend "object" (the acquirer is overcharging beyond the network-program passthrough).
   - if per-acquirer-rate-delta-on-volume > 0.10% AND per-acquirer-portfolio-volume > $5M/yr → recommend "renegotiate" or "counter-propose" (the rate-delta is too large to absorb).
   - if per-acquirer-rate-delta-per-transaction < $0.05 AND per-acquirer-portfolio-volume < $500K/yr → recommend "accept" (the cost-impact is too small to justify the negotiation effort).
   - if per-acquirer-rate-delta-on-volume > 0.20% → recommend "migrate" (the rate-delta is large enough to justify the integration effort).
   - if per-acquirer-rate-notice-days-remaining > 60 → recommend "counter-propose" with leverage from per-acquirer-portfolio + per-acquirer-network-program + per-acquirer-multi-region.
   - else → recommend "pass-through" (the cost-impact is real but the negotiation effort exceeds the cost-savings).
6. Return per-acquirer-rate-notice-response-action-plan (markdown + Slack-block + email).

## Common pitfalls (15 from real builds)

Each pitfall is a recurring failure mode observed across per-acquirer-rate-notice-letter-template-library builds in 2024-2026, grouped into 6 failure-mode clusters (A-F).

**Failure mode A — Per-acquirer-rate-notice-letter-template scope creep:**

1. **Per-acquirer-rate-notice-letter-template scope creep.** The most common pitfall. The 5 per-acquirer-rate-notice-letter-template families are a curated baseline, NOT an exhaustive list. If you start adding per-acquirer-rate-notice-followup-email-template + per-acquirer-rate-notice-counter-proposal-letter-template + per-acquirer-rate-notice-renegotiation-letter-template + per-acquirer-rate-notice-migration-letter-template + per-acquirer-rate-notice-pass-through-letter-template, you'll ship 10+ templates and the per-acquirer-finance team can't remember which one to use. STICK TO THE 5. Add per-acquirer-rate-notice-counter-proposal-letter-template + per-acquirer-rate-notice-renegotiation-letter-template + per-acquirer-rate-notice-migration-letter-template as separate Move #s (Move #167.5.12.1.6.4.2.X extensions).

2. **Per-acquirer-rate-notice-letter-template over-engineering.** Each of the 5 per-acquirer-rate-notice-letter-template families should be a 4-section letter (per-acquirer-rate-notice-summary → per-acquirer-rate-change-analysis → per-acquirer-response-window → per-acquirer-response-action-plan). Don't add 5+ sections — the per-acquirer-finance team won't read them.

3. **Per-acquirer-rate-notice-letter-template tone-of-voice drift.** The per-acquirer-rate-notice-letter-tone-of-voice (formal / collaborative / assertive) must match the per-acquirer-finance team's communication style with each acquirer. If the chat agent renders an "assertive" letter when the per-acquirer-finance team prefers "collaborative", the acquirer-RM will push back. Use the 6-dim per-acquirer-rate-notice-template configuration to lock the tone-of-voice per acquirer.

**Failure mode B — Per-acquirer-rate-change-analysis algorithm pitfalls:**

4. **Per-acquirer-rate-change-analysis algorithm misses network-program-context-isolation.** The single most impactful algorithm step. If you compute per-acquirer-cost-impact-annual without isolating the per-acquirer-network-program-context-isolation delta (the residual = per-acquirer-rate-delta MINUS per-acquirer-network-program-updates-delta), the per-acquirer-finance team will object to the entire delta including the industry-wide network-program passthrough, and the acquirer-RM will dismiss the objection. ALWAYS isolate the network-program-context.

5. **Per-acquirer-rate-change-analysis algorithm uses stale per-acquirer-volume data.** The per-acquirer-rate-change-analysis algorithm pulls per-acquirer-volume from Move #167.5.12 per-acquirer governance dashboard. If the dashboard's per-acquirer-volume is stale (e.g., 6 months old), the per-acquirer-cost-impact-annual will be wrong. ENSURE the per-acquirer-volume is fresh (within 30 days).

6. **Per-acquirer-rate-change-analysis algorithm ignores per-acquirer-rate-floor / rate-collar / rate-cap / rate-ratchet triggers.** The per-acquirer-rate-change-analysis algorithm should pull per-acquirer-rate-floor-status + per-acquirer-rate-collar-status + per-acquirer-rate-cap-status + per-acquirer-rate-ratchet-trigger-status from the per-acquirer contract (Move #167.5.12 per-acquirer calendar Component 1). If the rate-delta breaches the per-acquirer-rate-floor / rate-collar / rate-cap / rate-ratchet, the per-acquirer-rate-notice-response-action-plan should recommend "object" (the acquirer has breached the contract).

**Failure mode C — Per-acquirer-rate-notice-response-window tracker pitfalls:**

7. **Per-acquirer-rate-notice-response-window tracker misses the per-acquirer-rate-notice-decision-packet-date.** The per-acquirer-rate-notice-decision-packet-date is the date by which the CFO must decide. If the per-acquirer-rate-notice-decision-packet-date is < 14 days before the per-acquirer QBR, the per-acquirer-rate-notice-response-action-plan should recommend "couple with QBR" for portfolio-leverage. ENSURE the per-acquirer-rate-notice-response-window tracker pulls the per-acquirer QBR date from Move #167.5.12 per-acquirer QBR deck (Component 5).

8. **Per-acquirer-rate-notice-response-window tracker computes days-remaining wrong.** The per-acquirer-rate-notice-days-remaining = per-acquirer-rate-notice-objection-deadline MINUS today. Use UTC date arithmetic (not local date). If the per-acquirer-rate-notice-objection-deadline is in a non-UTC timezone, the days-remaining can be off by 1.

**Failure mode D — Per-acquirer-rate-notice-response-action-plan pitfalls:**

9. **Per-acquirer-rate-notice-response-action-plan algorithm recommends "accept" too eagerly.** The 6-rule per-acquirer-rate-notice-response-action-plan algorithm has 6 branches. The most common branch is "accept" (the cost-impact is too small to justify the negotiation effort). But the per-acquirer-finance team should ALWAYS object when the per-acquirer-network-program-context-isolation-delta > 0.05% (the acquirer is overcharging beyond the network-program passthrough), regardless of the cost-impact. ENSURE the algorithm prioritizes network-program-context-isolation over cost-impact.

10. **Per-acquirer-rate-notice-response-action-plan algorithm ignores per-acquirer-portfolio-volume.** The per-acquirer-rate-notice-response-action-plan algorithm has a branch that recommends "renegotiate" when per-acquirer-portfolio-volume > $5M/yr AND per-acquirer-rate-delta-on-volume > 0.10%. If the per-acquirer-portfolio-volume is below $5M/yr, the algorithm recommends "accept" or "counter-propose" — but for $1M-$5M GMV operators, the per-acquirer-portfolio-volume is typically $200K-$2M/yr, and "accept" loses $5K-$50K/yr of cost-avoidance. ADJUST the per-acquirer-portfolio-volume threshold to $1M/yr for Path B mid-market case.

11. **Per-acquirer-rate-notice-response-action-plan algorithm recommends "migrate" too eagerly.** The 6-rule per-acquirer-rate-notice-response-action-plan algorithm has a branch that recommends "migrate" when per-acquirer-rate-delta-on-volume > 0.20%. But migrating an acquirer is 60-180 days of integration effort + $10K-$100K of integration cost. If the per-acquirer-rate-delta-on-volume is 0.20-0.30%, the integration effort exceeds the savings. RAISE the threshold to 0.50% (or move to something else).

**Failure mode E — Per-acquirer-rate-notice-objection-letter pitfalls:**

12. **Per-acquirer-rate-notice-objection-letter lacks per-acquirer-counter-proposal-leverage-matrix.** The single most impactful letter section. The per-acquirer-rate-notice-counter-proposal-leverage-matrix is the 5-7 dimension × 5-acquirer matrix that shows the acquirer-RM the per-acquirer-finance team's leverage (per-acquirer-volume × per-acquirer-profitability × per-acquirer-strategic-importance × per-acquirer-portfolio-volume × per-acquirer-network-program-context × per-acquirer-multi-region-context × per-acquirer-multi-currency-context). WITHOUT this matrix, the per-acquirer-rate-notice-objection-letter is just a complaint, not a counter-proposal. ENSURE the letter includes the matrix.

13. **Per-acquirer-rate-notice-objection-letter uses the wrong escalation-path.** The per-acquirer-rate-notice-objection-letter escalation-path is acquirer-rep → acquirer-RM → acquirer-network-program-management. If the per-acquirer-rate-notice-letter is sent to the acquirer-rep first, the acquirer-RM may dismiss it. For per-acquirer-rate-notices with cost-impact > $50K/yr, send the letter directly to the acquirer-RM (skip the acquirer-rep).

**Failure mode F — Per-acquirer-rate-notice auto-load + publish pitfalls:**

14. **Per-acquirer-rate-notice auto-load directive matches too many questions.** The per-acquirer-rate-notice question-intent-detection regex rules are 5 patterns (per-acquirer-rate-notice / per-acquirer-rate-change / per-acquirer-rate-increase / per-acquirer-rate-objection / per-acquirer-rate-response). The regex `per-acquirer-rate-change` is too broad — it matches "per-acquirer-rate-change-MORP 2026" (which is a per-acquirer-network-program-update question, not a per-acquirer-rate-notice question). NARROW the regex to `per-acquirer-rate-notice` OR `per-acquirer-rate-change-notice` (specific to the rate-notice flow).

15. **Per-acquirer-rate-notice-letter publish pipeline missing the Slack-block format.** The per-acquirer-rate-notice-letter publish pipeline ships to markdown / .docx / .pdf / .ics / Zendesk-macro / Gorgias-macro / Kustomer-macro / Helpdesk-macro / Slack-block / email / SMS / push / in-app. The Slack-block format is the most important for the per-acquirer-finance team's chat-agent-UX (the chat agent's response is rendered as a Slack-block in the operator's chat-channel). ENSURE the Slack-block format is wired.
