## Common pitfalls (15 from real builds)

1. **Per-acquirer-template family scope creep.** The most common pitfall. The 10 per-acquirer-template families are a curated baseline, NOT an exhaustive list. If you start adding per-acquirer-rate-notice-letter-template + per-acquirer-QBR-followup-email-template + per-acquirer-MID-onboarding-runbook-template + per-acquirer-MID-offboarding-runbook-template + per-acquirer-chargeback-rebuttal-template + per-acquirer-network-program-threshold-appeal-template + per-acquirer-3DS-fallback-memo-template + per-acquirer-account-updater-audit-template + per-acquirer-reserve-rollover-memo-template + per-acquirer-FX-hedge-recommendation-memo-template, the per-acquirer-template-library balloons to 20-30 templates and the per-acquirer-finance team can't keep them all current. The fix is to ship the 10 high-leverage templates first, observe which 3-5 templates the per-acquirer-finance team uses 80% of the time, and only add the next 3-5 templates when 80%+ of the existing templates are being used monthly. Don't ship a per-acquirer-template library with 30 templates — ship 10 and add 3-5 per quarter.
2. **Per-acquirer-template render function trusts the chat agent to fill the data correctly.** The pitfall. The per-acquirer-template-render pipeline must NEVER trust the chat agent to fill the per-acquirer-template skeleton with correct data — the chat agent will hallucinate per-acquirer-currency formats, per-acquirer-regulatory references, per-acquirer-tax-form references, per-acquirer-data-protection references. The fix is to call the per-acquirer-cadencer-MCP-server (Move #167.5.12.1) to fetch the canonical per-acquirer-data, then fill the per-acquirer-template skeleton with the canonical per-acquirer-data, then run the per-acquirer-template validation pass to catch hallucinations. If the per-acquirer-template validation pass fails, the per-acquirer-template-library MUST reject the per-acquirer-template render and re-call the per-acquirer-cadencer-MCP-server.
3. **Per-acquirer-template validation pass uses a regex-only lint.** The pitfall. The per-acquirer-template validation pass MUST call the per-acquirer-cadencer-MCP-server (Move #167.5.12.1) to verify the per-acquirer-template's per-acquirer-currency, per-acquirer-region, per-acquirer-regulatory, per-acquirer-tax-form, per-acquirer-data-protection references against the canonical per-acquirer-data. A regex-only lint will pass a per-acquirer-template with `per-acquirer-fine-of-$1,234,567` when the actual per-acquirer-fine is `$123,456` — the regex doesn't catch numeric-drift. The fix is to fetch the canonical per-acquirer-data from the per-acquirer-cadencer-MCP-server and compare the per-acquirer-template's per-acquirer-currency values + per-acquirer-regulatory references + per-acquirer-tax-form references against the canonical.
4. **Per-acquirer-template version control uses Git-only.** The pitfall. The per-acquirer-template-library MUST use a per-acquirer-template-version + per-acquirer-template-rollback + per-acquirer-template-publish pipeline that lives in the per-acquirer-cadencer-dashboard (not in a separate Git repo). The per-acquirer-finance team doesn't have time to learn Git; the per-acquirer-template-version + per-acquirer-template-rollback + per-acquirer-template-publish pipeline MUST be a 1-click action from the per-acquirer-cadencer-dashboard.
