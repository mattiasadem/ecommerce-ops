### Layer 2 — Per-subscription-discount-LTV-tier-x-cohort-affinity-x-BFCM-cohort-x-device-x-traffic-source-quad-axis-x-cohort-affinity-sexiary completion-rate-and-leak-rate counter

- `leak_rate = 1 - completion_rate` (broken into 9 sub-leaks: address-validation / payment-method-rejection / shipping-cost-expectation-mismatch / tax-calculation-surprise / inventory-availability-disappointment / currency-conversion-resistance / language-translation-friction / warehouse-cutoff-time-missed / return-policy-rejection-at-payment)

## Common pitfalls (18 from real builds)

1. **The Cloudflare + Fastly + Akamai BFCM-traffic-burst-event-streams + device-cohort-x-traffic-source-traffic-burst-event-streams + device-x-traffic-source-pair-emergence-event-streams + cohort-affinity-quaternary-axis-traffic-burst-event-streams + cohort-affinity-quaternary-axis-emergence-event-streams + cohort-affinity-quinary-axis-traffic-burst-event-streams + cohort-affinity-quinary-axis-emergence-event-streams + cohort-affinity-sexiary-axis-traffic-burst-event-streams (Move #3.26-unique) MUST be wired FIRST, before any Layer-2/3/4 work.** A Move #3.26 build that skips this wiring surfaces 5-15% residual leak-rate that the operator cannot decompose because the cohort-affinity-sexiary-axis-event-stream never lands. Symptom: 8-cohort-affinity-sexiary-axis benchmarks load but the top-leak-cells view is empty during BFCM peaks. Fix: prioritize Phase 5 wiring before Phase 2/3/4.

2. **Don't conflate cohort-affinity-sexiary-axis with Move #3.25's cohort-affinity-quinary-axis.** The sexiary-axis is the 11th axis (the canonical 8 sexiary-axis dimensions), decomposing Move #3.25's quinary-axis cells further. A conflated build surfaces double-counted completion-rate-leaderboard rows (same cell appears in both Move #3.25 + Move #3.26 leaderboards).

3. **The 8-cohort-affinity-sexiary-axis (per-language / per-currency / per-shipping-region / per-tax-jurisdiction / per-product-category / per-SKU-tier / per-inventory-availability / per-warehouse-region) MUST each have ≥3 months of historical data with ≥1,000 checkout-attempts per cell** before the completion-rate-baseline is statistically meaningful. A Move #3.26 build that goes live with <3 months of data surfaces spurious "leak-cells" that are actually cold-start noise.
